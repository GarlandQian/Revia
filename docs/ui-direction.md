# UI 方向

更新日期：2026-11-21。状态：M13（UI 全面重构，Q234–Q245）已完成实施、功能审查与历史兼容清理并合入本地 `main`，详见 [M13 报告](./milestones/m13/report.md) 与 [M13 视觉稿 v1](./milestones/m13/mockups/revia-ui-v1.html)。

## 视觉风格

M13 起，**告别 Liquid Glass 与 Rebased 一比一布局约束，采用克制、清晰、高完成度的实色现代桌面开发工具风格**（Q234–Q245，[ADR-0011](./adr/0011-rebuild-like-rebased-not-fork.md)、[ADR-0016](./adr/0016-decoupled-design-system-and-solid-surfaces.md)）：

- **外壳与材质**：窗口为标准不透明原生窗口，彻底移除 Liquid Glass、React Bits 材质层、SVG 玻璃镜片、胶囊堆叠与高开销网页背景模糊（Q235、Q239）。以细腻的中性灰阶层级、1px 细分隔线、克制圆角（控件 `6px`、浮层/弹窗 `10px`）与精准留白建立桌面工具质感。
- **外壳配色与密度（Q237）**：
  - 浅色模式：柔和浅灰外壳（`#F5F6F8`）+ 纯白工作面（`#FFFFFF`）+ 细灰分隔线；
  - 深色模式：深邃炭黑/中性板岩灰（外壳 `#141518`、工作面 `#1A1C20`）+ 低对比细边框；
  - 强调色：克制的钴蓝用于主操作、激活态与焦点环，Git 状态与 diff 增删保留清晰语义色；
  - 尺寸与密度：顶栏 `40px`、页签栏 `36px`、状态栏 `24px`、列表行高 `26px`，兼顾开发工具信息密度与视觉呼吸感。
- **外壳与代码颜色主题解耦（Q237、ADR-0016）**：界面外壳由 Revia 自己的浅/深色 Design Tokens 统一控制；代码 diff、三方合并与 blame 区域的底色、语法高亮与增删行色继续完整跟随所选或导入的 VS Code 颜色主题（内置 VS Code Light 2026、Atom One Light、VS Code Dark 2026、One Dark Pro，默认浅色 Atom One Light、深色 One Dark Pro），通过 1px 细边框与外壳自然衔接。
- **外观模式（Q237）**：设置“外观”页提供“跟随系统 / 浅色 / 深色”（默认跟随系统，兼容 Q50），联动切换外壳浅/深色令牌与对应的浅/深色代码颜色主题。
- **字体与图标（Q133、Q238）**：界面使用各平台系统字体；代码字体默认随应用打包的 JetBrains Mono 且可配置；界面控件图标统一通过 `AppIcon` 映射到 Lucide（`1.65px` 细线风格，已彻底移除 `@vscode/codicons` 与旧 `Codicon` 别名），文件类型图标保留 Material Icon Theme（在“关于 Revia”中注明许可）。
- **验收方式（Q245）**：先以浅/深色高保真 HTML 视觉稿经用户确认定稿，再按模块重构落盘并在真实桌面截图验收；不再要求与 Rebased 1.1.22 逐屏一比一对照。

Revia 独有的功能自然融入统一设计语言：

| 独有功能 | 放在哪里 |
| --- | --- |
| 回收区 | 左侧栏与“提交”“Stash”并列的分段页签 |
| 审阅标记 | 改动树行内精致小对勾、diff 统一上下文栏“标记为已审阅”按钮、提交区左下角审阅进度徽标（Q121、Q243） |
| 写前校验失败、结果待核对 | diff 区顶部提示条或右下角轻盈通知气泡 |
| 提交前快照 | 提交完成的通知气泡中说明存了哪些文件 |

历史方向演进记录（均已由 M13 取代）：
- **macOS 原生质感**（Q15、Q103）：早期原型，未采用。
- **参照 Rebased 一比一布局 / VS Code 控件外观**（Q107、Q119、Q131）：M4–M6 采用，易显旧式 IDE 感且外壳对比度随主题波动。
- **Liquid Glass + React Bits / AppKit 原生玻璃 + Loop 镜片卡片**（Q189、Q200、Q202、Q209）：M7–M12 采用，因代码清晰度、跨平台一致性与 Windows 渲染负担在 M13 彻底移除。

## 平台外壳

各平台共用完全一致的视觉设计、圆角、间距、配色与控件样式，零昂贵 CSS 背景模糊；只有以下“平台外壳”跟随操作系统（Q60、Q239）：

- 窗口恢复标准不透明原生窗口：macOS 保留红绿灯融入 `40px` 顶栏左缘的 Overlay 标题栏，Windows 保留右上角原生最小化/最大化/关闭按钮与标准窗口行为。
- 界面字体、快捷键修饰键显示（⌘ ⌥ ⇧ vs Ctrl Alt Shift）和原生菜单（系统菜单栏 vs 窗口内菜单）分别适配两平台。

## 主界面布局

M13 瘦身重整后的窗口骨架（Q240–Q244）：

- **顶部主工具栏（`40px`）**：移除原来只有 1 个按钮的左侧 `ActivityBar`；左缘放置“收起 / 展开侧栏”按钮，紧接紧凑的 **仓库 / Worktree / 分支** 层级切换器（去掉胶囊堆叠）；右侧放置 **更新 / 推送**、**PR / 终端** 面板开关与 **设置** 按钮（有可用应用更新时在设置按钮上显示提示点或轻量入口）。**克隆**归入仓库下拉底部、欢迎页、菜单栏和命令面板；**诊断信息**与**应用更新**归入设置页、菜单栏和命令面板。
- **左侧工具侧栏（可拖拽调宽）**：顶部清爽的三段切换页签（**提交 / Stash / 回收区**）。“提交”页签上方是改动树（暂存区模式下分已暂存、未暂存、未跟踪三组，未跟踪默认收起；也支持更改列表模式），下方是**支持上下拖拽分隔高度的卡片式提交区**（顶部轻工具行：修改上一次提交、最近记录、AI 生成/取消、更多选项；中间简洁输入框与 72 字柔和提示；底部审阅进度徽标 + 提交 / 提交并推送按钮；hook 输出与提交结果在提交区展开）。
- **主区域（页签工作区）**：顶层是 `36px` 简洁页签栏，**提交日志**常驻首位，后面排布打开的 diff、三方合并、文件历史与 **GitHub PR** 页签（Q241）。
  - 打开 diff 页签时，页签栏下方合并为**单条统一上下文栏**（左侧文件路径面包屑 + 两侧对比标签如 `HEAD → 工作区`，右侧上一处/下一处差异、并排/统一视图切换、显示选项弹窗、标记已审阅与整文件操作），取代旧版三层叠放头栏（Q244）。
  - 提交日志保留 Q201（分支图完整渲染、引用标签独立一列不省略、窄窗横向滚动），顶部收束为单行清爽筛选栏，重绘精细矢量分支图、小圆角引用胶囊与清晰元信息详情分栏（Q244）。
- **底部可拖拽抽屉（默认收起）**：统一承载 **内置终端** 与 **Git 命令日志**，支持切标签与自由拖拽高度（Q241）。
- **底部状态栏（`24px`）**：显示当前分支、领先/落后数、环境加载或自动刷新异常提示、快捷打开 Git 命令日志与审阅进度。
- **设置弹窗**：居中宽敞两栏模态弹窗（上限约 `920×640`，轻量压暗遮罩无重模糊），左侧搜索 + Lucide 图标分组导航，右侧清晰分组卡片（Q242）。
- 首版不做多窗口。

## 文件状态表示

M13 改用高可读中性文件名配行尾等宽语义状态徽标（Q243，取代 Q128）：

- 每行展示 Material Icon Theme 文件类型图标、清晰高对比中性色文件名（删除文件加淡删除线）、淡灰目录路径与已审阅小对勾；
- 行尾右侧显示克制语义色的等宽单字母状态（`M` 琥珀、`A` 绿、`D` 红、`R` 蓝、`?` 灰）；
- 鼠标悬停行时，行尾状态字母平滑切换为行内快捷操作图标（暂存 / 取消暂存 / 丢弃），不抖动且不挤占文件名宽度。

## 刷新与执行中反馈

- 刷新后，同文件在原组仍有改动则留在原位置；移到另一组时优先跟随同文件；完全离开改动列表时选择原位置附近的文件，没有可选项则清空 diff（Q89）。
- 新快照到来后旧 hunk 和旧确认失效，不把旧序号重新解释为新快照中的操作目标。
- 写操作期间仍可浏览、切换文件和 worktree；同 worktree 的其他写入口禁用，不积压点击队列（Q90）。
- 已发起操作始终作用于原目标；结果提示标明所属 worktree，不能因切换把旧响应显示成当前 worktree 的内容。
- 只实时监视当前 worktree；切换 worktree、回到前台时重新核对，保留手动刷新入口（Q88）。
- 监视失败时持续显示“自动刷新不可用”，不能悄悄停止刷新；手动刷新、回到前台核对仍可用，写操作是否允许取决于写前读取与指纹校验，而不是监视器是否可用（Q95）。
- 写操作期间关闭窗口或退出，提供“等待完成后关闭／退出”与“留在应用”，先保留窗口和进程；不提供取消写操作或直接杀掉 Git 的入口。正常完成并记录结果后执行原请求；结果待核对时先展示情况，不静默退出（Q96）。

## 审阅标记的操作

- 已审阅的文件在文件列表中显示一个小图标；diff 页签工具栏的“标记为已审阅”按钮切换标记，不跳转，类似 GitHub PR 中的 Viewed（Q121，取代 Q37 的行右侧勾选框；Q94）。
- 快捷键 ⌥⌘R 只标记、不取消；标记后按当前文件列表顺序跳到下一个未审阅文件，同文件跨组去重，末尾可回到开头，目标在折叠组里则展开该组。全部已审阅时留在当前文件，提示“全部已审阅”（Q94）。
- 同一个文件同时出现在“未暂存”和“已暂存”两组时，两行显示同一个标记。
- 标记失效时小图标直接消失，不额外提示。
- 审阅进度显示在提交按钮旁，规则见 [产品方向](./product-direction.md#审阅标记)。

## diff 显示

- 默认左右并排，一键切换为统一视图，选择会被记住（Q17）。
- 并排视图照 Rebased 的左右对照法：两栏各自连续显示，不插空行；中间窄栏带两列行号，用弧形色带连起对应的块，并在窄栏上用 » / « 暂存、取消暂存一块（Q138）。
- 可以打开“忽略空白”，分三档：忽略行尾空白、忽略所有空白、同时忽略空行。diff 改用 Git 对应的忽略空白结果显示；前两档仍能按块暂存、取消暂存、丢弃，补丁由显示的同一个块生成，用 Git 的忽略空白方式执行，纯空白改动留在原处，关掉后可见；“同时忽略空行”一档只用于查看，块按钮变灰。保证操作的就是看到的（Q140，修订 Q17）。
- M7 起 diff 的工作区一侧可以编辑，保存前做写前校验，文件在外部被改过就拒绝覆盖；不做项目文件树和文件编辑器（Q122，取代 Q18）。M7 之前 diff 只读。
- 工作区编辑用 ⌘S 明确保存。切文件或 worktree 保留未保存编辑；关闭时提供保存、放弃、取消；暂存或提交前处理相关未保存编辑（Q177）。未保存编辑自动保存为本机编辑草稿，重启或崩溃后提供恢复；磁盘文件已变化时保留两版供对比，不自动覆盖（Q186）。具体可编辑范围与恢复交互仍在 M7 访谈中。
- lock 文件（如 `pnpm-lock.yaml`）、二进制文件和超大文件默认收起，点开才渲染（Q32）。
- 回收区的恢复对比也使用同一个只读 diff 视图（Q29）。
- hunk 的来源和渲染约束见 [ADR-0004](./adr/0004-hunks-come-from-git.md)，渲染原型的验收标准见 [技术方向](./technical-direction.md#diff-渲染原型)。

### 回收区恢复

- 即使丢弃的是一个 hunk，恢复的也是该文件丢弃前的完整工作区状态；界面不能把它描述成只恢复这一个 hunk，恢复不改变暂存区（Q85）。
- 发生后续变化时，文本展示当前内容与保存内容的只读 diff，由用户自行复制；二进制展示两个版本的大小、记录时间等信息，保存版本可另存为未被占用的新路径，不提供强制覆盖原文件（Q29、Q86）。
- 原 worktree 身份无法确认时说明原因，回收记录仍可查看直到正常到期，不提供直接恢复到新目录的操作（Q87）。

### 文件历史

- 提交列表载入后即可浏览，默认选中第一条并读取它的 diff。切换条目时，右侧显示新条目的加载状态，随后显示它的 diff。即使上一条的请求更晚完成，右侧也跟随当前选择（Q232）。

## 快捷键

核心操作沿用 JetBrains 在 macOS 上的默认快捷键（Q19，Q33 再次确认）：

| 快捷键 | 操作 |
| --- | --- |
| ⌘K | 提交 |
| ⌘D | 查看 diff |
| ⌘S | 保存工作区 diff 的编辑（M7，Q177） |
| F7 / ⇧F7 | 下一处 / 上一处差异 |
| ⌥⌘A | 暂存 |
| ⌥⌘Z | 丢弃改动 |
| ⌥⌘R | 标记已审阅并跳到下一个未审阅的文件（Q37） |
| ⌘⇧A | 命令面板（对应 JetBrains 的 Find Action） |
| ⌘+ / ⌘- | 调整 diff 字体大小（Q39） |
| ↑ / ↓ | 在文件列表中移动 |
| 空格 | 暂存或取消暂存当前文件 |

命令面板不用 ⌘K（⌘K 保留给提交）；M7 起在「设置 → 快捷键」中支持自定义快捷键、冲突替换与恢复默认（Q139）。

Windows 版沿用 JetBrains 在 Windows 上的默认键位：⌘ 换成 Ctrl，⌥ 换成 Alt，例如 Ctrl+K 提交、Ctrl+Alt+A 暂存、Ctrl+Shift+A 命令面板、Ctrl+= / Ctrl+- 调整字号（Q61）。焦点在提交信息框等输入框里时，Ctrl+Alt 组合键不生效：德语、波兰语等键盘的 AltGr 等同于 Ctrl+Alt，用来输入 ą、@ 等字符，不能误触发暂存或丢弃。

### 快捷键作用范围

- 暂存区模式下，⌥⌘A、⌥⌘Z 的整文件操作面向改动树选区。取消选中最后一个文件后，这两个快捷键停用，右侧仍可显示该文件的 diff（Q93、Q227、Q228）。空格保留文件列表中的整文件暂存／取消暂存动作。
- 选中 A、C 时，点击选区外 B 行的“暂存”只暂存 B，A、C 继续保持选中（Q229）。
- Shift 连选沿展开后的文件行顺序取两端之间的条目，跳过折叠目录里的文件（Q230）。
- 折叠目录会保留其中已有的选区。例如先选中 `src/a.ts` 和 `src/b.ts` 再折叠 `src`，目录名旁显示“已选 2”，下一次批量暂存会包含这两项（Q231）。
- 块标题提供明确的“暂存此块／取消暂存此块／丢弃此块”按钮（用词按 Q135），按当前组和文件能力显示，可用键盘聚焦并激活。M2 不新增 hunk 专用快捷键，不按鼠标位置或屏幕上最近的 hunk 猜目标。
- 输入框、弹窗和按钮有自己的键盘行为，不能穿透到后台文件操作。

## 菜单

- 系统菜单栏使用 macOS 原生菜单：Revia、文件、编辑、仓库、提交、视图、窗口、帮助，菜单项旁显示快捷键（Q38）。
- 右键菜单也使用原生菜单。
- 窗口内部弹出层由 `@base-ui/react`（Popover）提供定位与焦点管理，对话框使用原生 `<dialog>` + `useModalDialog`（Q38、M13）。

## 错误展示

| 类型 | 例子 | 展示位置 |
| --- | --- | --- |
| 操作被拒绝 | diff 指纹对不上、锁文件被占用 | diff 区顶部的提示条，同时自动刷新 |
| Git 命令失败 | hook 失败、签名失败 | 提交区下方展开 Git 的原始输出，可以复制 |
| 环境问题 | 找不到 git、版本过低 | 窗口顶部的全局提示条，带设置入口 |

测量面板只在自动测量、长测等测量模式下显示；工具栏不显示 Git 版本、文件数等调试信息，也不放字号按钮（字号用 ⌘+／⌘−）（Q101）。

另有默认隐藏的“Git 命令日志”面板，记录 Revia 执行过的每条 Git 命令的参数、退出码、耗时和输出，对应 JetBrains Git 窗口中的 Console 标签（Q36）。

Git 超时或中断后无法确认写入结果时，显示“结果待核对”，不能显示成“未执行”或“已撤销”；保留回收记录，重新核对真实状态，不自动继续操作或提供盲目重试（Q91）。这是操作结果状态，不改变上述错误分类。

## 首次打开

没有仓库时提供“添加仓库”，支持 ⌘O 和拖入文件夹；M7 增加克隆入口，填写 URL 和目标目录，分支、浅克隆和递归子模块放入高级选项（Q35、Q179）。环境检查没有问题时不显示任何提示。完整规则见 [产品方向](./product-direction.md#首次打开)。

## M7 终端与应用更新

- 内置终端按 worktree 保留独立会话，允许多个会话，切换时保留；关闭运行中进程前先确认（Q178）。Git 命令日志仍是日志，不把它当成终端。
- 应用更新默认稳定版，预发布版由用户开启；提示后由用户确认下载与安装。安装前处理未保存编辑、Git 写入和终端会话，再确认重启（Q181）。

## 设置

设置采用居中宽敞的两栏模态弹窗：左上角搜索，左侧 Lucide 图标分组导航，右侧清晰表单卡片（Q242）。设置项清单如下：

| 分类 | 设置项 | 里程碑 |

## 界面语言

M6 起可在设置中即时切换简体中文 / English 并记住选择；首次启动未设置语言时，中文系统使用简体中文，其他系统使用英文（Q163、Q164，取代固定中文默认与 Q139 的 M7 排期）。切换不清空页签、提交草稿或合并编辑内容，英文界面也须验收窄窗口布局。

文案通过 x18n 集中维护和校验，不写死在组件中；Rust 用户报错通过错误类型和参数在前端翻译。用户内容、Git 原始输出、调试与测量日志不翻译。HEAD、worktree、rebase 等 Git 术语保留英文；中文界面的 hunk 按 Git 官方中文翻译叫“块”（Q135）。用词与 [术语表](../GLOSSARY.md) 一致。

# UI 方向

更新日期：2026-10-24。状态：总体 UI 方向与 M2 访谈已确认；M2 补充回收区、刷新、执行中反馈与键盘作用范围（Q85–Q96），以及界面清理与美化（Q99–Q104、Q107）。

## 视觉风格

从 M4 起，**布局、功能和交互照 Rebased，外观照 VS Code**（Q119、Q131）：

- 布局与交互：区域划分与位置、各处的操作入口和行为，照本机安装的 Rebased 1.1.22（Q117、Q119）。
- 外观：配色、界面字体（系统字体）、控件样式与尺寸照 VS Code，配色来自所选的颜色主题（Q131、Q132）；界面图标用 Codicons，文件类型图标用 Material Icon Theme（Q130）。
- 颜色主题：浅色、深色各选一套，随系统深浅色切换（Q50、Q132）。内置 VS Code Light 2026、Atom One Light、VS Code Dark 2026、One Dark Pro；默认浅色 Atom One Light，深色 One Dark Pro。
- 文件名按状态上色，颜色取颜色主题中的 Git 状态色，不显示状态字母（Q128）。
- 每完成一屏，与 Rebased（布局、交互）和 VS Code（外观）并排截图，经用户认可再继续（Q125）。界面文字用中文，沿用术语表（Q124）。
- 确认的效果图见 [M4 效果图](./milestones/m4/mockups/)。

Revia 独有的功能只用 Rebased 已有的控件形式表达，不自创控件（Q119）：

| 独有功能 | 放在哪里 |
| --- | --- |
| 回收区 | 提交工具窗口中与“提交”并列的页签，即 Rebased 放“搁置”的位置 |
| 审阅标记 | 文件列表中的小图标、diff 页签工具栏的“标记为已审阅”按钮、提交按钮旁的审阅进度（Q121） |
| 写前校验失败、结果待核对 | 编辑器顶部提示条或右下角通知气泡 |
| 提交前快照 | 提交完成的通知气泡中说明存了哪些文件 |

本文件中更早的界面细节与上述方向冲突时，布局与交互照 Rebased，外观照 VS Code，不再逐项追问；安全边界和 Revia 独有功能除外（Q129、Q131）。

未采用的方向：

- **macOS 原生质感**（Q15、Q103 的原方向：系统强调色、侧栏半透明）：任务 13 画过两版效果图，用户不满意。
- **参照 Rebased 自行设计**（Q107，M2 任务 13 的实现）：用户认为比 Rebased 更难看、更难用、看不懂。
- **外观一比一照 Rebased**（Q119 原定）：用户认为 Rebased 的外观不好看，改照 VS Code（Q131）。
- **中性的跨平台开发工具风格**：缺少辨识度。Windows 版（M8）仍用“共享设计 + 平台外壳”的方式，见下一节（Q60）。

## 平台外壳

各平台共用同一套布局、信息密度、配色和 Git 状态色；只有以下“平台外壳”跟随操作系统（Q60）：

界面字体用各平台的系统字体（同 VS Code，Q131）；代码字体默认 JetBrains Mono，可在设置中修改（Q133）；面板不透明，不随平台变化（取代 Q60 原表中的等宽字体和侧栏材质两行）。

| 部分 | macOS | Windows |
| --- | --- | --- |
| 窗口控制按钮 | 左上角红绿灯，融入工具栏 | 右上角最小化、最大化、关闭 |
| 快捷键的修饰键 | ⌘ ⌥ ⇧ | Ctrl Alt Shift |
| 菜单 | 屏幕顶部的系统菜单栏 | 窗口内的原生菜单 |

## 主界面布局

照 Rebased 的默认布局（Q119），具体尺寸与交互在 M4 规格中按 Rebased 实测写定：

- 顶部主工具栏：仓库组件；worktree 下拉，每行显示分支、有无未提交改动、进行中的操作、领先和落后数，取代原定的 worktree 侧栏（Q126）；M5 起加入分支组件与更新、推送按钮。
- 左侧工具窗口图标条。“提交”工具窗口有“提交”和“回收区”两个页签：“提交”页签上方是改动列表（暂存区模式下分已暂存、未暂存、未跟踪三组，Q120；未跟踪一组默认收起，Q30），下方是提交区：“修改上一次提交”、提交信息框、“提交”和“提交并推送”按钮、审阅进度（Q20、Q21、Q23、Q122）。hook 输出和提交结果在提交区展开显示。
- 主区域是编辑器页签：M5 起默认显示提交日志，日志右侧是所选提交的改动文件和详情；双击文件在页签中打开 diff。M4 还没有日志，主区域只放 diff 页签。
- 底部状态栏。
- 首版不做多窗口。

## 文件状态表示

照 Rebased：文件名按 Git 状态上色，行右侧不再显示状态字母（Q128，取代 Q31）。各状态的颜色在 M4 按 Rebased 实测和 IntelliJ 主题写定。

原 Q31 的方案（文件名保持正常颜色，右侧用带颜色的单字母 M、A、D、R、U、? 标状态）不再采用。

## 刷新与执行中反馈

- 刷新后，同文件在原组仍有改动则留在原位置；移到另一组时优先跟随同文件；完全离开改动列表时选择原位置附近的文件，没有可选项则清空 diff（Q89）。
- 新快照到来后旧 hunk 和旧确认失效，不把旧序号重新解释为新快照中的操作目标。
- 写操作期间仍可浏览、切换文件和 worktree；同 worktree 的其他写入口禁用，不积压点击队列（Q90）。
- 已发起操作始终作用于原目标；结果提示标明所属 worktree，不能因切换把旧响应显示成当前 worktree 的内容。
- 只实时监视当前 worktree；切换 worktree、回到前台时重新核对，保留手动刷新入口（Q88）。
- 监视失败时持续显示“自动刷新不可用”，不能悄悄停止刷新；手动刷新、回到前台核对仍可用，写操作是否允许取决于写前读取与指纹校验，而不是监视器是否可用（Q95）。
- 写操作期间关闭窗口或退出，提供“等待完成后关闭／退出”与“留在应用”，先保留窗口和进程；不提供取消写操作或直接杀掉 Git 的入口。正常完成并记录结果后执行原请求；结果待核对时先展示情况，不静默退出（Q96）。

## 审阅标记的操作

- 已审阅的文件在文件列表中显示一个小图标；diff 页签工具栏的“标记为已审阅”按钮切换标记，不跳转，类似 GitHub PR 中的 Viewed（Q121，取代 Q37 的行右侧勾选框；Q94）。
- 快捷键 ⌥⌘R 只标记、不取消；标记后按当前文件列表顺序跳到下一个未审阅文件，同文件跨组去重，末尾可回到开头，目标在折叠组里则展开该组。全部已审阅时留在当前文件，提示“全部已审阅”（Q94）。
- 同一个文件同时出现在“未暂存”和“已暂存”两组时，两行显示同一个标记。
- 标记失效时小图标直接消失，不额外提示。
- 审阅进度显示在提交按钮旁，规则见 [产品方向](./product-direction.md#审阅标记)。

## diff 显示

- 默认左右并排，一键切换为统一视图，选择会被记住（Q17）。
- 不提供“忽略空白”等会改变 hunk 划分的显示选项，保证看到的就是要暂存的（Q17）。
- M7 起 diff 的工作区一侧可以编辑，保存前做写前校验，文件在外部被改过就拒绝覆盖；不做项目文件树和文件编辑器（Q122，取代 Q18）。M7 之前 diff 只读。
- lock 文件（如 `pnpm-lock.yaml`）、二进制文件和超大文件默认收起，点开才渲染（Q32）。
- 回收区的恢复对比也使用同一个只读 diff 视图（Q29）。
- hunk 的来源和渲染约束见 [ADR-0004](./adr/0004-hunks-come-from-git.md)，渲染原型的验收标准见 [技术方向](./technical-direction.md#diff-渲染原型)。

### 回收区恢复

- 即使丢弃的是一个 hunk，恢复的也是该文件丢弃前的完整工作区状态；界面不能把它描述成只恢复这一个 hunk，恢复不改变暂存区（Q85）。
- 发生后续变化时，文本展示当前内容与保存内容的只读 diff，由用户自行复制；二进制展示两个版本的大小、记录时间等信息，保存版本可另存为未被占用的新路径，不提供强制覆盖原文件（Q29、Q86）。
- 原 worktree 身份无法确认时说明原因，回收记录仍可查看直到正常到期，不提供直接恢复到新目录的操作（Q87）。

## 快捷键

核心操作沿用 JetBrains 在 macOS 上的默认快捷键（Q19，Q33 再次确认）：

| 快捷键 | 操作 |
| --- | --- |
| ⌘K | 提交 |
| ⌘D | 查看 diff |
| F7 / ⇧F7 | 下一处 / 上一处差异 |
| ⌥⌘A | 暂存 |
| ⌥⌘Z | 丢弃改动 |
| ⌥⌘R | 标记已审阅并跳到下一个未审阅的文件（Q37） |
| ⌘⇧A | 命令面板（对应 JetBrains 的 Find Action） |
| ⌘+ / ⌘- | 调整 diff 字体大小（Q39） |
| ↑ / ↓ | 在文件列表中移动 |
| 空格 | 暂存或取消暂存当前文件 |

命令面板不用 shadcn/ui 示例中常见的 ⌘K，因为 ⌘K 已经是提交。首版不支持自定义快捷键。自用阶段也使用这套快捷键。

Windows 版沿用 JetBrains 在 Windows 上的默认键位：⌘ 换成 Ctrl，⌥ 换成 Alt，例如 Ctrl+K 提交、Ctrl+Alt+A 暂存、Ctrl+Shift+A 命令面板、Ctrl+= / Ctrl+- 调整字号（Q61）。焦点在提交信息框等输入框里时，Ctrl+Alt 组合键不生效：德语、波兰语等键盘的 AltGr 等同于 Ctrl+Alt，用来输入 ą、@ 等字符，不能误触发暂存或丢弃。

### 快捷键作用范围

- ⌥⌘A、⌥⌘Z 操作当前文件，不能因焦点在 diff 中就变成操作某个 hunk；空格保留文件列表中的整文件暂存／取消暂存动作（Q93）。
- 块标题提供明确的“暂存此块／取消暂存此块／丢弃此块”按钮（用词按 Q135），按当前组和文件能力显示，可用键盘聚焦并激活。M2 不新增 hunk 专用快捷键，不按鼠标位置或屏幕上最近的 hunk 猜目标。
- 输入框、弹窗和按钮有自己的键盘行为，不能穿透到后台文件操作。

## 菜单

- 系统菜单栏使用 macOS 原生菜单：Revia、文件、编辑、仓库、提交、视图、窗口、帮助，菜单项旁显示快捷键（Q38）。
- 右键菜单也使用原生菜单。
- 不使用 shadcn/ui 的 Menubar 和 Context Menu。shadcn/ui 只用于窗口内部的组件：命令面板、对话框、弹出层、提示、可调整面板。

## 错误展示

| 类型 | 例子 | 展示位置 |
| --- | --- | --- |
| 操作被拒绝 | diff 指纹对不上、锁文件被占用 | diff 区顶部的提示条，同时自动刷新 |
| Git 命令失败 | hook 失败、签名失败 | 提交区下方展开 Git 的原始输出，可以复制 |
| 环境问题 | 找不到 git、版本过低 | 窗口顶部的全局提示条，带设置入口 |

测量面板只在自动测量、长测等测量模式下显示；工具栏不显示 Git 版本、文件数等调试信息，也不放字号按钮（字号用 ⌘+／⌘−）（Q101）。

另有默认隐藏的“Git 命令日志”面板，记录 Revia 执行过的每条 Git 命令的参数、退出码、耗时和输出，对应 JetBrains Git 窗口中的 Console 标签（Q36）。

Git 超时或中断后无法确认写入结果时，显示“结果待核对”，不能显示成“未执行”或“已撤销”；保留回收记录，重新核对真实状态，不自动继续操作或提供盲目重试（Q91）。这是操作结果状态，不改变上述错误分类。

## 首次打开

没有仓库时，窗口中间只显示“添加仓库”，支持 ⌘O 和拖入文件夹；环境检查没有问题时不显示任何提示（Q35）。完整规则见 [产品方向](./product-direction.md#首次打开)。

## 设置

首版只提供以下设置（Q39）：

- Git 程序路径
- 合并工具
- 重新加载环境
- 回收区：查看、清空
- diff 字体大小（也可用 ⌘+ / ⌘- 调整，调整后记住）
- 暂存区模式 / 更改列表模式（Q120，M7）
- 颜色主题：浅色、深色各选一套（Q132）
- 代码字体与字号（Q133）

不提供自定义快捷键和行距设置。

## 界面语言

首版界面只提供简体中文（Q40）。文案集中管理，不写死在组件中，以后增加英文时不需要修改组件。HEAD、worktree、rebase 等 Git 术语保留英文；hunk 按 Git 官方中文翻译叫“块”（Q135）。用词与 [术语表](../GLOSSARY.md) 一致。

# 产品方向

更新日期：2026-10-20。状态：总体方向与 M2 访谈已确认（Q78–Q97）；实施与验收见 [M2 规格](./milestones/m2/spec.md)。

## 定位

Revia 是一个遵循标准 Git 工作流、重视差异审阅和提交整理的轻量桌面 Git 客户端。最终提供 macOS Apple Silicon 版、Windows x64 安装版和 Windows x64 便携版；首版只做 macOS，Windows 放在首版验证之后（Q55）。它借鉴 JetBrains 的 Git 操作关系和快捷键，而不是照搬外观。

明确不做：

- **Rebased 复刻**：不追求 JetBrains Git 功能的全集。
- **GitButler 式的虚拟分支**：不在 Git 之上发明自己的工作流模型。
- **IDE 里的 Git 插件**：Revia 是独立应用，与编辑器并行使用。

## 取舍顺序

三个特点冲突时，按以下顺序取舍（Q5）：

1. **提交可信**：清楚区分未暂存改动、已暂存改动和最终提交内容；不偷偷改工作区；不自动执行危险操作。
2. **审阅舒服**：diff 清楚，键盘操作顺手，文件切换快。
3. **项目切换高效**：多个仓库和 worktree 的状态一眼可见。

例如“更快”和“更稳”冲突时选更稳：每次写操作前都重新读取仓库状态，即使多花几十毫秒。

## 核心工作流

审阅 diff → 选择变更 → 提交（Q2）。首版的其他能力都围绕这个闭环取舍。

## 首版范围

| 能力 | 首版提供 | 首版不提供 | 编号 |
| --- | --- | --- | --- |

| 未跟踪文件 | 单独一组，默认收起；只能整文件暂存；不显示被忽略的文件 | 对未跟踪文件按 hunk 暂存 | Q30 |

| 审阅标记 | 按文件标记已审阅；内容变化后自动失效；显示审阅进度 | 按 hunk 标记；用标记阻止提交 | Q20 |

### M2 写操作范围

M2 每次只操作一个文件或一个 hunk，不增加文件多选、“全部暂存”和批量丢弃（Q79）。整文件与 hunk 操作的适用范围如下（Q81–Q83）：

| 文件情况 | M2 允许的 Git 写操作 | 限制 |
| --- | --- | --- |
| 普通已跟踪文本文件 | 整文件或按 hunk 暂存、取消暂存、丢弃未暂存改动 | 不一步丢弃已暂存内容 |
| 二进制文件、仅权限变化、重命名 | 整文件暂存、取消暂存、丢弃未暂存改动 | 不提供 hunk 操作 |
| 未跟踪文件 | 整文件暂存 | 不提供按 hunk 暂存、丢弃或删除 |
| 符号链接、子模块、无法无损处理的非 UTF-8 路径 | 无，只读并说明限制原因 | 中文、空格等正常文件名不在限制之列 |
| Git 仍标记为未解决冲突的文件 | 无，只读并提示到外部处理 | 不通过普通暂存隐含地标记冲突已解决 |

只读限制优先于其他文件类型的操作能力。完整的进行中操作识别仍在 M3，外部合并工具入口仍在 M4；这两个里程碑不因 M2 的冲突文件保护而提前（Q82）。

整文件快捷键不随 diff 焦点改变作用范围；hunk 使用明确的操作按钮，不根据鼠标或屏幕位置猜目标，具体入口见 [UI 方向](./ui-direction.md#快捷键作用范围)（Q93）。

## 审阅标记

审阅标记以文件为单位，记录的是“HEAD 中的版本 + 工作区中的版本”这一对内容（Q20）：

| 场景 | 结果 |
| --- | --- |
| 暂存或取消暂存这个文件 | 标记保留，内容没有变化 |
| 在编辑器中修改了这个文件 | 标记失效 |
| 只提交了这个文件的一部分 | HEAD 变化，剩余部分的标记失效，需要重新审阅 |
| 重启 Revia | 标记保留；内容变化过的标记自然失效 |

- 标记保存在 Revia 自己的数据目录中，按 worktree 分开。
- worktree 移动、删除重建后身份不明确时，不因路径相同而继承原审阅标记（Q87）。
- 标记不阻止提交，只在提交按钮旁显示审阅进度，例如“已审阅 3/5”。
- 宁可失效得勤一点，也不能该失效时没失效。
- 勾选框只切换标记、不跳转；⌥⌘R 只标记、不取消，再按文件列表顺序寻找下一个未审阅文件，同文件跨组去重、末尾可回到开头，并展开目标所在折叠组。全部已审阅时留在当前文件并提示（Q94）。

## 提交

### hooks

- hooks 照常执行，目标是和在终端里进入这个 worktree 再执行 `git commit` 的效果一致（Q21）。
- 运行环境按 worktree 解析，详见 [技术方向](./technical-direction.md#运行环境)。
- hook 的输出实时显示；失败时保留已经写好的提交信息。
- 每次提交可以勾选“跳过 hooks”，默认不勾，提交后自动复原。这是环境出问题时的退路。

### 提交前快照

- 存在部分暂存的文件时，提交前自动把这些文件的工作区内容存入回收区（Q22）。
- 提交完成后，如果 hooks（例如 lint-staged 格式化）修改了工作区或暂存区的文件，在提交结果中列出这些文件。

### 修改上一次提交

- 提交区提供“修改上一次提交”开关，对应 JetBrains 的 Amend；勾选时预填上一次的提交信息（Q23）。
- 上一次提交已经包含在上游跟踪分支中（按本地记录判断）时，显示警告并要求再次确认。
- 有进行中的操作时不可用。

### 提交信息框

- 单个多行输入框；首行超过 72 个字符时提示，不阻止提交（Q24）。
- 读取 Git 的 `commit.template` 配置。
- 可以从最近 20 条提交信息中选用。
- 每个 worktree 单独保留未完成的草稿，切换时不丢失。
- 提交信息为空时不能提交。

### 签名

遵循 Git 配置，不提供签名相关设置，也不专门测试签名场景；签名失败时原样显示 Git 的错误（Q25）。

## 外部修改

- M2 只实时监视当前选中的 worktree 及相关 Git 元数据，自动刷新状态；切换 worktree、回到前台时重新核对，并保留手动刷新（Q26、Q88）。不为全部登记仓库常驻监视，完整概览随 M4 侧栏完善。
- 写操作执行前校验用户看到的 diff 是否仍然有效，对不上就拒绝执行、刷新界面并提示“文件已变化，请重新确认”，见 [ADR-0005](./adr/0005-write-ops-carry-diff-fingerprint.md)。
- M2 的校验范围是操作涉及的文件及相关版本、状态和路径；无关文件变化不阻止操作。即使只操作一个 hunk，同一文件其他部分的相关变化也必须拒绝，见 [ADR-0009](./adr/0009-file-scoped-write-fingerprints.md)（Q80）。
- 遇到 `index.lock` 时短暂重试，仍被占用就提示用户，绝不删除锁文件。
- 刷新后优先保留原组中的同一文件，其次跟随移到另一组的同一文件；文件完全离开改动列表时选原位置附近的文件，无可选项则清空 diff。更新后的旧 hunk 和旧确认失效，不能把旧序号套到新快照（Q89）。
- 文件监视失败时持续提示“自动刷新不可用”，保留手动刷新与回到前台核对；只要写前仍能重新读取状态且指纹校验通过就允许操作，读取或校验失败则拒绝写入，不静默降级（Q95）。

### 写操作执行中

- 允许继续浏览和切换文件、worktree，但切换界面不改变已发起操作的目标（Q90）。
- 同一个 worktree 一次只执行一个 Revia 写操作，期间禁用该 worktree 的其他写入口，不把连续点击积压成操作队列。
- 结果提示归属原 worktree，旧响应不得覆盖当前界面。
- 回收区保存后操作中断（例如执行途中应用退出）、Git 超时等导致结果无法确定时，保留已保存记录，显示“结果待核对”，重新核对真实状态；不自动继续丢弃、恢复或重跑命令。下一次写入基于重新读取的状态，超时不等于没有发生变化（Q91）。
- 写操作期间请求关闭窗口或退出时，先保留窗口和进程，提供“等待完成后关闭／退出”或“留在应用”；不为关闭窗口杀掉 Git，不提供未经验证的取消写操作。正常完成并记录结果后执行原请求；若结果待核对，先展示情况，不静默退出。系统强退或崩溃仍按 Q91 处理（Q96）。

## 回收区

- 保存两类内容：丢弃前的原内容（Q9），以及提交前快照（Q22）。
- 每条回收记录包括时间、来源和对应文件的工作区状态，绑定原仓库与原 worktree，存放在 Revia 的数据目录中，不放进仓库（Q29、Q87）。
- M2 即使只丢弃一个 hunk，也保存该文件丢弃前的完整状态：内容、相关路径、存在状态和可执行权限。恢复回到这次丢弃前的工作区状态，不改变暂存区，不自动重放反向补丁；接受由此增加的存储占用（Q85，见 [ADR-0010](./adr/0010-recovery-records-preserve-worktree-state.md)）。
- 恢复时，当前状态与丢弃完成后的状态一致才直接写回；不能拿当前状态与保存的丢弃前内容比较来判断是否有后续变化。发生后续变化时不覆盖，文本用只读 diff 对比当前内容和保存内容，由用户自行复制需要的部分（Q29、Q85）。
- 二进制恢复遇到后续变化时，展示两个版本的大小、记录时间等信息；保存版本可另存为未被占用的新路径，不提供强制覆盖原文件（Q86）。
- worktree 移动、删除重建后身份不明确时，不按路径相同猜测迁移，不直接恢复到新目录；记录仍保留供查看直到正常到期（Q87）。
- 超过 14 天自动清理。
- 不使用 `git stash` 或 reflog 实现：stash 会出现在用户自己的 `git stash list` 中，reflog 也不保护从未提交过的内容。

## 合并工具

- 冲突文件用外部合并工具打开，Revia 不修改用户的 Git 配置（Q12、Q28）。
- 用户配置了 `merge.tool` 时直接使用。
- 没有配置时，第一次需要时列出 Git 检测到可用的工具让用户选择一次，保存在 Revia 的设置中，之后用 `git mergetool --tool=<所选工具>` 打开。

## 首次打开

- 没有仓库时，窗口中间只显示“添加仓库”：⌘O 选择文件夹，或把文件夹拖进窗口（Q35）。
- 选中的是某个 worktree 而不是主目录时，自动归到所属仓库下，并列出该仓库的其他 worktree。
- 选中的不是 Git 仓库时给出提示，不提供 `git init`。
- 首次启动检查 Git 程序和运行环境，没有问题就不打扰，有问题才显示。
- 不做新手引导或教程。

## 验证计划

分两个阶段（Q14）：

1. **自用**：连续 2 周，自己 Vue 和 Swift 项目的日常提交都通过 Revia 完成。每次不得不回到终端或 IDE，都记录原因。这个阶段不做应用签名。
2. **试用**：邀请 3–5 位熟悉 JetBrains Git 的开发者试用 1 周。试用结束后他们仍主动用它审阅和提交，才算成功。试用用的是未签名的版本（Q63），随包附一页带截图的“首次打开说明”：在“系统设置 → 隐私与安全性”中点“仍要打开”。

**硬性红线**：只要出现一次“提交内容与界面显示不一致”或“改动丢失”，就暂停新功能，先修复。

### 试用反馈

- 不收集任何遥测，不联网上报（Q42）。
- 崩溃信息和 Git 命令日志只保存在本机。
- “帮助 → 导出诊断信息”把日志和环境信息（macOS、Git、Revia 的版本）打包，去掉文件内容和 diff；导出前可以预览，由试用者自己发送。

### M2 长期运行验收

Q78 补充 Q53 的验收口径，不把历史报告中的卡住记录当成当前版本已经复现的故障：

- M2 第一项仍是用当前正式工程复现和验证长期运行问题，不以每轮重启应用的短测替代。
- 使用 release 构建、可见窗口，在固定的一组文件和 worktree 上同进程连续操作 30 分钟，包括切换文件、切换视图和滚动。
- 允许首次加载和填充缓存时的内存增长；热身后不能持续增长，同时观察 Rust 主进程与相关 WebView 进程。
- 若无法复现旧问题，但长测达标并保留操作过程和内存趋势证据，可以继续 M2；报告写“未复现，长测通过”，不能写“已修复”。
- 若发生卡死或内存持续增长，先修复再继续；M2 功能完成后重新进行长测。
- [并排视图偶发慢帧](./milestones/backlog/01-split-scroll-hitch.md) 继续留在 backlog，不作为 M2 必须解决的项目；不得破坏已有滚动表现。若排查证明与长期卡住同源，再依据证据讨论处理范围（Q84）。

### M2 正确性与异常验收

采用两层验证，不以其中一层替代另一层（Q92）：

- 真实 Git 临时仓库的自动化验证：Rust 测试自行创建仓库和独立应用数据目录，不因 fixture 缺失而跳过并报告成功；通过可控制的时钟、外部修改、存储失败与执行阶段中断，验证 14 天清理、保存失败、过期 diff、锁占用及结果待核对等边界。
- 真实桌面验收：检查焦点和选中项、自动刷新、切换后的旧响应，以及前述长期运行表现。前端沿用类型检查、lint 和 build，不为 M2 新增前端测试框架；测试接口与工具由实施方设计。

## 安全边界

以下约束来自已确认的选择，后续设计不得突破：

- 写操作前重新校验状态，不基于过期界面执行（Q5、Q26）。
- 丢弃前、以及存在部分暂存文件的提交前，先把内容存入回收区；回收区独立于 Git（Q9、Q22）。
- 不代替用户继续或中止进行中的操作（Q12）。
- 不删除 Git 的锁文件，不修改用户的 Git 配置（Q26、Q28）。
- 界面显示的 hunk 与实际暂存的补丁来自同一份 Git 输出（Q18，见 [ADR-0004](./adr/0004-hunks-come-from-git.md)）。

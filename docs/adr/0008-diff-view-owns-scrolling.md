# diff 区域由程序接管滚动，不用浏览器原生滚动

M1 用浏览器原生滚动加只渲染可见行的方式，在真实桌面上快速甩动触控板时，可见区域会整块变白。原因是 WebKit 把滚动交给系统单独处理：画面先滚到新位置，网页还没来得及画出那里的内容，加大预渲染余量和底图都只能缓解。因此 diff 区域改为由程序接管滚动：程序直接接收触控板和滚轮事件（包括 macOS 的惯性滚动），在同一帧里同时更新滚动位置和要显示的行，画面不可能跑到内容前面。VS Code 的编辑器也是这样做的。

## Consequences

- 滚动条、点击滚动条空白处翻页、键盘的 ↑↓、PageUp/PageDown、Home/End 都要自己实现；拖选文字到边缘时自动滚动暂未实现。
- 不能为了“简化”改回原生滚动，否则快速滑动会重新出现白块。
- 小文件（2 万显示行以内）在首屏之后于后台预取全部行数据，快速滑动时数据已在内存中；更大的文件仍按可见范围分批获取（Q69）。

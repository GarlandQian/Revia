# diff 的 hunk 一律来自 Git

界面显示的 hunk 由 Rust 层解析 `git diff` 的输出得到。暂存、取消暂存或丢弃某个 hunk 时，补丁就由这同一个 hunk 生成。前端不用 JS diff 库重新计算差异。“忽略空白”同样交给 Git（Q140 修订）：显示用 `git diff` 的忽略空白选项，按块写操作用同一个 hunk 生成补丁、以 `git apply --ignore-whitespace` 执行，纯空白改动留在原处；“同时忽略空行”会让补丁行数对不上，这一档只用于查看。以此保证用户操作的就是看到的、将要暂存的。

原决定中的“diff 只读”已由 Q122 修改：M7 允许编辑工作区一侧，保存前做写前校验，外部已修改时拒绝覆盖；Q177 明确采用手动保存，并在暂存、提交前处理相关未保存编辑。这不改变本 ADR 对 Git hunk 的要求，也不开放历史版本编辑。

## Consequences

- diff 渲染组件必须能渲染外部给定的 hunk。以“传入两份文本、组件自己计算差异”为核心的方案（如 Monaco、CodeMirror 的 diff 组件）不能直接使用。
- 以后做按行暂存时，要在 Git 给出的 hunk 上改写补丁，而不是另算一份差异。
- 按段（界面上的“块”）暂存、取消暂存、丢弃时（Q142），同样在 Git 给出的 hunk 上按段改写补丁，与 `git add -p` 拆块相同；补丁仍带上下文严格应用，不用 `--unidiff-zero` 等放宽方式。

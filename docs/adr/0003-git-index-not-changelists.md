# 默认呈现 Git 暂存区，另提供互斥的更改列表模式

Revia 默认忠实呈现 Git 原生的暂存区：同一个文件可以同时有已暂存改动和未暂存改动，两者分别显示，终端和其他 Git 工具看到的是同一份状态。照 Rebased（Q120）另提供更改列表模式：按更改列表组织未提交改动，勾选的文件和 hunk 就是下一次提交的内容。两种模式与 IntelliJ 一样互斥，同一时间只启用一种，在设置中切换；这样不会同时维护两套分组，“下一次提交到底包含什么”在任一模式下都只有一个答案，符合“提交可信”优先的取舍。代价是更改列表只存在于 Revia 内部，终端和其他 Git 工具看不到；切换模式时用户要理解两种模式下提交内容的来源不同。

最初的决定是只呈现暂存区、不做 Changelists，理由是两套分组模型会让提交内容变得含糊；2026-10-26 改为照 Rebased 提供两种互斥模式（Q120），互斥正是为了保留原来的理由。

## Consequences

- 默认是暂存区模式，Q8 的忠实呈现在该模式下保持不变。
- 更改列表按 worktree 保存在 Revia 的数据目录中，切换模式不删除已有分组。
- 更改列表模式下提交时，勾选内容仍以 Git 生成的 hunk 写入暂存区后提交（ADR-0004），写前校验 diff 指纹（ADR-0005）不变。
- 更改列表模式下，终端里已经暂存的内容如何处理，照 Rebased 的实测行为写入实施该模式的里程碑规格（M7），不在此处预设。

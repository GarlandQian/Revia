# 写操作必须携带用户看到的 diff 指纹

编辑器、终端和其他工具会和 Revia 同时修改仓库，界面上的状态随时可能过期。因此暂存、取消暂存、丢弃、提交等写操作都必须附带用户当时看到的 diff 的指纹；Rust 层执行前重新计算并比对，对不上就拒绝执行、刷新界面，并提示用户重新确认。文件监视只负责尽快刷新，不能替代执行前的校验。这样做每次写操作都要多算一遍 diff，并且所有写操作的接口都要带上指纹参数；但按“提交可信”优先的取舍，宁可多拒绝一次，也不能基于过期状态改动用户的仓库。

## Consequences

- 不能为了省事绕过校验，提供“直接暂存某个文件”这类不带指纹的写操作。
- 遇到 `index.lock` 被占用时只重试和提示，绝不删除锁文件。

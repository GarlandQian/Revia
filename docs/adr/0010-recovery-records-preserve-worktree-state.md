# 回收记录保存完整文件状态，并绑定原 worktree

M2 即使只丢弃一个 hunk，也保存该文件丢弃前的完整工作区状态，包括内容、相关路径、存在状态和可执行权限；恢复回到这次丢弃前的状态，不改变暂存区，而不是自动重放反向补丁（Q85）。记录绑定原仓库与原 worktree；移动、删除重建后身份不明确时，不能仅凭路径相同迁移记录或继承审阅标记（Q87）。与只保存补丁、按路径重新关联相比，这需要更多存储，也放弃部分自动恢复机会，但恢复的对象与含义更明确，避免把保存内容写到另一个 worktree。

## Consequences

- 是否能直接恢复，要将当前状态与丢弃完成后的状态比较，而不是与保存的丢弃前内容比较；发生后续变化时按 Q29 对比，不覆盖。
- 无法确认原 worktree 身份时，回收记录仍可查看直到正常到期，但不直接恢复到新目录。
- 本决定约束持久记录的语义，不指定身份识别算法或存储格式；不能以路径相同代替身份确认。

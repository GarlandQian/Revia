## 首批：只读历史基础

执行任务：[01 只读历史后端与 IPC](./issues/01-readonly-history.md)。本批提供 F01 所需的数据与读取能力，不声称 F01/F06 界面已完成。

### H01：仓库归属与固定目标

- 所有历史命令使用已登记的 worktree ID，沿用既有环境、Git 程序与命令记录；不接受任意仓库目录或 Git 参数。
- 提供本地引用读取及提交遍历。查询明确指定起点与是否只走第一父提交，首批不设 UI 的默认引用范围。
- 查询开始时把起点解析为完整提交 OID，分页绑定这批起点和查询身份。引用在两页之间移动时不能悄悄换成另一条历史。
- 返回完整提交 OID、原始父提交 OID、作者/提交者身份与时间、主题及展示引用所需的信息。父节点不在本页时仍保留父边；遍历限制不篡改真实父提交列表。
- 有界分页与资源释放，不能一次把整个仓库历史传给前端。工程限额由实施方记录；超过限额或查询过期必须明确返回，不能伪装为历史末尾。

### H02：详情与改动文件

- 按固定提交 OID 读取完整提交信息与父提交列表；读取失败和空仓库分开表示。
- 读取所选提交相对**显式指定的一个真实父提交**的改动文件；merge commit 的产品默认比较对象留待核对，不能在 API 内悄悄取第一个父提交。根提交明确使用空 tree。
- 文件模型独立于 `ChangeEntry` / `ChangesKind`，包含可识别的增删改、重命名、路径、对象/模式及只读限制信息。文件身份不能从当前工作区猜测。
- 中文、空格、制表符等可无损路径正常处理；非 UTF-8 路径与非文本对象不得有损转换后冒充另一条可打开路径。

### H03：提交 diff

- 比较目标绑定提交、父提交、旧/新路径和 blob；路径只能来自后端确认的该提交改动文件，不任意读取磁盘。
- diff 来自 Git，复用既有解析、行布局、段与 syntect 高亮能力；纯文本先出、按可见范围取行。左右对照仍各自连续显示文件，不插空行对齐。
- 历史布局与行返回值显式只读，不签发 `HunkAction` / `SegmentAction`，不复用工作区写入指纹、审阅标记或“已暂存”身份。
- 统一行、左右布局/行及高亮都使用同一固定目标，当前工作区或分支改变不改变已打开的提交 diff。请求/结果包含足够的目标身份，以拒绝旧请求和跨 worktree 误用。
- 二进制、子模块、符号链接、仅权限变化、空文件、文件末尾无换行按真实对象状态表示；不支持的显示明确说明原因，不以空 diff 吞错。
- 内容缓存有界，支持释放。关闭目标、切换仓库与环境重载后不会把失效会话重新认作新目标。

### H04：首批验证

- Rust 现有测试体系创建独占真实 Git 临时仓库及应用数据目录，通过生产历史 API 验证；不依赖用户仓库或临时交接 fixture。
- 覆盖根提交、普通提交、两个父提交的 merge、重命名/删除、空文件/二进制、特殊路径、跨页父边、分页中引用移动、无效/跨 worktree 目标、释放后访问、只读前后状态一致。
- 新增公共类型由 ts-rs 生成，`src/lib/ipc.ts` 只提供固定类型封装。保留工作区 API 的兼容性。
- 完成所有相关修改后集中运行 Rust 测试、类型检查、lint、前端 build 和现有 Node 脚本；失败记录原始证据，不以静态检查替代桌面验收。

### L：提交日志（任务 02，F01、F06）

**L01 位置与生命周期**

- 主区域编辑器页签最左是固定的“日志”页签，不可关闭，打开仓库后默认显示；改动 diff 页签和提交 diff 页签在它右侧（Q119）。
- 日志跟随当前 worktree。切换 worktree 时显示该 worktree 的日志；各 worktree 的筛选条件、选中提交和滚动位置在本次运行内各自保留。
- HEAD 或引用变化（提交、检出、fetch、更新、推送、外部 Git 操作）后日志重新查询；所选提交仍在结果中时保持选中与滚动位置。
- 工作区刷新不关闭提交 diff 页签，也不抢激活状态；提交 diff 页签与改动 diff 页签分型，标题写“文件名（短哈希）”，同一提交同一文件重复打开时激活已有页签。
- 历史读取使用任务 01 的生产命令与生命周期：worktree 释放、环境重载后按任务 01 的失效规则重新打开目标。

**L02 表格**

- 列：分支图与主题（主题前显示指向该提交的引用标签：HEAD、本地分支、远端分支、标签，当前分支突出显示）、作者、日期；“哈希”列默认隐藏。列的显示在“日志”设置与表头右键菜单中切换（Columns）。
- 日期显示作者时间（Rebased 的 Commit Timestamp 默认关），本地时区：今天、昨天显示“今天 14:22”“昨天 09:05”，其余显示“2026/10/27 14:22”。
- 表格虚拟滚动；按任务 01 的分页接口滚到接近末尾时再取下一页。超过查询跨度上限时在表格末尾明确说明，不当作历史末尾。
- 键盘：↑/↓ 移动所选提交，Home/End 到首尾，⌘F 聚焦文字筛选（Focus Text Filter），Esc 从筛选框回到表格。只支持单选；任意两个提交比较不在 M5。
- 表格右键菜单（原生菜单）M5 只有“复制哈希”“从此提交新建分支…”（见 B02）；改写历史的项在 M6。

**L03 分支图**

- 照 IntelliJ：按拓扑顺序排列，每条分支线一种颜色，画出合并与分叉；提交点画在所在的线上。
- 随分页增量计算，不为画图一次读完整个历史。图在 Rust 还是前端计算由实施方决定，写进报告。
- “只看第一父提交”（设置，默认关）开启时按 first-parent 查询，图只画第一父边，父列表仍是真实全部父提交（任务 01 契约）。
- “合并线拉直”设置对应 Rebased 的 Long Edges（默认关，名称待桌面核对）：关闭时跨越很多行的边折成上下两端的短箭头，点击箭头跳到另一端；开启时画出完整长边。

**L04 筛选**

日志工具栏从左到右：文字、分支、作者、日期、路径。多个筛选同时生效（取交集）。

- 文字（Text or hash）：匹配提交信息；输入看起来像哈希时也按哈希前缀匹配。选项“区分大小写”“正则”（Regex，用 Git 的扩展正则），默认都关。
- 分支（Branch）：默认“全部”，即所有本地分支、远端分支、标签和 HEAD 可达的提交；可多选具体分支或标签。
- 作者（User）：多选，候选项来自已加载的历史，另有“我”（读取当前仓库生效的 user.name / user.email，只读，不改配置）。
- 日期（Date）：最近 1 天、7 天、30 天，或自定义起止日期。
- 路径（Paths）：从仓库文件树选择文件或目录，可多选；不跟随重命名（文件历史在 M6）。
- 无结果时表格显示“没有符合筛选条件的提交”与“重置筛选”。筛选条件按 worktree 保留（见 L01）。
- 前端只传结构化筛选条件，由 Rust 组合成固定参数的 Git 命令（扩展任务 01 的查询接口，保持起点固定、游标绑定目标、分页上限等契约）。路径照任务 01 的方式按字面匹配。
- 不建日志索引（Q151）。

**L05 提交详情与改动文件**

- 日志右侧上方是所选提交的改动文件树，按目录分组或平铺与提交工具窗口共用同一设置；下方是详情：完整提交信息、作者与时间、提交者与时间（与作者不同时显示）、完整哈希（可复制）、父提交（点击在日志中定位）、引用标签。
- 普通提交相对唯一父提交比较，根提交相对空内容比较（任务 01）。
- merge 提交（Q147）：默认只列相对每个父提交都有差异的文件（文件集合与 `git diff-tree -c` 一致）；双击打开时三栏只读显示“父提交 1 | 合并结果 | 父提交 2”，沿用 M4 合并页签的三栏组件但不可编辑、不显示任何写入按钮。超过两个父提交时默认按父提交分组。改动列表上方的开关“分别显示相对每个父提交的改动”（Show Changes to Parents，默认关）打开后按“相对父提交 1”“相对父提交 2”分组列出全部改动，双击打开普通提交 diff。新读取接口照任务 01 的只读契约：身份绑定、来自 Git 对象、不签发写入凭据、有界缓存。
- 双击文件（或选中后按 Enter、⌘D）在编辑器页签打开提交 diff：统一 / 左右对照沿用当前 diff 设置与 M4 的组件，只读，不显示块按钮、审阅标记和写入入口。
- diff 预览（Show Diff Preview）：日志工具栏的开关，默认关；开启后在日志中显示所选文件的提交 diff，位置由“diff 预览位置”设置决定（右侧或底部，默认右侧）。

**L06 日志设置（F06）**

设置对话框“日志”页：显示的列（作者、日期、哈希）、合并线拉直、只看第一父提交、diff 预览位置。随现有设置一起持久化。日志索引在 M7（Q151）。

### B：分支、远端与 Git 命令日志（任务 03，F02–F05）

**B01 共同规则**

- 检出、新建分支、fetch、更新、推送都是写操作：同 worktree 一次只执行一个，不排队；执行期间可以浏览和切换；结果、错误与刷新归原 worktree；关闭窗口或退出时先保留，等完成或留在应用；结果无法确定时标“结果待核对”（Q90、Q91、Q96）。前端经 App 的统一写入编排（同 M4 的 `runMergeWrite` 模式），Rust 侧使用同 worktree 写锁。
- 会覆盖或丢弃工作区内容的步骤先存入回收区（安全边界、Q148、Q150）；回收记录注明是哪种操作之前保存的。
- 网络操作（fetch、更新、推送、检查远端）单独使用 10 分钟上限，不受普通 Git 调用 120 秒超时限制；超时或中断时按“结果待核对”处理并重新读取引用与状态，不自动重试，不提供取消（Q96）。
- 凭据（Q153）：所有网络命令都不能等待输入。执行时关闭 Git 的终端提示，标准输入为空，SSH 不进入交互；需要凭据或确认主机密钥时立即失败，显示 Git 的原始输出，并提示到终端配置 credential helper 或 ssh-agent。不覆盖用户在环境或配置中指定的 ssh 命令与 askpass 程序，不修改 Git 配置。
- 不修改用户的 Git 配置：更新方式、标签方式等都用命令参数传递。为新分支记录上游（推送新分支、检出远端分支）是 Git 这些操作本身的结果，属于允许范围；除此以外不写任何配置。
- 错误按“操作被拒绝 / Git 命令失败 / 环境问题”三类展示（Q36）。

**B02 分支组件与新建分支（F02）**

- 顶栏 worktree 下拉右侧是分支组件，显示当前分支名，游离 HEAD 时显示短哈希。点开弹层：搜索框、“新建分支…”、“fetch”；“本地”列出本地分支，当前分支置顶并标记，有上游的显示领先 / 落后数（截至上次 fetch）；“远端”按远端分组列出远端分支。
- 点分支弹出子菜单：“检出”“从此分支新建分支…”。
- 检出本地分支：已被其他 worktree 检出时按 Git 的拒绝显示原因。检出远端分支：已有跟踪它的同名本地分支则检出该分支；没有同名本地分支则新建同名本地分支跟踪它并检出；同名本地分支存在但不跟踪它时提示改名，不覆盖。
- 本地改动会被检出覆盖时（Git 拒绝检出）弹出对话框，列出会被覆盖的文件，提供“智能检出”“强制检出”“取消”（Q150）：
  - 智能检出（Smart Checkout）：先把这些文件的当前内容存入回收区，再 stash 本地改动、检出、恢复 stash；恢复冲突时保留该 stash 条目，通知用户并显示冲突。
  - 强制检出（Force Checkout）：强制检出会丢弃全部已跟踪文件的本地改动，执行前把这些改动全部存入回收区，对话框中写明。
- 新建分支对话框：分支名（按 Git 的分支名规则校验，已存在时提示）、“检出新分支”（默认勾选）。起点：从分支组件进入时是当前 HEAD，从分支子菜单进入时是该分支，从日志右键进入时是所选提交。

**B03 fetch（F03）**

- 分支弹层与菜单中的“fetch”：对当前仓库的所有远端执行 fetch，按“fetch 标签方式”设置附加参数：自动（Auto，跟随 Git 配置，不加参数，默认）、同步（Sync，同步删除远端已删除的标签和分支）、总是（Always，取回全部标签）、从不（Never，不取标签）。
- 完成后刷新引用、领先 / 落后数与日志；失败显示 Git 原始输出。
- 自动 fetch（Fetch remote changes automatically，默认关，Q152）：开启后每 10 分钟对当前 worktree 所在仓库 fetch 一次；该 worktree 有写操作时跳过本轮；失败只在状态栏提示“自动 fetch 失败”，点开看原因，不弹通知。
- 检查远端是否有新提交（Check remote for incoming changes，默认关）：开启后同样每 10 分钟比较当前分支上游在远端的最新提交，有新提交时在分支组件上标出；只比较引用，不取回对象。

**B04 更新（F03）**

- 顶栏“更新”按钮，快捷键 ⌘T（Update Project）。对当前分支：先 fetch 上游所在远端，再按更新方式把上游并入当前分支：merge（默认，Q149）、rebase、按分支默认（只读读取该分支与仓库的 rebase 相关配置决定 merge 或 rebase）。没有上游或处于游离 HEAD 时说明原因，不执行。
- 有未提交改动时（Q148）：先把已跟踪文件的改动存入回收区，再带 Git 的 autostash 执行。所装 Git 不支持 merge 的 autostash 时，有未提交改动就拒绝更新并说明原因。恢复改动时有冲突：Git 保留的 stash 条目不删除，通知用户并列出冲突文件。
- 冲突（Q149）：merge 冲突进入 M3 的进行中操作提示与 M4 的冲突组、合并页签，解决后正常提交完成合并；rebase 冲突在提示条中说明到终端继续或中止，按钮在 M6。
- 已是最新时通知“已是最新”；更新成功时通知并入的提交数，刷新日志与改动列表。

**B05 推送（F03）**

- 顶栏“推送”按钮，快捷键 ⌘⇧K（Push），打开推送对话框：列出将要推送的提交（本地分支相对目标远端分支多出的提交，用日志同款的行显示），目标显示“远端/分支”。有上游时目标是上游；没有上游时默认推到 origin（有多个远端时可选）的同名分支，分支名可改，推送成功后记录为上游。
- 选项“推送标签”（默认不勾，勾选时只推送当前分支相关的带注释标签）。
- 按钮：“推送”，以及下拉中的“强制推送”。受保护分支（默认 master、main）上强制推送不可用并说明原因；其他分支二次确认，确认文字说明会覆盖远端提交，执行时用 `--force-with-lease` 并带上推送前读取的远端跟踪分支值（Q123）。
- 被拒绝（远端有新提交）：通知“推送被拒绝”，提供“更新后再推送”。设置“推送被拒时自动更新”（Auto-update if push of the current branch was rejected，默认关）开启时，自动做一次更新（同 B04），成功且无冲突再推送一次；仍失败只报告，不再重试。
- 推送成功：通知推送的提交数与目标，刷新领先 / 落后数与日志。

**B06 提交并推送（F03）**

- 提交区“提交并推送”按钮，快捷键 ⌥⌘K（Commit and Push）：先走 M3 的提交流程；提交成功后，设置“提交并推送时显示推送对话框”（默认开）开启时打开推送对话框（同 B05），关闭时直接推送；子选项“只在受保护分支显示”（默认关）开启时，只有当前分支是受保护分支才显示对话框。
- 提交失败或提交结果待核对时不推送。

**B07 Git 命令日志（F04）**

- 底部“Git”工具窗口默认隐藏，从“视图”菜单与状态栏打开；其中的“控制台”显示 Revia 本次运行执行过的 Git 命令：时间、所属 worktree、命令与参数、退出码、耗时、输出（标准输出与错误输出，单条最多保留 64 KB，截断时标明）。

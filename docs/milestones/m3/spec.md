## F01 进行中的操作

1. Rust从当前登记worktree的真实gitDir/Git输出识别merge、rebase、cherry-pick、revert及未解决冲突，包含linked worktree和sequencer中间阶段。读取失败显式报错，不当作“无操作”。
2. 常驻中文提示条说明操作及需到终端处理；有未解决冲突一律禁用提交。merge无冲突时可普通提交完成合并；rebase/cherry-pick/revert进行中禁用提交。不提供continue/abort/skip。
3. 有任意进行中操作时禁用amend。刷新/切换/回到前台时更新；写前重新读取，不能只信UI。

## F02 提交信息与持久草稿

1. 在现有变更工具窗口下方增加提交区，遵循Q107岛屿布局、既有Inter/JetBrains Mono/主题变量；不做网站式新布局。
2. 多行信息框，首行超过72个字符只提示（按字符，不按UTF-8字节）；空白信息不能提交。普通提交仅提交真实暂存区，不自动暂存、不偷改工作区。
3. Rust读取 `commit.template`，不修改Git配置；模板只在无草稿时初始化，不覆盖用户输入；读取失败可见。
4. 可选择最近20条提交信息；处理多行、Unicode和根仓库无HEAD。不得借此加入历史浏览功能。
5. 每worktree单独持久草稿，切换/重启保留，身份不明确不从同路径旧身份继承。异步读取/保存须绑定worktree与代际，旧回包不覆盖新草稿；持久化失败明确显示且保留本地输入。失败提交保留原文；成功只清除该次提交对应且期间未被重新编辑的草稿。

## F03 固定类型提交入口与指纹

1. Rust提供固定带类型的提交上下文/提交命令，前端只传登记worktree ID、信息、amend/skip选项和用户所见提交预期，不传任意Git参数/命令。
2. ADR-0005覆盖整个实际提交内容：绑定当前HEAD（含unborn）、暂存区条目/模式/对象及进行中操作状态；执行前重新读取比较，外部暂存/HEAD/操作状态变化拒绝并要求重新确认。不能用M2单文件fingerprint冒充整个提交契约。
3. 使用既有同worktree写锁、前端WriteGuardOrchestrator、CloseDriver/退出保护，且不排队；执行期间允许浏览、切换worktree，结果和错误归原worktree。旧响应不能覆盖当前UI。
4. 普通无暂存内容不可提交；无冲突merge完成提交、amend仅修改信息等合法情况按真实Git语义处理。不支持allow-empty按钮。
5. 写前失败/启动失败与命令已启动后结果不确定分开。已启动后不能自动重跑，也不能为关闭/退出杀Git；不提供未经验证的取消。若无法确认是否创建提交则“结果待核对”，保留草稿/快照、阻止静默退出；真实重新核对后才可由用户重新发起。
6. 错误继续用操作被拒绝/Git命令失败/环境问题三类。Git锁绝不删除，签名遵循Git配置，失败保留原始输出，不添加签名设置。

## F04 hooks 与实时输出

1. 通过当前worktree已有登录shell环境执行真正 `git commit`，默认正常运行hooks，不另拼shell命令。stdout/stderr实时交付到提交结果区，可展开、复制；事件绑定操作ID/worktree，切走后结果仍保留。输出处理不能死锁或无限保留内存。
2. “跳过 hooks”默认false，仅本次命令生效，完成后复原，不修改用户Git配置。使用命令局部机制实现，不把只绕过部分hooks的能力冒称全跳过。
3. 非零退出保留信息并显示真实输出，不能假定hook失败意味着工作区/index没有变化；完成后重新读取真实状态、列出hooks修改的文件（含工作区/暂存区），不自动撤销hook改动。
4. hook/签名交互等待期间不偷偷杀Git。关闭仍走M2 Wait/Stay；不新增系统唤醒/禁用休眠等设置。

## F05 提交前快照

1. 存在部分暂存文件时，在启动commit之前将这些文件**完整工作区状态**存入现有回收区，包含存在状态、字节、相关路径和可执行位；不可用部分补丁代替，不使用stash/reflog。
2. 快照必须可靠落盘，失败则不启动commit。保存后到commit启动前再次核对提交预期及这些工作区状态；变化时拒绝，保留已存记录。
3. 使用明确 `commitSnapshot` 来源，与discardFile/discardHunk区分，现有查看/另存/恢复/14天清理机制能识别；成功或已确认失败后保存真实操作后基准，恢复只在身份和后续状态匹配时写工作区、不改index、不覆盖后续修改。
4. 结果不确定/记录收尾失败保留NeedsVerification，不把未捕获的after伪造为基准；回收区UI文案不能把提交快照称“已丢弃”。

## F06 amend、安全确认与完成反馈

1. 勾选“修改上一次提交”预填最近HEAD完整信息；无HEAD或进行中操作不可用；输入/切换期间不得被异步旧信息覆盖。
2. 以本地上游跟踪分支记录判断HEAD是否已包含于上游。已包含则明确警告且另一次确认；不fetch。确认绑定worktree、HEAD/暂存区预期、信息和选项，刷新/切换/编辑后旧确认失效。
3. 显示“截至上次fetch”的本地记录边界。不猜测远端真实状态；读取错误不能当作未发布。
4. 提交后刷新列表、diff、审阅进度，按真实HEAD变化失效审阅标记；成功显示新commit ID、输出及hook改动文件。失败/待核对保留草稿。清理信息、amend和skip只作用原worktree/原次编辑，不抹掉期间新输入。
5. 提交按钮旁显示审阅进度，不用审阅状态阻止提交。提供⌘K/Ctrl+K并明确目标；信息框中可触发提交，其他弹窗内不穿透。平台差异放既有platform模块，中文文案集中i18n。

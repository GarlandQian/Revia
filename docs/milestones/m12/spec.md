# M12 改动树选区与文件历史

Status: done

日期：2026-11-18。产品代码基线为 `81c5ce9`，决策见 Q227–Q233。

## Problem Statement

在暂存区模式多选文件后取消其中一项，打开该项的 diff 会把批量暂存目标改成刚取消的文件。按目录分组时，Shift 连选还可能包含折叠目录中的文件。打开文件历史时，用户只想看第一条，却要等待整页最多 40 条的 diff 逐一读取。

## Solution

改动树选区决定批量操作的目标。用户可以查看选区以外的文件，也能看清折叠目录中已有多少条目被选中。文件历史先展示提交列表，再为当前选中条目加载 diff。

## User Stories

1. 选中三个未暂存文件 A、B、C 后，用平台多选修饰键取消 B，我仍可看 B 的 diff，再将 A、C 一起暂存。
2. 取消最后一项后，我仍可看预览。此时按整文件暂存或丢弃快捷键，仓库和暂存区保持原状。
3. 选中 A、C 后，我可以点 B 行上的“暂存”处理 B，再继续处理 A、C。
4. 用 Shift 连选时，起点与终点之间展开的文件行进入选区。即使中间有折叠目录，我也能从树上判断这次选择的范围。
5. 先选中目录里的两个文件再折叠，目录名旁显示“已选 2”，批量暂存包含这两个条目。
6. 打开文件历史，我可以在首条 diff 读取期间浏览列表，点选第三条后，右侧随即显示第三条的加载状态与结果。
7. 查看较早版本或重命名前的文件时，我看到对应提交及路径的 diff。翻页保持已有选中项，未查看的条目无需读取 diff。

## Implementation Decisions

- 暂存区模式的选区以文件条目为单位，包含路径和所属改动组。右侧预览可以独立变化。显式空选区应被保留，批量暂存和丢弃不会回退到预览文件。继续使用既有批量写操作、写前校验与丢弃确认。
- Shift 范围沿渲染所用的文件行顺序计算，跳过折叠内容并包括展开列表中需滚动才可见的行。折叠本身保留选区，折叠目录显示其子树中已选条目数。选区外的“暂存”只处理点中的一行。
- 文件历史列表和选中 diff 分开读取。由 Rust 提供固定类型的只读操作并沿用 Git 生成的差异、重命名路径、截断和错误处理。当前分支、所有分支与固定历史起点仍遵循现有文件历史语义。
- 预览只接收当前 worktree、文件、历史条目及请求对应的响应。迟到的成功与失败均不能替换当前选择。翻译沿用现有简体中文和 English 机制。

## Testing Decisions

- 通过生产界面事件和已有真实 Git 入口检验最终状态。在独占的临时仓库创建已跟踪的 A、B、C，分别修改三者；多选后取消 B，预览 B，批量暂存后核对 index 只有 A、C，B 仍为未暂存改动。
- 用现有前端行为测试方式覆盖空选区、选区外行内暂存、Shift 跨折叠目录、先选再折叠。保留更改列表模式现有回归。
- 在至少有 40 次文件变更的临时仓库打开文件历史，以 Git 命令记录核对满页只看首条时用于读取 diff 的 `git show` 恰好一次。用受控响应验证快速切换时的加载状态与先后结果，覆盖翻页、重命名和既有只读限制。
- 规划方在固定源码构建的 macOS 窗口中使用独立应用数据和临时仓库验收。报告区分真实窗口观察、自动测试与没有执行的平台检查。

## Out of Scope

大文件刷新、更新包重新下载、冷启动加载量列入后续候选。全项目 CI 改造、公开发布和历史待验项目另行安排。

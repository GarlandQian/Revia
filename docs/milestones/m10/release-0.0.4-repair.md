# 0.0.4 发布返修：Git 输出读取竞态

Status: done
日期：2026-11-10
基线：`6051ece405813794e12962df213899ff885f7571`

## 问题与范围

首轮 macOS CI 分别在更改列表的 rebase 验证和合并应用验证中失败。前者明确是 Git 成功退出而上层拿到空路径；日志不足以断定两个失败均由同一原因导致。静态检查发现既存 `read_pipe` 在暂时无数据之后才检查子进程退出状态，可能丢掉两次观察之间已经到达的输出。该循环在 M10 之前就存在。

## 必须满足

- 修复“读取暂时无数据 → Git 写入并退出 → 读取线程恢复”时过早停止的问题；以本次读取开始前的退出状态判定空读取能否结束。
- `Interrupted` 继续读取，不作为管道已排空的证明。
- 保持现有输出截断上限、日志与返回错误语义；后代进程保留 writer 时仍须有限返回。本次保留既有 100ms 排空上限，另行记录它在极端调度停顿下的残余风险。
- 观察接缝只作用于单次调用，生产默认关闭，不使用全局 hook，不更改 Git 配置或用户仓库。
- 沿现有 Rust 体系在 `src-tauri/tests/` 用独占临时仓库、真实 Git 与 Barrier / 受控阶段稳定复现 stdout、stderr 丢失；旧代码失败、新代码通过，并保留原始命令、退出码和输出。
- 核对后代保留 writer 的有限返回，完成全部修改后运行完整 Rust 测试；不因本轮失败关闭测试、降低门槛或把原失败改写为成功。

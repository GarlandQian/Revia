# M6：冲突与历史、双语界面

Status: ready-for-agent

依据：Q122–Q124、Q129、Q131、Q139、Q143、Q149、Q155–Q172；ADR-0002、0004、0005、0008、0009、0010、0012、0013。
本机参照 Rebased 1.1.22；布局与交互照 Rebased，外观沿用现有 VS Code 主题与组件。静态事实与未确认的运行时细节见 [资料核对](./references.md)。

## 问题

M5 已能浏览日志、提交与同步分支，但冲突后仍需终端继续操作，不能完整管理 stash、改写历史或查看文件历史 / blame。
既有界面只有中文静态字典，Rust 还直接返回中文用户错误，不能完成中英文即时切换。
本轮把这些能力接成完整日常流程，同时保留写前校验、覆盖前回收、结果待核对和关闭保护。

## 方案与交付方式

同一个 Paseo / Pi 会话在 `m6` worktree 一次实现本规格全部功能，再集中检查、交付完整报告；规划方整包独立审查、桌面验收后才合并。
只有 [01 整包任务](./issues/01-complete-m6.md)，内部章节是验收编号，不是多次派发。
使用 x18n MCP 和已安装的 `x18n` / `x18n-check` skills；产品代码、语言资源、后端错误和验证一起迁移。

## 用户故事

1. 用户能查看仓库的 stash 列表、说明、时间、原分支和文件差异，找到终端或 Revia 保存的改动。
2. 用户能用说明和“保留暂存区”保存 stash，不需要面对新增的“包含未跟踪文件”选项。
3. 用户能应用 stash，并明确决定是否恢复暂存区、应用后删除或作为新分支应用。
4. 用户能确认删除单条或清空 stash，并在 14 天内从回收区取回完整条目。
5. 用户应用 stash 或清理未提交改动前已有回收保护；保护失败时文件不会被覆盖。
6. 用户能在冲突合并页签解决文件后，明确继续、中止或跳过适用的 Git 操作。
7. 用户能分辨“编辑停点”和“冲突停点”，前者可修改 / 拆分提交，后者仍不能普通提交。
8. 用户能在日志中 cherry-pick、revert、reset、改提交信息和编排交互式 rebase。
9. 用户已有未提交改动时能自动保存，或在可能覆盖时明确选择保护 / 覆盖 / 取消。
10. 用户知道自动保存的 stash 来自哪个操作，可从通知直接查看，冲突时内容仍保留。
11. 用户能在确认页看见空 cherry-pick 策略，完成后知道哪些提交因空提交被跳过。
12. 用户能查看当前或所有分支的文件历史、版本内容、diff 和对应提交。
13. 用户能按行查看 blame，控制空白与移动检测，并查看上一版本的 blame。
14. 用户可按既有 Git 配置或 Revia 设置使用外部 diff / 合并工具，同时保留内置三方合并。
15. 用户首次启动获得合适的系统语言，并在设置中即时切换简体中文 / English。
16. 用户切换语言时保留页签、提交草稿、合并编辑内容、撤销 / 重做和当前工作上下文。
17. 英文用户能读懂来自 Rust 的错误、限制原因和操作结果，不会遇到整段中文产品提示。
18. 用户在窄窗口阅读英文菜单与日志日期时，不会被换行重叠、遮挡或不可达按钮阻断。
19. 用户在另一个 worktree 浏览时，旧确认和迟到结果仍归属原目标，不会改错仓库。

## 共同契约 C

### C01 Git 与目标身份

- 所有 Git 读写在 Rust 层经现有受控 Git 执行器调用；前端传固定类型参数。用户文本、路径、分支与说明均作为独立参数，不能拼 shell 或接受任意 Git 参数。
- 执行前绑定并重验 worktree 身份、操作元数据版本、相关引用 / 完整 OID、文件状态和确认条件。刷新、切仓库、切 worktree、环境重载后旧确认失效，不能重新解析移动引用后偷换目标。
- 工作文件写门禁仍按 worktree；stash 列表是同一仓库多个 worktree 共享的资源，stash 写操作须额外协调并固定条目身份，不能用浮动的 `stash@{0}` 恢复或删除另一条内容。
- 同目标写操作不积压点击；可以继续只读浏览，结果与通知归属原仓库 / worktree。前端编排复用可独立验证的写生命周期，不绕过关闭 / 退出保护。

### C02 回收与异常

- 按适用规则先确认、完整回收并核验成功，再执行有覆盖风险的写入。回收失败拒绝后续写入，不能静默跳过不支持的路径或文件类型。
- Git hunk、差异和文件历史都来自 Git；继续使用已有路径、编码、符号链接、子模块及权限保护边界。
- 不删除 index.lock，不修改用户 Git 配置。沿用登录 shell 环境、hooks、签名与凭据行为；必要的非交互编辑器接线使用本次进程环境或受控内部协议，不写全局配置、不接受任意 shell 脚本。
- 操作中断、超时、完成回执失败而结果不确定时，保留归档和状态，标记“结果待核对”，重读真实 Git 状态；重启后不盲目重跑、继续、恢复或删除。
- 普通文件恢复遵守 ADR-0010；stash 恢复为条目遵守 ADR-0012，两种恢复语义不混用。

## stash S

### S01 列表与读取

- 按当前仓库展示真实 stash，能读取单条文件列表、说明和差异；其他 worktree / 终端变更后重读，保留可确认的选择，不沿用旧序号。
- diff 比较对象提供本地文件或父提交，按 Rebased 的既有设置表达；内容为只读，不能借历史 diff 取得工作区写凭据。
- 保存对话框仅说明和“保留暂存区”，按本机 Rebased 的 Git 行为保存；不增加未跟踪文件选项，也不引入 ignored 文件。实际暂存区保留与未跟踪行为用真实 fixture 核对并留报告。

### S02 应用

- 提供“应用后删除”（默认不勾）、“恢复暂存区”（本机新对话框默认不勾）和“作为新分支”；分支需明确命名并校验。互斥 / 组合规则照 Rebased / Git 实际能力，不能用 Git 的隐含删除行为绕过用户选择。
- 应用前把可能受影响的现有工作文件状态存入回收区。恢复暂存区时明确尊重已暂存状态和冲突边界。
- 应用有冲突时保留条目，跳到已有冲突处理流程；即使勾“应用后删除”也不删除，不自动继续其他操作。
- 应用成功后请求删除同样履行完整 stash 归档保护；归档或删除失败要分开报告“已应用、未删除”，不能重复应用。

### S03 删除、清空与取回

- 单条删除和清空都确认，确认绑定精确条目或条目集合。完整归档写在 Revia 回收区目录，保留 14 天；禁止在用户仓库增加 `refs/revia/...` 等隐藏引用。
- 归档包含重建条目必需的完整对象、文件内容、暂存区版本及存在时的未跟踪内容和元数据；只有 OID、补丁、reflog 或依赖外部原对象的增量归档均不满足独立保存。
- 清空前完整保存本次确认的条目集合；外部列表变化要拒绝旧确认，不能误删新条目。失败时如实保留已归档 / 未删除的边界与可核对结果。
- 回收区“恢复为 stash 条目”只放回原仓库列表，不直接改工作区或暂存区，不覆盖现有 stash。原身份无法确认时只读保留归档。
- 用真实 Git 清理原 stash 对象后验证仍能完整取回；同仓库多 worktree 并发与终端追加 stash 时仍选中正确对象。

## 进行中的操作 O

### O01 继续、中止、跳过

- 对 merge、rebase、cherry-pick、revert 按真实 Git 操作状态提供适用按钮；没有相应能力时不显示可执行入口，不能伪造 skip merge。
- 继续只在用户明确点击时执行，先重新核对冲突与操作元数据；在合并页签点“应用”只解决文件，不自动继续操作。
- 中止和跳过先确认，再回收可能被覆盖文件，之后执行固定操作。merge 仍可用普通提交完成，重复入口共用同一写保护。
- 冲突解决到下一步仍是原操作的停点，不能仅因 conflict_count 变成 0 就冒认为编辑停点。

### O02 自动保存与恢复

- rebase 需要清理时自动保存未提交改动；cherry-pick / revert 会覆盖时提供“先 stash 再执行再恢复 / 强制覆盖 / 取消”。不一律要求干净，也不先执行覆盖命令再补保护。
- 保存与覆盖前先回收；自动保存固定用 stash，不做 Shelf，不增加“清理工作区方式”设置。保护须包含实际可能被覆盖的未跟踪路径。
- 自动保存说明注明 Revia 与操作名称；通知说明已保存并提供“查看 stash”，能定位准确条目。
- 原操作因冲突暂停时保留自动保存条目；用户完成或中止原操作后再恢复。恢复冲突继续保留条目并提示，不自动删除或重复尝试。
- 只有确认完整恢复后才可清理本次自动保存条目；按 S03 的规则保护其删除。操作失败、关闭或重启不能丢失此关联。

### O03 编辑停点

- 识别交互式 rebase 用户安排的 edit 停点，允许 amend 与新建提交用于拆分；之后用户单独点“继续”。
- 冲突停点仍禁用普通提交，其他进行中操作不因此放开。现有提交检查、hooks、快照、目标验证和关闭保护保持。
- 工作文件在外部编辑器修改，现有整文件 / 块暂存可服务拆分，不提前做 M7 文件编辑器。语言切换和刷新不误判停点、不清空草稿。

## 日志历史操作 H

### H01 入口与确认

- 在日志中接入 cherry-pick、revert、reset、改提交信息和交互式 rebase；菜单按真实选择与能力启用，确认列出固定提交 / 操作范围与后果。
- 已在上游的历史改写额外警告，受保护分支规则沿用现有决定，不隐式推送或强制推送。
- 多提交操作保持明确执行顺序，失败 / 冲突后列出完成、跳过、待处理项，不能对部分成功整批重试。按本机 Rebased 核对选择顺序和能力，不自行默认 merge 的主线父项。
- revert merge 按本机 Rebased 禁用；其他需主线选择或含 merge 的动作按已证实能力执行，有未决语义明确报告并保持入口不可误执行，不能猜一个父提交后写入。

### H02 cherry-pick、revert、reset、改信息

- cherry-pick 空提交策略设置“跳过 / 创建空提交”，默认跳过；执行确认展示本次策略，用户确认后本次可以按策略处理空提交，结果逐条列出空提交跳过项。该窄例外不授权自动跳过冲突或重启续跑。
- cherry-pick 来源后缀开关与实际适用条件照 Rebased：安装资源显示默认开，已发布提交才加入来源；按本地引用核对，不为此联网。
- revert 接正常冲突 / 继续流程，遵循 O02 的本地改动保护；不误叫“丢弃未暂存改动”。
- reset 提供 Rebased 的 Soft / Mixed / Hard / Keep，首次 Mixed、确认后记住本次模式；确认明确 index / 工作文件影响，覆盖前回收。不能把 soft/mixed 误实现成 hard。
- 改提交信息针对当前分支可改写的固定提交范围；保留父子关系、作者与已有安全规则，不能只改当前 HEAD 而忽略所选历史提交。改写范围含 merge 时遵守 H03 的限制。

### H03 交互式 rebase

- 提供排序、改信息、squash、fixup、删除和暂停编辑；没有任意 shell 命令 / exec 输入。
- 范围含 merge 提交时按钮不可用，并说明原因，不静默展平。通过固定范围、完整 OID 和许可动作构造计划，执行前重验；不把任意 Git todo 文本当作可执行用户参数。
- 预览改写的提交和影响，确认后执行；按 O02 自动保存，按 O01/O03 支持冲突与编辑停点。
- 不能在后台自动完成冲突、自动继续或把取消编排当成取消已执行的 Git 写入。

## 文件历史与 blame F

### F01 文件历史

- 从工作文件和日志相关文件入口打开只读文件历史，默认当前分支，可切所有分支；文件名显示选项接到设置与实际呈现。
- 选提交可查看该版本文件与 diff，跳到日志对应提交；路径、重命名和不存在版本遵循 Git 的真实历史，不把同路径的新文件误认作同一对象。
- 读取使用固定目标、分页 / 有界缓存，切仓库或条件后迟到响应失效；有截断或不支持的文件类型明确说明，不一次拉取无界完整历史。

### F02 blame

- 对明确文件版本展示行号、提交 / 作者关联，能跳到提交 / diff；保留原文件内容。
- 提供忽略空白、检测文件内移动、检测跨文件移动三项开关与“查看上一版本的 blame”。上一版本绑定当前行 / 版本的真实父关系，根或不可读取版本明确说明。
- 参数由 Rust 按开关生成，移动识别依赖 Git，不自行计算归属；开关变化后刷新对应身份的缓存与结果。
- 默认值与入口细节按本机 Rebased 对照，原始观察写报告。中文、空格路径和重命名须验证，二进制或不可无损呈现内容保持只读限制。

## 外部工具 T

- 保留内置合并；外部 diff 与合并为可选设置。优先尊重已有 Git 工具配置，未配置时按 Q28 列出 Git 检测到的可用工具让用户选一次，保存到 Revia 设置。
- 外部命令在 Rust 层用固定类型协议和独立参数启动，沿用 worktree 环境；用户文件名不经 shell 展开，不改用户 Git 配置。
- 外部工具可能写文件，启动与收尾遵守目标验证、回收、写门禁、关闭保护和冲突结果核对。进程退出成功不直接等同于 Git 冲突已经解决。
- 自动解决 import 冲突按 Q167 留在未排期 backlog，本轮不实现、不放无效设置，不加到 M7。

## 双语与 x18n L

### L01 运行时语言

- 简体中文 / English 覆盖已有及新增产品界面、菜单、提示、通知、设置、只读限制和错误。首次无语言设置时，系统语言为中文则简体中文，否则英文；检测平台差异集中处理。
- 设置即时切换并持久化；已有页签、选择、滚动、提交草稿、合并结果和撤销 / 重做保留。不能用重新加载整页代替切换。
- 用户内容、文件、提交信息、Git 原始输出、调试 / 测量日志不翻译。保留平台快捷键与安全确认的精确目标数据。

### L02 资源迁移

- 遵守 [文案规则](./i18n-proposal.md)：源语言 `zh-CN`、目标 `en`，语义分组与 camelCase 键保留；`Snapshot Before Commit` 是提交前快照的英文。
- 现有中文字典约 66 条函数式文案必须迁为参数 / 占位符文案，不能复制成另一套语言函数。盘点真实数量，保留计数、路径、快捷键和复数语义，参数名中英文一致。
- `dateLabels[...]`、`readonlyReasons[...]`、`merge.unavailable[...]` 及类似运行时查表迁为显式完整字面量键映射；允许运行时选择映射项，不运行时拼接翻译键。
- 先通过 x18n 查询是否已有同义键；资源写入使用 MCP 或 CLI set / apply / rename，遵守两个 skills。配置可手工编辑；宽范围改名或自动删除未用键须另行确认，不在迁移中顺手删键。
- 使用与 React / 现有工程相容的运行时接线；x18n 是文案维护与校验工具，安装它不代表语言运行时已完成。工程内部库与模块组织由实施方选择并说明，不更换技术栈。

### L03 Rust 用户错误

- 将所有用户可见中文错误 / 原因 / 操作结果迁为稳定错误类型、代码与参数，保留既有错误分类和结果待核对语义，见 ADR-0013。用户估计 Rust 约 784 处中文字符串，须实际分类与盘点，不能机械翻译所有内部日志。
- 前端唯一生产格式化链路按当前语言呈现，同一已存在错误切换语言后也能正确呈现；不匹配英文句子来判业务，不把中文整句放进参数冒充完成迁移。
- 异步结构化结果、通知、只读原因等不能漏迁移；Git 原始 stderr 可单独作为详情，产品说明须双语。生成绑定与所有 IPC 调用方同步更新，不以 `[object Object]` 显示错误。

### L04 检查

- `x18n check --json` 检查缺失键、翻译、占位符与语法并对错误失败；未使用键与术语先警告，完整报告且不自动删除。
- 另执行 `x18n extract --list --json`，检查产品界面仍有写死中文；列表非空须经现有脚本体系生成失败退出码，不能因 CLI 列举成功退出 0 而当成零问题。
- 调试和测量日志用最小范围 `x18n-ignore` 标出且不翻译；不得排除整个界面目录躲过扫描。扫描范围 / 白名单与结果可审查，不把注释、用户数据、测试 fixture 或语言资源误当产品界面。

## 日期列修复 D01

日志日期一行内显示，不折行、不压邻行；放不下时省略，完整内容可查看；表头、行与最小表格宽度共享列宽约束。
覆盖非今天 / 昨天的日期格式，补英文界面与窄窗口，见 [backlog 07](../backlog/07-log-date-column-wrap.md)。

## 验证 V

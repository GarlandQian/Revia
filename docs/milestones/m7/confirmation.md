**第四版已获用户确认，可以开始。** 启动依据是用户查看本版及清单后的“可以”（Q199）；第二版的“大体可以”只保留为当时反馈。

## 本轮已确认的补充项

以下建议已由用户本轮“可以”整体确认，对应 Q193–Q199。

| 事项 | 已确认内容 |
| --- | --- |
| GitHub 授权 | 采用 GitHub App，允许选择授权仓库并细分权限。组织仓库可能需要管理员安装或批准；继续保留手动 Token 入口，仍遵守组织策略。账号范围与验证码登录沿已定结论 |
| PR 细节 | 支持已有 fork 的分支，M7 暂不自动创建 fork；多个远端时明确选择来源和目标。创建 PR、发表评论或审阅都由用户明确提交，合并前确认目标与当前提交；不自动加 remote 或代为推送。审阅草稿保存在本机，发布前核对 PR 版本，权限不足时说明原因并保留草稿 |
| 编辑范围 | 可安全写回的普通文本文件；二进制、符号链接、子模块与超出既有大小限制的文件继续只读。并排视图编辑工作区一侧；统一视图先保留只读，提供切换到同文件并排编辑的入口。外部变化时提供草稿与磁盘对比，由用户决定后重新保存 |
| 终端恢复 | 重启保留页签、所属 worktree 和起始目录，重新打开 shell；不恢复旧进程、不重放命令、不持久保存终端输出。Revia 写入期间显示该 worktree 的忙碌状态，终端产生的变化仍按外部修改核对 |
| 更改列表 | 每项改动只属于一个列表，新改动进入当前默认列表；文件和块可移动归组。删除列表时把剩余改动移回默认列表；提交后只移除已提交部分。块变化无法可靠对应时保留原分组信息供核对，取消失效勾选并提示重新选择，避免悄悄改变提交内容 |
| 主题与快捷键 | 导入本地 VS Code 颜色主题 JSON / JSONC，缺失颜色回退到对应内置主题，不执行扩展代码；无效文件保留当前主题。快捷键按作用范围检测冲突，由用户确认替换，提供单项和全部恢复默认，提示随平台修饰键变化 |
| 组件使用与最终外观 | 优先用 React Bits 的 Glass Surface、Specular Button、Glass Icons 统一面板、按钮和图标入口；缺少的业务控件沿用既有交互并统一材质。Glass Icons 接收现有 Codicons 图形，文件类型图标和代码保持清晰，不把所有小图标变成独立玻璃块。第四版及这个使用范围已确认 |

授权建议依据 GitHub 官方对细粒度权限、选定仓库和组织安装要求的比较，属于本项目的选型建议；OAuth App 可作为偏好更直接账号授权的另一选择，但仓库权限粒度更粗。[GitHub 官方比较](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/differences-between-github-apps-and-oauth-apps)（2026-10-30 复核）。

**由 Codex 先核对的事实**：更改列表模式下终端已有暂存内容怎样处理，按 Q120 / ADR-0003 必须先实测 Rebased，当前缺少桌面操控入口，辅助功能检查未获授权；单独阻塞该项提交逻辑，不能写成某一种行为已确定，其余任务可推进。

**由 Codex 整理的验证方案**：使用独占仓库、账号 / 远端 fixture 和应用数据，保留原始命令与输出，验证编辑冲突、网络失败、终端进程、更新失败等实际结果。用户可见取舍收口后再写规格；不将第四版浏览器预览当作 macOS 或 Windows 产品验收。

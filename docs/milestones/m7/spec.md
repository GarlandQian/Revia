# M7：扩展工作流与 Liquid Glass

Status: ready-for-agent
日期：2026-11-01
已确认依据：Q120、Q122、Q126、Q132、Q139、Q176–Q200；安全与验收沿用既有 ADR。
范围说明：任务 13 的 Rebased 1.1.22 真实事实已于 2026-10-31 取得，按 I 实施；任务 14 仍待完整固定候选的真实桌面验收。任何人不得把部分就绪写成整包完成。

## Problem Statement

用户目前仍须离开 Revia 编辑工作区、使用终端、克隆仓库、处理 GitHub PR、组织多组改动和管理应用版本。界面已能呈现 Git 工作流，但用户确认要采用连贯的 Liquid Glass 外观，并要求代码清晰、按钮与图标材质协调，设计阶段同时覆盖 macOS 和 Windows。

## Solution

在已有审阅、暂存、提交、历史与回收基础上补齐扩展工作流。外观以 Q200 为当前基准：macOS 26+ 使用系统原生 Liquid Glass，Windows 11 接入 Mica，旧系统保留 CSS 材质；沿用开发工具密度与清晰代码。编辑、终端、GitHub、诊断和应用更新均围绕当前仓库与 worktree 展示明确目标和结果，发生外部变化或结果不确定时保留用户内容与已知回执。

M7 的产品交付为 macOS Apple Silicon；Windows 外壳、修饰键、可编译性和降级设计同步考虑，Windows x64 安装版与便携版仍在 M8 发布。

## User Stories

1. 作为审阅者，我希望顶栏、侧栏、按钮和浮层采用统一玻璃材质，以获得连贯界面。
2. 作为开发者，我希望代码、行号、增删标记始终清晰，以长时间阅读 diff。
3. 作为 Windows 用户，我希望窗口按钮、菜单和快捷键符合平台习惯，以便后续直接使用。
4. 作为用户，我希望降低透明度、降低动态效果和高对比度时仍可操作，以适应系统设置。
5. 作为用户，我希望浅深色各自导入本地 VS Code 主题，以保留熟悉配色。
6. 作为用户，我希望无效主题导入失败时保留当前外观，以继续工作。
7. 作为键盘用户，我希望自定义快捷键并看到作用范围冲突，以避免误触发。

17. 作为用户，我希望关闭运行中终端前确认，以避免无意结束进程。
18. 作为用户，我希望重启恢复页签和起始目录并启动新 shell，以恢复工作位置而不重放命令。
19. 作为用户，我希望终端产生的外部改动被刷新和写前校验，以避免过期操作。
20. 作为用户，我希望输入 URL、目录及高级选项克隆并打开仓库，以开始工作。
21. 作为用户，我希望取消或失败后看到保留目录的位置，以自行处理残留。
22. 作为 GitHub 用户，我希望通过浏览器验证码登录或使用 Token，以处理 PR。
23. 作为多账号用户，我希望按仓库记住账号且令牌安全保存，以区分个人和工作身份。

## Implementation Decisions

### A. 已确认外观与平台

- Q200 取代 Q199 在 macOS 26+ 上用 React Bits 模拟外壳材质的要求：窗口透明，整窗一块 AppKit 原生 Liquid Glass，外壳、侧栏、日志和 diff 代码放在同一块玻璃上；不再保留 VS Code 编辑器底色与分栏外观。macOS 26 以下与 Windows 10 保留 CSS 材质。
- 工具栏横跨顶部，仓库 / worktree / 分支、更新 / 推送、工具入口按用途组成玻璃胶囊，紧跟红绿灯靠左；设置单独一块。侧栏和编辑区排在工具栏下面。设置页铺满整窗；克隆、诊断、更新及确认对话框作为浮动原生玻璃面板，背景界面淡出并模糊；终端、PR 面板同样放在玻璃上，工具栏下拉菜单使用对齐其矩形的原生玻璃。
- Windows 沿用相同结构与原生标题栏：Windows 11 窗口底用 Mica，胶囊、对话框和弹层由网页绘制，采用 Fluent 小圆角；本轮完成接线，Windows 真机验证与分发仍在 M8（Q126、Q191）。
- 现有 Codicons 和文件类型图标继续提供符号；正文、行号和增删标记不参与模糊或折射。语法高亮照旧，增删行半透明；代码面用一层中性半透明底压住背景字形，按 Q190 实测可读性，不能仅凭透明参数宣称通过。
- 主提交按钮用系统强调色，其余按钮在共享材质上保持清晰标签、悬停、按下、禁用和焦点状态。CSS 回退继续复用已固定的 React Bits 组件与许可，不要求原生模式继续渲染网页玻璃或着色器高光。
- 弹层定位、焦点返回、键盘导航、拖动、选区与点击目标沿用功能组件，材质装饰不截获输入。系统减少透明度 / 动态效果和强制颜色有清晰降级。
- 固定所引入的上游源码与许可；预览中已有固定来源可复用，不把 MIT + Commons Clause 标为普通 MIT。
- 平台差异集中处理；macOS 红绿灯、菜单与 Command，Windows 原生外壳、系统菜单与 Ctrl 均保留。真实 WKWebView / WebView2 的能力须实际测量，不以 CSS 属性支持或浏览器 UA 判断等同像素效果通过。

### B. 主题与快捷键

- 支持本地 VS Code 颜色主题 JSON / JSONC 导入，浅深色各选一套。只解析数据，不运行主题扩展、远程脚本或任意代码。
- 缺失颜色回退所对应的内置主题；非法文件失败时保持当前主题、编辑与页签状态。沿既有持久化和即时切换链路应用。
- 快捷键按实际作用范围检测冲突，确认替换后才保存；可单项或全部恢复默认。编辑输入、终端和弹层优先处理自身键盘事件，避免一次按键执行多个写操作。

### C. 工作区编辑与草稿

- 只有绑定真实 worktree 身份、路径和内容版本的普通文本工作区一侧可编辑；历史、暂存区、二进制、符号链接、子模块、超出既有大小或安全编码范围继续只读，说明原因。
- 并排视图提供编辑；统一视图保留只读并能定位到同文件的并排编辑。不增加通用文件树或独立文件编辑器。
- 显式保存通过 Rust 会话的写门禁与相关文件 diff 指纹核验；重新验证路径类型、仓库身份、原内容及权限，保存保留既有编码 / 换行策略和可执行权限。
- 未保存编辑以本机编辑草稿持久化，绑定 worktree 身份与基线版本。切换文件、视图、仓库、语言或主题保留内容；删除重建的同路径不得继承另一个 worktree 的草稿。
- 外部变化时保留草稿与磁盘两版，拒绝旧保存；用户核对后基于新基线重新编辑 / 保存，不提供绕过校验的盲目覆盖。
- 关闭时提供保存、放弃、取消。暂存、提交等依赖相关文件内容的操作先处理这些文件的草稿；未完成保存时不继续写操作。已有三方合并编辑和 Git 原始 hunk 契约保留。
- 持久化失败、写入可能已发生后重读失败时保留内容、原目标和已知回执，标记结果待核对，不自动重发保存或提交。

### D. 内置终端

- Rust 创建真实 PTY / 平台终端会话，前端发送用户的输入字节与尺寸，不能把 Git 功能改成前端拼接 shell 命令。沿既有环境解析，工作目录归属注册的 worktree。
- 每个 worktree 可有多个独立会话；在应用运行期间切换保留进程。Ctrl / Command、组合键、窗口 resize、中文输入和 UTF-8 输出由终端正常处理。
- 关闭运行中进程前确认，取消则保留；退出应用 / 安装更新同样纳入关闭协调器。重启只恢复页签、原 worktree 与起始目录，启动新 shell，不恢复进程、不重放命令。
- 输出只在内存中适度保留；不写入跨重启诊断或编辑草稿。Revia 写入期间显示对应 worktree 忙碌，终端写入按外部变化处理；不承诺能阻止终端绕过应用门禁。

### E. 克隆

- 提供 URL 与目标目录，分支、正整数浅克隆深度和递归子模块为高级选项。URL / 分支作为独立参数经系统 Git CLI，拒绝把用户输入当命令选项或 shell 表达式。
- 成功后登记并打开真实仓库；过程有进度、失败和取消。失败或取消保留已生成目录，明确路径与结果，不递归清除既有用户目录。
- Git 传输沿已有 credential helper / ssh-agent，需要交互认证时按既定规则及时失败并指引终端配置。API 登录不改变该身份。

### F. GitHub 账号与 PR

- GitHub App + device flow，手动 Token 备用；只支持 github.com，多账号按仓库记住。用户令牌与刷新令牌放 macOS 钥匙串，普通配置仅保存必要的非敏感标识；日志、诊断、前端持久存储均不含令牌。
- 注册 client_id、启用 device flow 与组织安装为外部前提；没有配置时显示具体说明并保留 Token 入口，不嵌入 client secret 或借用其他应用身份。权限取用户、App 和安装范围的实际交集。
- 显示验证码、授权链接、轮询 / 取消 / 过期与拒绝状态；按服务器节流和刷新轮换结果持久保存。切账号 / 仓库后迟到结果不得覆盖新目标；失败保留原目标与草稿。
- PR 列表 / 详情 / diff / 讨论可分页，使用实际权限与 head / base 标识；GitHub 返回文本按不可信内容展示，不执行其中 HTML / 脚本。
- 检出 PR 经 Rust 受控 Git 入口，并沿已有未提交改动、保护与回收策略；明确仓库、远端、分支和 head。不悄悄添加远端，不自动推送。
- 支持已有 fork，明确来源仓库 / 分支和目标仓库 / 分支；M7 不自动创建 fork。用户明确提交才创建 PR、发评论或审阅。
- PR 审阅草稿保存在本机并绑定 PR 与提交版本；发布前重新核对版本。权限不足、离线、过期或 head 变化时保留草稿并解释，不自动改用新版本发送。
- 合并前确认方式、目标与 head SHA；GitHub 版本冲突或结果不确定不自动重试写入，先查询核对，展示已知回执。
- 分支保护只读取得现有分支保护状态，与本地保护列表取并集；完整分页成功才替换缓存。失败保留旧结果并标注可能过期，首次无缓存时明确未同步；不修改 GitHub 规则。

### G. 诊断

- 以当前仓库为默认范围，跨重启只保留脱敏操作摘要和错误，正常保留 7 天，可清空；导出前展示与实际产物相同的预览，用户手动导出和发送。
- 采用明确字段白名单提取，不把原 Git 命令日志输出拷贝后打码当作合格诊断。路径、远端地址、邮箱、凭据等默认脱敏；始终排除文件正文、diff、终端输入输出、编辑草稿和 Token。
- 解析异常或无法确认内容边界时宁可省略该段并保留结构化错误类别，不把不受控的 stderr、异常字符串或 HTTP 正文直接持久化。
- 仅在独占 appdata 中验证到期、清空、故障与原子写；不读取用户历史诊断或密钥。

### H. 应用更新与 Actions 打包

- 启动时检查版本，默认稳定版；用户主动开启预发布。检查、下载、已下载待安装、安装 / 重启、失败状态分开，用户确认后下载和安装。
- 安装前协调未保存编辑、合并编辑、在途 Git 写入、结果待核对与运行中终端，再确认重启；取消或处理失败时不关闭、不安装。切语言 / 仓库不丢失全局更新状态。
- 使用 Tauri updater 的强制签名校验；正式公钥与发布来源可配置但必须受信任，未配置时明确不可更新。测试公钥与坏签名仅用于独占 fixture，不能作为生产发布身份。
- GitHub App、正式签名公钥和私钥、CI Secrets、真实账号授权、真实下载更新属于部署接线 / 验收前提；实现配置与文档，不能用占位值冒充已上线。
- GitHub Actions：main 推送只检查，版本标签构建 macOS Apple Silicon 的安装包与 updater 产物，先进入 Release 草稿；公开后才进入所选渠道。版本、平台、架构、URL、签名与产物必须对应；保留现有 Windows 编译检查。
- 无 Apple 开发者证书，暂不做该证书签名 / 公证，不关闭 updater 签名校验。私钥只经 CI secret 注入，不进源码或日志。
- 本轮授权实现工作流与本地构建；不授权推送、打版本标签、创建远端 PR / Release、配置用户 Secrets 或公开发布。

### I. 更改列表：事实门槛

- 默认暂存区模式；更改列表模式与之互斥，在设置中切换；分组按 worktree 保存在 Revia，切换不删除分组。
- 每项改动只属一个列表，支持创建 / 重命名 / 默认列表、移动整文件与 Git 原始块；新改动入默认列表，删列表时剩余内容回默认；提交后只移除已提交部分。
- Git hunk 与块选择仍来自系统 Git；块变化无法可靠关联时保留原分组信息供核对，取消失效勾选，要求重新选择。
- 终端已有已暂存内容、部分暂存同文件、切换模式前后真实 index、只勾另一块提交后未选内容的处理，按 Q120 / ADR-0003 必须先实测 Rebased 1.1.22。
- 2026-10-31 独占 fixture 的真实 Rebased 1.1.22 观察已完成（详见任务13 Comments及 `rebased-index-observations.md`）：切换两种模式不改变 HEAD、index 或工作区；更改列表提交只包含勾选内容。
- 提交未触及的其他路径，其已有暂存内容保持原样且不得混入提交；被部分提交的同一路径，提交后 index 对齐新 HEAD，未勾选块（含原先已暂存块）保留在工作区并显示为未暂存。工作区内容不因选择提交而被覆盖。
- 提交前核对 HEAD、index、操作状态及选择对应的文件/原始 Git 块；失配拒绝，取消失效勾选并保留归组信息。提交失败或结果待核对保留输入、分组和原始保护记录，不自动重试。

## Testing Decisions

- 测试目标是提交内容、文件字节 / 权限、目标身份、持久化、外部变化与用户确认等可观察结果；避免镜像实现或为纯样式新增测试框架。
- 优先复用生产 Rust 命令 / WorktreeSession、已有真实 Git 集成测试和前端 IPC 消费链路。新资源只在 HTTP / 凭据存储 / PTY / updater 等外部边界提供受控适配，不在业务代码遍布测试开关。
- Git 采用独占 fixture、独占 HOME / appdata 和 local remote；编辑覆盖外部修改、换 worktree、保存后重读失败与重启恢复；更改列表事实解阻后断言实际提交树、index 和剩余工作区。

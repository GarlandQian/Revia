## 已确认：第一轮

用户于 2026-10-30 对 Q176–Q181 回复“按你推荐”，补充“还有要使用github actions作为打包”，并对 Q181 注释“我没有证书”。

| 决策 | 结论 |
| --- | --- |
| Q176 | PR 包含列表、详情与 diff、创建草稿或正式 PR、检出分支、评论、提交审阅、合并 |
| Q177 | 工作区 diff 用 ⌘S 明确保存；切文件或 worktree 保留未保存编辑；关闭时保存 / 放弃 / 取消；暂存、提交前处理相关未保存编辑 |
| Q178 | 每个 worktree 独立保留多个终端会话；切换时保留；关闭运行中进程前确认；仓库变化按外部修改核对 |
| Q179 | 克隆 URL＋目标目录，高级选项含分支、浅克隆、递归子模块；成功后打开；失败或取消保留已生成目录并说明残留 |
| Q180 | 诊断默认当前仓库；路径、远端地址、作者邮箱等默认脱敏；导出前预览，始终排除文件正文和 diff |
| Q181 | 默认稳定版，预发布版主动开启；确认后下载和安装；处理未保存编辑、Git 写入与终端会话后再确认重启 |
| Q182 | GitHub Actions 打包；无 Apple 证书仍沿 Q63 试用分发，Tauri 更新包使用自行生成的签名密钥 |

Q182 延续 Q62 的触发方式：main 推送只检查，版本标签生成分发包。M7 发布 macOS Apple Silicon，Windows 发布仍在 M8；现有 Windows 编译检查保留。本轮没有要求推送、打标签或发布。

## 已核对的实现起点

- 普通 diff 尚无编辑保存接口；已有三方合并结果编辑器不等于工作区编辑已实现。
- 底栏终端图标当前打开的是 Git 命令日志，没有可交互的终端会话。
- 当前仓库登记针对已有本地仓库，尚无克隆流程；Git 传输继续沿 credential helper / ssh-agent（Q153），GitHub API 登录另行设计。
- 当前分支保护是本地列表；尚无 GitHub API、PR 或钥匙串接线。
- GitHub 的只读事实调查已完成：device flow 需要注册应用并启用，但客户端不需携带 client secret；保护分支状态与完整远端策略是不同范围。调查结论是技术依据，不代表用户已选认证方案或同步范围，见 [GitHub 事实](./github-facts.md)。
- 现有命令日志保留 stdout/stderr，可能含文件正文和 diff；不能把它原样作为满足 Q180 的诊断包。
- 只有编译检查工作流，尚无发布打包或 updater 接线。[分发事实核对](./distribution-facts.md) 区分 Apple 证书与更新签名。

本轮仅做文档与只读核对，没有运行产品构建、测试或桌面验收；不将源码中已有接缝写成验证已通过。

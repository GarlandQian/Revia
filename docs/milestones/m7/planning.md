# M7 扩展：访谈记录

更新日期：2026-10-30。阶段：第 1 步访谈；本文件不是 `spec.md`，不表示实施已就绪。决定以 [docs/README.md](../../README.md) 为准。

## 起点与范围

M6 已合入 main，接手基点为 `8b9548774054c64921e2a1f57214b711f51c5f72`。M6 收尾小改动真机补查见 [backlog 14](../backlog/14-m6-final-desktop-recheck.md)，旧 M6 交接待办不再作为当前实施任务。

M7 的七项核心功能是更改列表模式、diff 工作区一侧可编辑、内置终端、克隆、GitHub PR、导出诊断信息、应用更新（Q126）。另外包含已排入 M7 的颜色主题导入（Q132）、自定义快捷键与 GitHub 分支保护规则同步（Q139）。日志索引只有在大仓库筛选确实慢时才实施（Q151），本轮未测出需要建索引的事实。界面双语已在 M6，自动解决 import 冲突未排期；其他 backlog 不自动纳入。

布局与交互继续按 Rebased 1.1.22；第四轮新增 Liquid Glass 外观，保留颜色主题与代码可读性（Q189、Q190）。更改列表模式下终端已有暂存内容的处理，Q120 与 [ADR-0003](../../adr/0003-git-index-not-changelists.md) 明确要求先实测 Rebased，目前尚无本轮实测结果。

## 已确认：第一轮

用户于 2026-10-30 对 Q176–Q181 回复“按你推荐”，补充“还有要使用github actions作为打包”，并对 Q181 注释“我没有证书”。

| 决策 | 结论 |
| --- | --- |
| Q176 | PR 包含列表、详情与 diff、创建草稿或正式 PR、检出分支、评论、提交审阅、合并 |
| Q177 | 工作区 diff 用 ⌘S 明确保存；切文件或 worktree 保留未保存编辑；关闭时保存 / 放弃 / 取消；暂存、提交前处理相关未保存编辑 |
| Q178 | 每个 worktree 独立保留多个终端会话；切换时保留；关闭运行中进程前确认；仓库变化按外部修改核对 |
| Q179 | 克隆 URL＋目标目录，高级选项含分支、浅克隆、递归子模块；成功后打开；失败或取消保留已生成目录并说明残留 |
| Q180 | 诊断默认当前仓库；路径、远端地址、作者邮箱等默认脱敏；导出前预览，始终排除文件正文和 diff |
| Q181 | 默认稳定版，预发布版主动开启；确认后下载和安装；处理未保存编辑、Git 写入与终端会话后再确认重启 |
| Q182 | GitHub Actions 打包；无 Apple 证书仍沿 Q63 试用分发，Tauri 更新包使用自行生成的签名密钥 |

Q182 延续 Q62 的触发方式：main 推送只检查，版本标签生成分发包。M7 发布 macOS Apple Silicon，Windows 发布仍在 M8；现有 Windows 编译检查保留。本轮没有要求推送、打标签或发布。

## 第二轮：部分确认

用户于 2026-10-30 对 Q183 追问“什么意思”，对 Q184 追问“rebased是怎么做的”，并回复“其余按推荐”。该轮只确认 Q185–Q188，当时保留 Q183、Q184 待解释；后续确认见第三轮。

| 决策 | 结论 |
| --- | --- |
| Q185 | 只读同步 GitHub 现有分支的保护状态，与本地列表取并集；失败保留上次结果并提示过期，不修改远端规则 |
| Q186 | 未保存编辑自动保存本机编辑草稿，重启或崩溃后可恢复；磁盘文件已变化时保留两版供对比，不自动覆盖 |
| Q187 | 脱敏操作摘要与错误跨重启保留 7 天，可手动清空；排除正文、diff、终端输入输出 |
| Q188 | 版本标签触发 Actions 打包，先生成带安装包的 Release 草稿；确认后公开，公开后客户端才收到更新 |

当时解释的 Q183 提案涵盖 github.com 上的公开、私有和组织仓库；多个账号指可按仓库记住个人或工作账号，另域名的 Enterprise 服务是单独的兼容范围。Q184 补核了 Rebased 1.1.22 安装包：接有浏览器 OAuth、Token、Enterprise 入口，浏览器流程使用 JetBrains 服务；未实际登录。静态事实见 [GitHub 事实](./github-facts.md#rebased-1122-的登录参照)。

## 第三轮：账号与登录确认

用户进一步问“用途是什么”。解释 GitHub 登录用于 PR、讨论、审阅、合并和保护状态，多账号用于区分个人与工作身份，本地 Git 操作不要求该登录，Git 传输仍沿既有凭据后，用户回复“按你推荐”。Q183、Q184 至此确认，不重新询问。

| 决策 | 结论 |
| --- | --- |
| Q183 | 仅 github.com，涵盖公开、私有和组织仓库；可添加多个账号并按仓库记住选择；另域名 Enterprise 后做 |
| Q184 | 浏览器验证码授权（device flow）加手动 Token 备用入口，使用 Revia 自己注册的应用，令牌存 macOS 钥匙串；与 Git 传输认证分别管理 |

登录流程及客户端无需借用 JetBrains 授权服务已确定。官方资料已核实 GitHub App 和 OAuth App 的 device flow 首次交换及续期均可不携带应用密钥；权限范围与组织安装模型仍有用户可见差异，App 类型尚未确认，详见 [GitHub 事实](./github-facts.md#应用类型权限与续期)。

## 第四轮：Liquid Glass 与代码清晰度

用户提供 React Bits 仓库，要求将外观改为 Liquid Glass，并选择较强的透明、折射与悬浮感；随后强调代码必须看清。记录为 Q189、Q190，纳入 M7 外观范围；原有 Rebased 布局与交互、颜色主题、字体、图标、安全边界继续沿用。

外观预览采用强玻璃框架和不透明代码底色。用户又询问“如果全部替换为玻璃可行吗”，因此增加全界面玻璃的对比提案：代码区采用低透明底层，文字不参与滤镜。此询问不视为已经选择代码区透明；两种预览均不能替代真实 WebView 验收。见 [材质核对与预览](./liquid-glass.md)。

## 第五轮：协调性与 Windows

用户对第一版及全玻璃对比反馈“很不协调”，并要求考虑将来发布的 Windows 版。记录 Q191：设计阶段同时考虑 macOS 与 Windows，沿用共享设计与平台外壳，不变更 Windows 的 M8 发布时间。

第一版保留为未采用稿。第二版提案改为整窗连续材质、同色系的代码表面、细分隔线与统一控件比例，分别示意 macOS 红绿灯 / 系统菜单和 Windows 标题栏 / 原生菜单 / 右侧窗口按钮。预览提供浅深色、CSS 缩放与降低透明度检查；它不验证真实原生窗口、DPI 或 WebView2。第二版尚待用户反馈，不能写成已确认的像素规格。见 [第二版预览](./mockups/liquid-glass-v2.html)。

## 已核对的实现起点

- 普通 diff 尚无编辑保存接口；已有三方合并结果编辑器不等于工作区编辑已实现。
- 底栏终端图标当前打开的是 Git 命令日志，没有可交互的终端会话。
- 当前仓库登记针对已有本地仓库，尚无克隆流程；Git 传输继续沿 credential helper / ssh-agent（Q153），GitHub API 登录另行设计。
- 当前分支保护是本地列表；尚无 GitHub API、PR 或钥匙串接线。
- GitHub 的只读事实调查已确认 device flow 需要注册应用并启用，初次换取和续期不要求客户端携带 client secret。账号范围与登录方式已由 Q183、Q184 确定，App 类型尚未选择。保护分支状态与完整远端策略是不同范围，保护同步范围已由 Q185 确定，见 [GitHub 事实](./github-facts.md)。
- 现有命令日志保留 stdout/stderr，可能含文件正文和 diff；不能把它原样作为满足 Q180 的诊断包。
- 只有编译检查工作流，尚无发布打包或 updater 接线。[分发事实核对](./distribution-facts.md) 区分 Apple 证书与更新签名。

本轮仅做文档、独立外观预览与只读核对，没有运行产品构建、测试或桌面验收；预览检查单独记录，不将源码中已有接缝写成验证已通过。

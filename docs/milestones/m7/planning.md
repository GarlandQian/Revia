| 决策 | 结论 |

Q182 延续 Q62 的触发方式：main 推送只检查，版本标签生成分发包。M7 发布 macOS Apple Silicon，Windows 发布仍在 M8；现有 Windows 编译检查保留。本轮没有要求推送、打标签或发布。

## 第二轮：部分确认

用户于 2026-10-30 对 Q183 追问“什么意思”，对 Q184 追问“rebased是怎么做的”，并回复“其余按推荐”。因此本轮只确认 Q185–Q188；Q183、Q184 的编号保留，未放入已确认表。

| 决策 | 结论 |
| --- | --- |
| Q185 | 只读同步 GitHub 现有分支的保护状态，与本地列表取并集；失败保留上次结果并提示过期，不修改远端规则 |
| Q186 | 未保存编辑自动保存本机编辑草稿，重启或崩溃后可恢复；磁盘文件已变化时保留两版供对比，不自动覆盖 |
| Q187 | 脱敏操作摘要与错误跨重启保留 7 天，可手动清空；排除正文、diff、终端输入输出 |
| Q188 | 版本标签触发 Actions 打包，先生成带安装包的 Release 草稿；确认后公开，公开后客户端才收到更新 |

Q183 的提案涵盖 github.com 上的公开、私有和组织仓库；多个账号指可按仓库记住个人或工作账号，另域名的 Enterprise 服务是单独的兼容范围。Q184 已补核 Rebased 1.1.22 安装包：接有浏览器 OAuth、Token、Enterprise 入口，浏览器流程使用 JetBrains 服务；尚未实际登录。Revia 的浏览器验证码授权与 Token 备用入口仍是建议，不把用户的询问当成同意，详见 [GitHub 事实](./github-facts.md#rebased-1122-的登录参照)。

## 已核对的实现起点

- 普通 diff 尚无编辑保存接口；已有三方合并结果编辑器不等于工作区编辑已实现。
- 底栏终端图标当前打开的是 Git 命令日志，没有可交互的终端会话。
- 当前仓库登记针对已有本地仓库，尚无克隆流程；Git 传输继续沿 credential helper / ssh-agent（Q153），GitHub API 登录另行设计。
- 当前分支保护是本地列表；尚无 GitHub API、PR 或钥匙串接线。
- GitHub 的只读事实调查已完成：device flow 需要注册应用并启用，但客户端不需携带 client secret；保护分支状态与完整远端策略是不同范围。认证方案仍待确认，保护同步范围已由 Q185 确定，见 [GitHub 事实](./github-facts.md)。
- 现有命令日志保留 stdout/stderr，可能含文件正文和 diff；不能把它原样作为满足 Q180 的诊断包。
- 只有编译检查工作流，尚无发布打包或 updater 接线。[分发事实核对](./distribution-facts.md) 区分 Apple 证书与更新签名。

本轮仅做文档与只读核对，没有运行产品构建、测试或桌面验收；不将源码中已有接缝写成验证已通过。

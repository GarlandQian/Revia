# M4：界面重做（Rebased 的布局与交互，VS Code 的外观）

**Status:** ready-for-agent

依据：Q117–Q136；ADR-0003、ADR-0004、ADR-0005、ADR-0009、ADR-0010、ADR-0011；[产品方向](../../product-direction.md#实施顺序)、[UI 方向](../../ui-direction.md)、[安全边界](../../product-direction.md#安全边界)。布局与交互参照见 [Rebased 参照](./rebased-reference.md)，外观见已确认的 [效果图](./mockups/)。

按 Q136 整包实施：Pi 在 `m4` worktree 中一次实现整份规格，做完后统一审查与验收，中间不逐项派发、不逐屏等待确认。执行说明见 [整包交接](./paseo-batch.md)。下文写明的交互是实现依据；验收时再与本机 Rebased 1.1.22 对照，不一致的按 Rebased 修正（Q129、Q131）。

## 目标

把 M1–M3 已有的功能（仓库与 worktree、改动列表、暂存与取消暂存、丢弃与回收区、审阅标记、diff、提交区）按本机 Rebased 1.1.22 的布局与交互、VS Code 的外观重做界面，加上颜色主题与代码字体设置，并补上多选、全部暂存和多个文件一起丢弃。M4 完成后开始自用，推送先在终端中做（Q126）。

## 不在 M4

- M5：日志、分支组件、fetch、pull、push、提交并推送、Git 控制台日志。
- M6：stash、内置三方合并与继续/中止/跳过、在日志中改写历史、文件历史与 blame。
- M7：更改列表模式、diff 可编辑、内置终端、克隆、GitHub PR、导出诊断信息、自动更新。
- M8：Windows 打包。

这些功能在 Rebased 中的位置（例如顶栏的分支组件）M4 留空，不放入口或占位按钮。

## 规则

- 布局与交互以 Rebased 为准，外观以 VS Code 和所选颜色主题为准；旧界面决定冲突时同样照此处理（Q129、Q131）。
- 以下保持原决定：
  - 安全边界：写前校验 diff 指纹；丢弃先存回收区；hunk 来自 Git，不提供忽略空白等改变 hunk 划分的选项（Q17、ADR-0004）；不删锁文件；不改用户的 Git 配置。
  - Revia 独有功能的行为：审阅标记、回收区、结果待核对、提交前快照。
- 全部代码（界面与后端）由 Pi 实现，模型顺序按 Q112；整包完成后由规划方审查，审查问题按 Q113 最多交回 Pi 返修一次（Q136）。

## F01 视觉基础

1. 颜色主题（Q132、Q134）：设计变量按 VS Code 颜色主题的键命名并取值（例如 `sideBar.background`、`list.activeSelectionBackground`、`diffEditor.insertedTextBackground`、`gitDecoration.modifiedResourceForeground`），语法颜色取主题的 `tokenColors`。内置 VS Code Light 2026、Atom One Light、VS Code Dark 2026、One Dark Pro 四套，浅色、深色各选一套，随系统切换；默认浅色 Atom One Light、深色 One Dark Pro。主题文件随应用打包并保留各自许可。Q107 时期的设计变量全部替换。
2. 字体（Q131、Q133）：界面字体用系统字体，控件样式与尺寸照 VS Code（效果图中的行高 22、页签高 35、状态栏高 22）；代码字体默认 JetBrains Mono，可在设置中改字体和字号，本机没有该字体时退回默认。
3. 图标（Q130）：界面图标用 Codicons，取代现在的 lucide-react；文件类型图标用 Material Icon Theme，取代现在自绘的文件类型图标。图标的尺寸、位置和用在哪个操作上照 Rebased，只换图形。两套图标的版本与来源记在仓库中，“关于 Revia”注明 Codicons（CC BY 4.0）与 Material Icon Theme（MIT）的版权与许可。
4. 文件名按状态上色，颜色取颜色主题的 `gitDecoration.*`，不显示状态字母（Q128）。

## F02 主窗口框架

布局按[效果图](./mockups/)：

1. 主工具栏（高 38）：macOS 红绿灯；仓库组件，点开是已添加仓库的列表和“添加仓库…”；worktree 组件，点开是当前仓库的 worktree 列表，每行显示分支、路径、有无未提交改动、进行中的操作、领先和落后数（Q126，取代原定的 worktree 侧栏）；右侧是设置按钮。
2. 左侧工具窗口图标条，M4 只有“提交”一个图标，带未提交文件数徽标；点击切换“提交”工具窗口的显示与隐藏。
3. 主区域是编辑器页签区，M4 只有 diff 页签。没有打开的页签时显示空状态，写常用快捷键提示。
4. 底部状态栏：当前分支、领先和落后数（注明“截至上次 fetch”）、自动刷新不可用时的提示、审阅进度。
5. 没有仓库时显示欢迎界面：已添加仓库列表与“添加仓库”按钮，支持 ⌘O 和拖入文件夹（Q35）。

## F03 提交工具窗口（暂存区模式）

1. 标题行有“提交”“回收区”两个页签（Q119）和工具条：刷新、丢弃所选、展开全部、收起全部、更多。
2. 改动树依次为已暂存、未暂存、未跟踪三组，组标题显示文件数；未跟踪默认收起（Q30）；同一文件可以同时出现在两组（Q8）。每行是文件类型图标、按状态上色的文件名、灰色的所在目录（重命名时写“原 …”）。
3. 单击文件：选中并在预览页签（标题斜体）中显示 diff，单击另一个文件时替换预览页签；双击或按 Enter：把它固定为普通页签。
4. 多选：Shift 点选连续范围，⌘ 点选增减，⇧↑ / ⇧↓ 扩展，⌘A 全选当前树。暂存（⌥⌘A）、取消暂存、丢弃（⌥⌘Z）作用于全部选中项；悬停或选中的行在右侧显示行内按钮（未暂存、未跟踪行：丢弃、暂存；已暂存行：取消暂存）；组标题右侧显示“全部暂存”或“全部取消暂存”按钮。
5. 只读文件不参与批量操作，在结果中说明跳过原因：符号链接、子模块、无法无损处理的路径、未解决冲突（Q81–Q83）。
6. 丢弃多个文件：弹出一次确认对话框，列出将丢弃的文件，说明会先存入回收区；确认后逐个文件先存回收区再丢弃（Q120）。部分失败时用通知如实列出哪些已完成、哪些未执行。
7. 已审阅的文件在行尾显示小图标（Q121）；⌥⌘R 的行为不变（Q94）。

## F04 提交区

1. 位于“提交”页签底部，从上到下：“修改上一次提交”勾选框（右侧是最近提交信息按钮）、提交信息框、“提交”按钮与齿轮按钮、审阅进度（Q20）。齿轮打开提交选项弹层，内有“跳过 hooks”，默认不勾，提交后复原（Q21）。
2. M3 的行为全部保留：进行中操作的门禁、模板、最近 20 条、按 worktree 保存的草稿、amend 已在上游时的确认、⌘K 提交。
3. 提交进行中，提交区显示进度和可展开的 hooks 实时输出；完成后用通知气泡报告结果（提交号、提交信息首行、提交前快照存了哪些文件、hooks 改动过的文件），失败时保留提交信息与输出。

## F05 diff 页签

1. 页签标题是文件名加“未暂存”或“已暂存”；页签下方是路径导航行。页签栏右侧工具条：上一处、下一处改动（⇧F7 / F7）、并排与统一切换（选择会被记住，Q17）、“标记为已审阅”、更多。
2. 块（hunk）级暂存、取消暂存、丢弃的入口照 Rebased 暂存区模式下的 diff，按钮写“暂存此块”“取消暂存此块”“丢弃此块”；界面文案中的 hunk 全部改为“块”（Q135）。操作对象仍是 Git 生成的 hunk，执行前校验指纹（ADR-0004、ADR-0005、ADR-0009）。
3. “标记为已审阅”按钮切换当前文件的审阅标记，不跳转（Q121）。
4. lock 文件、二进制和超大文件默认收起（Q32），说明用编辑器提示条。
5. 渲染与滚动保持 M2 规格 D06 的性能门槛。

## F06 回收区页签

回收记录的列表、详情、恢复、另存和清空移到“回收区”页签，规则不变（Q29、Q85–Q87、ADR-0010）。确认和只读说明改用 Rebased 的对话框与提示条形式。

## F07 提示与通知

把现有的提示条、错误、结果待核对、自动刷新不可用、写入期间关闭或退出的询问，换成以下形式，内容和规则不变（Q90、Q91、Q95、Q96、Q119）：

- 与当前文件有关的状态（默认收起、只读、冲突、写前校验失败）：diff 页签顶部的提示条。
- 一次操作的结果（暂存、丢弃、提交、恢复）：窗口右下角的通知气泡；成功的约 10 秒后自动消失，失败与结果待核对的一直保留到手动关闭。
- 需要选择的情况（丢弃确认、写入期间关闭或退出）：对话框。

## F08 设置

设置是一个对话框，左侧分类、右侧内容（Rebased 的设置布局），外观照 VS Code；分类为“外观”（颜色主题、代码字体与字号）和“Git”（Git 程序路径、合并工具、重新加载环境）。设置项：Git 程序路径、合并工具、重新加载环境、颜色主题（浅色、深色各一项，Q132）、代码字体与字号（Q133）。回收区的查看与清空在“回收区”页签中。

## F09 后端

1. 多文件暂存、取消暂存、丢弃：按文件校验写前指纹（ADR-0009），串行执行，返回逐个文件的结果；丢弃时逐个先存回收区。
2. worktree 列表的只读状态：分支、有无未提交改动、进行中的操作、领先和落后数（按本地记录）。
3. 不新增 M5 以后的命令。

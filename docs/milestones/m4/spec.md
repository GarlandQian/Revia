# M4：界面照 Rebased 重做

**Status:** needs-info

依据：Q117–Q130；ADR-0003、ADR-0004、ADR-0005、ADR-0009、ADR-0010、ADR-0011；[产品方向](../../product-direction.md#实施顺序)、[UI 方向](../../ui-direction.md)、[安全边界](../../product-direction.md#安全边界)。外观数据见 [Rebased 参照](./rebased-reference.md)。

本规格是草稿。在 Rebased 窗口里逐屏截图实测（见参照末节），把实测的尺寸与交互补进下文后，改为 `ready-for-agent`。

## 目标

把 M1–M3 已有的功能（仓库与 worktree、改动列表、暂存与取消暂存、丢弃与回收区、审阅标记、diff、提交区）按本机 Rebased 1.1.22 一比一重做界面，并补上多选、全部暂存和多个文件一起丢弃。M4 完成后开始自用，推送先在终端中做（Q126）。

## 不在 M4

- M5：日志、分支组件、fetch、pull、push、提交并推送、Git 控制台日志。
- M6：stash、内置三方合并与继续/中止/跳过、在日志中改写历史、文件历史与 blame。
- M7：更改列表模式、diff 可编辑、内置终端、克隆、GitHub PR、导出诊断信息、自动更新。
- M8：Windows 打包。

这些功能在 Rebased 中的位置（例如顶栏的分支组件）M4 留空，不放入口或占位按钮。

## 规则

- 外观与交互以 Rebased 为准，旧界面决定与 Rebased 冲突时照 Rebased（Q129）。
- 以下保持原决定：
  - 安全边界：写前校验 diff 指纹；丢弃先存回收区；hunk 来自 Git，不提供忽略空白等改变 hunk 划分的选项（Q17、ADR-0004）；不删锁文件；不改用户的 Git 配置。
  - Revia 独有功能的行为：审阅标记、回收区、结果待核对、提交前快照。
- 界面由 Claude 实现，每完成一屏与 Rebased 并排截图，经用户认可再继续；后端任务派给 Pi（Q125）。

## F01 视觉基础

1. 设计变量全部取自 Islands Light / Islands Dark（参照数据），跟随系统深浅色。Q107 时期的近似值全部替换：现在的窗口底色、工具窗口底色、选中色和 diff 配色都与 Rebased 不同。
2. Inter 与 JetBrains Mono 继续随应用打包；字号与行高按实测。
3. 图标（Q130）：界面图标用 Codicons，取代现在的 lucide-react；文件类型图标用 Material Icon Theme，取代现在自绘的文件类型图标。图标的尺寸、位置和用在哪个操作上照 Rebased，只换图形。两套图标的版本与来源记在仓库中，“关于 Revia”注明 Codicons（CC BY 4.0）与 Material Icon Theme（MIT）的版权与许可。
4. 文件名按状态上色，颜色取 `FILESTATUS_*`，不再显示状态字母（Q128）。

## F02 主窗口框架

1. 主工具栏：macOS 红绿灯；仓库组件（切换仓库、添加仓库）；worktree 下拉，每行显示分支、有无未提交改动、进行中的操作、领先和落后数（Q126，取代原定的 worktree 侧栏）。
2. 左侧工具窗口图标条，M4 只有“提交”工具窗口。
3. 主区域是编辑器页签区，M4 只有 diff 页签；没有打开页签时照 Rebased 的空状态。
4. 底部状态栏。
5. 没有仓库时照 Rebased 的欢迎界面，保留 ⌘O 和拖入文件夹（Q35）。

## F03 提交工具窗口（暂存区模式）

1. 两个页签：“提交”“回收区”（Q119）。
2. 改动树分已暂存、未暂存、未跟踪三组：未跟踪默认收起（Q30），同一文件可以同时出现在两组（Q8）。分组、行和工具条按钮照 Rebased 的暂存区模式。
3. 多选：Shift、⌘ 点选和键盘扩展选择。对选中项暂存、取消暂存、丢弃；分组上提供全部暂存、全部取消暂存。
4. 只读文件不参与批量操作并说明原因，包括符号链接、子模块、无法无损处理的路径、未解决冲突（Q81–Q83）。
5. 多个文件一起丢弃：确认一次，逐个文件先存回收区再丢弃（Q120）。部分失败时如实列出哪些已完成、哪些未执行。
6. 已审阅的文件显示小图标（Q121）。
7. 选中文件后在编辑器页签打开 diff，单击、双击行为照 Rebased。
8. 快捷键照 Rebased；⌥⌘R 的审阅行为不变（Q94）。

## F04 提交区

1. 位于“提交”页签下方，照 Rebased：“修改上一次提交”勾选框、提交信息框、“提交”按钮、提交选项弹层。“跳过 hooks”放在弹层里，默认不勾，提交后复原（Q21）。
2. 审阅进度显示在提交按钮旁（Q20）。
3. M3 的行为全部保留：进行中操作的门禁、模板、最近 20 条、按 worktree 保存的草稿、amend 已在上游时的确认、hooks 实时输出、提交前快照。输出与结果改用 Rebased 的展示位置，按实测。

## F05 diff 页签

1. 页签标题、差异导航、并排与统一切换照 Rebased 的 diff 查看器。
2. hunk 级暂存、取消暂存、丢弃的入口照 Rebased 暂存区模式下的 diff。操作对象仍是 Git 生成的 hunk，执行前校验指纹（ADR-0004、ADR-0005、ADR-0009）。
3. 工具栏放“标记为已审阅”按钮（Q121）。
4. lock 文件、二进制和超大文件默认收起（Q32），说明用编辑器提示条。
5. 渲染与滚动保持 M2 规格 D06 的性能门槛。

## F06 回收区页签

回收记录的列表、详情、恢复、另存和清空移到“回收区”页签，规则不变（Q29、Q85–Q87、ADR-0010）。确认和只读说明改用 Rebased 的对话框与提示条形式。

## F07 提示与通知

把现有的提示条、错误、结果待核对、自动刷新不可用、写入期间关闭或退出的询问，换成 Rebased 的编辑器提示条、通知气泡和对话框（位置见 Q119）。内容和规则不变（Q90、Q91、Q95、Q96）。

## F08 设置

设置改为 Rebased 设置对话框的形式。设置项沿用现有的：Git 程序路径、合并工具、重新加载环境、diff 字号。回收区的查看与清空在“回收区”页签中。

## F09 后端

1. 多文件暂存、取消暂存、丢弃：按文件校验写前指纹（ADR-0009），串行执行，返回逐个文件的结果；丢弃时逐个先存回收区。
2. worktree 列表的只读状态：分支、有无未提交改动、进行中的操作、领先和落后数（按本地记录）。
3. 不新增 M5 以后的命令。

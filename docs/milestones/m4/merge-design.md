# M4 内置三方合并：实现设计（Q143）

本设计供 Pi 在 M4 返修中实现 Q143，照 Rebased 的合并窗口来做。差异与合并结果全部由 Git 生成，Revia 不自己算合并。继续、中止、跳过仍在 M6，M4 不放入口。安全边界不变：
- 覆盖工作区内容前先存回收区（Q123）；
- 写前校验指纹；
- 不修改 Git 配置、不删除 `index.lock`；
- Git 调用只在 Rust 层。

## 1. 入口

- **冲突组：** 改动树最上方新增“冲突”组，照 Rebased 的 Merge Conflicts 节点：
  - 列出 Git 标记为未解决冲突的文件；
  - 组标题右侧有“解决…”按钮，打开冲突对话框；
  - 双击某个文件或按 Enter，直接打开它的合并页签；
  - 冲突文件不再出现在已暂存、未暂存组里，批量操作照旧跳过它们（Q82）。
- **冲突对话框：** 照 Rebased 的 Conflicts 对话框：
  - 左侧是文件列表，列出文件、你的版本状态、对方的版本状态（已修改、已删除、已新增）；
  - 右侧三个按钮：“接受你的版本”“接受对方的版本”“合并…”；
  - 可以多选文件后一起接受某一侧。
- **diff 页签：** 冲突文件的 diff 页签顶部提示条写“有未解决的冲突”，带“解决冲突”按钮，打开合并页签。这一条取代左右对照设计第 3.2 节里的“用合并工具打开”：M4 不再调用外部合并工具。

## 2. 合并页签（三栏）

```
┌ 你的版本：当前分支 main ──┬────┬ 结果 ───────────────────┬────┬ 对方的版本：feature ──┐
│ A-main               ░░░ │ »  │ <冲突：待选择>       ▓▓▓ │  « │ a                 ░░░ │
│ b-main               ░░░ │    │                          │    │ B-feature         ░░░ │
│ c                        │    │ c                        │    │ c                     │
│ …                        │    │ G-feature   已应用       │    │ G-feature             │
└──────────────────────────┴────┴──────────────────────────┴────┴───────────────────────┘
```

- 合并页签和 diff 页签一样，是编辑器页签区里的一个页签，标题为“合并：<文件名>”。
- **栏头**按进行中的操作命名，名称取 M3 进行中操作识别的数据：

  | 进行中的操作 | 左侧（stage 2） | 右侧（stage 3） |
  | --- | --- | --- |
  | merge | 当前分支 `<分支>` | 合并进来的 `<分支或短哈希>` |
  | rebase | 上游 `<onto>` | 你的提交 `<短哈希 首行>` |
  | cherry-pick、revert | HEAD | 被应用的提交 `<短哈希 首行>` |

  取不到名称时，左侧写“你的版本”，右侧写“对方的版本”。
- **两条窄栏**（左与中之间、中与右之间）做法同 [左右对照设计](./side-by-side-design.md)：行号、弧形色带、按钮。
  - 左窄栏的 »：把左边这一段放进结果；右窄栏的 «：把右边这一段放进结果；
  - 冲突段旁另有“✕ 忽略这一侧”；同一处冲突两侧都放进结果时，左边在前。
  - 冲突段用颜色主题的冲突色；已经自动放进结果的不冲突段，标“已应用”并淡显。
- **同步滚动：** 以中栏为基准，用左右对照设计里的 `mapLine` 分别映射到左栏和右栏。
- **中栏可以编辑：**
  - 用普通文本编辑器，推荐 CodeMirror 6 的基础编辑功能，不加载它的 diff 或 merge 扩展，差异全部来自 Git；
  - 支持撤销、重做，语法高亮沿用现有配色；
  - 编辑后各段位置随之更新；编辑落在某段内时，该段标为“已手动修改”。
- **工具条：**
  - 上一处、下一处冲突（⇧F7、F7）；
  - “应用所有不冲突的改动”：设置“合并时自动应用无冲突改动”关闭时可用，这项设置从 M6 提到 M4；
  - “全部接受左边”“全部接受右边”；
  - “还有 N 处冲突”计数；
  - 主按钮“应用”；
  - “取消”。
- **不能三栏合并的冲突**（二进制、符号链接、子模块、一边删除一边修改）：页签里只显示说明，以及“接受你的版本”“接受对方的版本”两个按钮。

## 3. 数据：Rust 层

- **读取：**
  - 三个版本：`git show :1:<路径>`（共同祖先；两边都新增时不存在）、`:2:<路径>`、`:3:<路径>`；
  - 再加工作区当前文件；
  - 四者与进行中的操作（类型、HEAD、MERGE_HEAD 等）在同一次快照里读取，生成指纹。
- **初始结果：**
  - 把三份内容写到 Revia 数据目录下的临时目录，不写进仓库；
  - 运行 `git merge-file -p --diff3 -L <左侧名> -L 共同祖先 -L <右侧名> <ours> <base> <theirs>`。退出码就是冲突数；不冲突的改动 Git 已经合进去了；
  - 解析冲突标记，得到每处冲突的你的版本、共同祖先、对方版本三段文本；
  - 规划方已在临时仓库验证这一步。
  - 设置“合并时自动应用无冲突改动”关闭时，初始结果用共同祖先，不冲突的段等用户点 » / « 或“应用所有不冲突的改动”。
- **段表：** 在临时文件上用 `git diff --no-index -U0` 分别求共同祖先到你的版本、共同祖先到对方版本的改动段（仍由 Git 生成），再换算到结果栏的坐标。用完删除临时目录。
- **命令（与现有命令同样带类型）：**
  - `merge_open(目标) -> MergeLayout`：两侧名称、各栏行数、段表、冲突表、指纹、快照版本；
  - `merge_lines(栏, from, to)`：按需取行；
  - `merge_apply(目标, 结果文本, 指纹)`；
  - `merge_accept_side(目标列表, 你的或对方的, 指纹)`。

## 4. 写入

- **点“应用”时还有未处理的冲突，或结果里仍有冲突标记：** 先弹对话框“还有 N 处冲突未解决，仍要保存当前结果吗？”，选项为“保存当前结果”“继续解决”，照 Rebased。
- **“应用”的步骤：**
  1. 写前校验指纹：三个版本的 blob 和工作区文件都没变，进行中的操作也没变。不一致就拒绝，并重新打开页签。
  2. 把工作区当前文件存入回收区（Q123）。
  3. 把结果写入工作区文件：
     - 换行风格保持与你的版本一致；
     - 可执行位不变。
  4. 用 `git add -- <路径>` 标记为已解决。这是用户明确点了“应用”，不算普通暂存隐含标记（Q82）。
  5. 写后核对：该路径不再是未解决冲突，暂存区内容等于写入的结果；对不上就标“结果待核对”。
- **整文件接受一侧：**
  - 你的版本或对方的版本：`git checkout --ours|--theirs -- <路径>` 后 `git add`；
  - 接受“删除”的一侧：用 `git rm -- <路径>`；
  - 同样先存回收区、写前校验、写后核对。
- **全部冲突解决后：** “冲突”组消失，进行中操作的提示条照 M3 显示。M4 不提供继续、中止、跳过。

## 5. 性能与测试

- **性能：**
  - 8000 行的文件，合并页签首屏 ≤ 300ms；
  - 三栏快速滚动不露白；
  - 滚动停下后同步误差 ≤ 1 行。
- **Rust 测试**（每项都用真实 Git 仓库）：
  - merge 的内容冲突；
  - 两边都新增（没有共同祖先）；
  - 一边删除一边修改；
  - 二进制冲突只能接受一侧；
  - rebase 冲突的栏头名称；
  - 关闭“自动应用”时的初始结果；
  - “应用”前文件被外部修改时拒绝；
  - “应用”先存回收区；
  - “应用”后该路径不再是未解决冲突；
  - 整文件接受一侧；
  - CRLF 保持；
  - 不改 Git 配置：`git config --list` 前后一致；
  - 临时目录被清理。
- **fixture 与冒烟：** `tools/fixtures/setup.sh` 增加一个带冲突的仓库，冒烟检查打开冲突组和合并页签。

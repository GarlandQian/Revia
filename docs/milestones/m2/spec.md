# M2 需求规格：安全选择变更与持久审阅

实施交付批次按[Q106](../../README.md)与[整包交接](./paseo-batch.md)执行：本轮剩余实现一起交付后总体验证，功能契约、效果图确认及最终验收门槛不变。

**Status:** ready-for-agent

确认日期：2026-10-20，2026-10-23 补充 Q98–Q104。本文整理已确认的 Q78–Q104，并承接 Q8、Q9、Q18–Q20、Q26、Q29、Q30、Q37、Q48、Q53、Q55、Q62、Q68、Q69；不产生新的产品决定。决策依据见 [设计文档](../../README.md)，术语以 [GLOSSARY](../../../GLOSSARY.md) 为准，遵守 [ADR](../../adr/) 中的约束。

## 问题

M1 已能打开本地仓库、切换已有 worktree 和查看 diff，但不能选择即将提交的改动。开发者仍需回到终端或 IDE 暂存、取消暂存、丢弃；编辑器在后台修改文件时，旧界面也不能成为安全写入的依据。M2 必须先验证当前工程的长期运行表现，再建立可恢复、目标明确、拒绝过期状态的写操作闭环，让开发者能够持续审阅与选择变更。

## 方案

先在可见的真实桌面窗口中完成同进程 30 分钟的长期运行基线。通过后提供单文件与单 hunk 暂存、取消暂存，以及先保存到回收区再执行的丢弃；恢复取回完整文件状态且不改变暂存区。审阅标记随文件版本持久保存；当前 worktree 的变化自动刷新，旧快照不能继续驱动操作。平台相关代码集中管理，并取得 Windows x64 上的实际编译结果。提交能力仍属于 M3。

## 实现决策

### 1. 长期运行门槛（Q53、Q78、Q84）

- M2 第一项工作是复现并验证当前正式工程的长期运行问题，其余功能以该项通过为前提。
- 使用 release 构建、可见窗口、固定一组文件和 worktree，在同一个进程连续切换文件、切换并排／统一视图并滚动 30 分钟。循环重启短测不能替代。
- 同时记录 Rust 主进程与相关 WebView 进程的内存趋势；允许首次加载、缓存热身增长，热身后不能持续增长。
- WebView 按“内存压力后仍保留的内存”判定（Q98）：约每 5 分钟发送一次 WebKit 低内存通知，约 10 秒后取样；热身后的压力后样本中，WebContent footprint 与 WebKit malloc allocated 每个都不超过热身后首个样本 10 MiB，整体线性趋势不超过每分钟 0.5 MiB。Rust 主进程按常规取样同样判定。普通取样照常记录和报告，但不单独作为不通过依据。
- 卡死或持续增长则先定位、修复并重测。不能复现旧问题但长测通过时，可继续 M2，报告明确写“未复现，长测通过”，不写“已修复”。功能完成后再次长测。
- 独立的并排视图偶发约 27ms 慢帧继续留 backlog，不设成 M2 必须消灭的指标；不得造成已有滚动表现退化，若证实同源再按 Q76 讨论范围。

### 2. 单项操作与能力边界（Q79、Q81–Q83）

| 文件情况 | 可用操作 | 边界 |
| --- | --- | --- |
| 普通已跟踪文本 | 整文件／单 hunk 暂存、取消暂存、丢弃未暂存改动 | 不直接丢弃已暂存内容 |
| 二进制、仅权限变化、Git 识别的重命名 | 整文件暂存、取消暂存、丢弃未暂存改动 | 无 hunk 操作 |
| 未跟踪文件 | 整文件暂存 | 无 hunk 暂存、丢弃或删除 |
| 符号链接、子模块、无法无损处理的非 UTF-8 路径 | 只读 | 界面说明限制原因 |
| Git 仍标记未解决冲突的文件 | 只读 | 不用普通暂存隐含标记已解决 |

- 每次一个文件或一个 hunk，不增加多选、全部暂存和批量丢弃；只读限制优先。
- 暂存、取消暂存只改变目标暂存区内容，不改变工作区；丢弃只改变目标未暂存改动，不改变暂存区；其他文件保持原状。
- 同文件可以在未暂存与已暂存组同时出现。操作哪一组就使用该组对应的差异，不把两组混成一份补丁。
- hunk 必须来自展示的同一份 Git 输出；补丁保留所需的原始信息，不能由截断后的渲染行或前端另算的 diff 重建（ADR-0004）。
- 重命名以 Git 给出的状态与新旧路径为准，不自行把删除和未跟踪文件猜成一对。取消暂存重命名后自然出现“旧路径未暂存删除 + 新路径未跟踪”时照实显示，不移动或删除工作区文件。

### 3. 写前校验与执行契约（Q26、Q80、Q89–Q91）

- 前端只调用 Rust 提供的固定、带类型的操作；请求绑定原 worktree、目标文件／相关路径、变更组、所选 hunk（适用时）和用户看到的 diff 指纹。前端不传任意 Git 参数或 shell 命令。
- 每次写入前读取真实状态，比较涉及文件的相关版本、状态、路径和类型；无关文件变化不拒绝当前操作，同文件其他部分相关变化也使 hunk 操作失效（ADR-0005、ADR-0009）。无普通文本 diff 的文件不能绕过校验。
- 指纹不一致则拒绝、刷新并提示“文件已变化，请重新确认”；刷新使旧 hunk 和旧确认失效，不能把旧序号绑定到新快照。
- 同一 worktree 一次只执行一个 Revia 写操作，禁用其余写入口，不积压连续点击。内部串行不等于锁住外部编辑器，不能代替执行前校验。
- 遇到 Git 的锁短暂重试，仍占用则提示；绝不删除锁。重试不能绕过对目标当前版本的核对。
- 写入期间可以浏览、切换文件和 worktree，操作目标不随当前选择改变；结果提示属于原 worktree，旧状态、diff 行、高亮响应不能覆盖当前快照。
- 超时、中断等导致结果不确定时，保留已经保存的回收记录，操作显示“结果待核对”；重新读取真实状态，不自动续做丢弃、恢复或重跑命令。下一次写入基于新状态。

### 4. 回收区与恢复（Q9、Q29、Q85–Q87、Q91）

- 丢弃前先确认，再把该文件丢弃前的完整工作区状态可靠保存到 Revia 数据目录；包括内容、相关路径、存在状态、可执行权限。即使仅丢弃一个 hunk 也不缩成 hunk 备份；保存失败不继续丢弃。
- 回收记录包含时间、来源、文件状态，绑定原仓库与原 worktree；不写进用户仓库，不使用 stash 或 reflog（ADR-0010）。
- 恢复回到这次丢弃前的工作区状态，不改变暂存区，不自动重放反向补丁。界面明确这是完整文件恢复，而非仅恢复一个 hunk。
- 判断是否发生后续变化，比较当前状态与丢弃完成后的状态，而不是与保存的丢弃前内容比较；结果待核对时不能假定丢弃已完成。
- 有后续变化则不覆盖。文本展示当前状态与保存状态的只读 diff，由用户自行复制；二进制展示两版大小、记录时间等信息，可把保存版本另存到未被占用的新路径，不提供强制覆盖。
- worktree 移动、删除重建后身份不明确时，不凭相同路径迁移记录或继承审阅标记；回收记录保留供查看直到正常到期，但不直接恢复到新目录。身份算法与存储格式由实施方选择。
- 回收区可查看、清空，超过 14 天自动清理；M3 的提交前快照不在本次实现范围。

### 5. 审阅标记与导航（Q20、Q37、Q48、Q87、Q94）

- 审阅标记按 worktree、文件以及“HEAD 中的文件版本 + 工作区中的文件版本”记录，任一版本变化即失效；只暂存或取消暂存而这两个版本未变时保留，重启后保留仍有效的标记。
- 同文件在两组共享一个标记，审阅进度按文件去重，标记不阻止后续提交。M2 显示进度，不提前启用 M3 提交能力。
- 文件行右侧勾选框只切换标记、不跳转；失效后恢复为空，不额外打扰。
- ⌥⌘R 只标记、不取消，按当前列表顺序寻找下一个未审阅文件，跨组去重，末尾可回到开头，必要时展开目标所在折叠组；全部已审阅时留在当前文件并提示。

### 6. 自动刷新与选中项（Q88、Q89、Q95）

- 只实时监视当前选中的 worktree 及相关 Git 元数据；切换 worktree、回到前台重新核对，保留手动刷新。不为全部登记仓库常驻监视；完整概览在 M4。
- 刷新后原组仍有同文件改动则留在原位置；移到另一组则优先跟随同文件；完全离开改动列表则选择原位置附近文件；无可选项则清空 diff。
- 内容变化但显示行数不变时，也要更新文字、高亮和操作版本；旧请求返回不能使内容倒退。
- 监视失败持续提示“自动刷新不可用”，保留手动与回到前台核对，不静默降级。写前仍能读取并校验通过时允许操作，否则拒绝写入。

### 7. 键盘与关闭请求（Q93、Q96）

- ⌥⌘A、⌥⌘Z 始终操作当前文件，不随 diff 焦点缩成 hunk；空格保留文件列表中的整文件暂存／取消暂存动作。
- hunk 标题提供明确、可聚焦激活的操作按钮；按变更组与能力显示暂存、取消暂存或丢弃，不增加 hunk 专用快捷键，不猜鼠标或屏幕位置。
- 输入框、弹窗、按钮使用自己的键盘行为，不穿透到后台文件操作；现有刷新快捷键不能吞掉 ⌥⌘R。
- 任何 worktree 仍有写操作时，请求关闭窗口或退出先保留窗口和进程，提供“等待完成后关闭／退出”和“留在应用”；不为关闭杀掉 Git，不提供未经验证的取消写操作。
- 正常完成并记录结果后执行原关闭／退出请求，不把关闭窗口擅自解释为其他请求；结果待核对则先展示、不静默退出。系统强退／崩溃按结果核对处理。

### 8. 平台与验收授权（Q55、Q62、Q97）

- 从 M2 起把登录 shell 环境解析、窗口外观、快捷键修饰键等平台逻辑集中，核心操作保持平台无关；不提前实现 M5 的完整 Windows 产品体验。
- 在 GitHub Actions 的 Windows x64 环境实际编译正式工程，不能以 Mac 上交叉编译、只构建前端或仅存在工作流文件替代。
- 保持 main 上仅编译的既定方向；M2 增加 m2 的仅编译入口。允许为本次验收按需正常推送 m2 到现有 origin，不推 main、不强推、不打标签、不创建 PR、不发布安装包。
- CI 结果必须对应最终验收的代码版本；授权不包括以后里程碑或其他远端。

### 9. 界面清理与美化（Q16、Q39、Q99–Q104、Q107）

- 分两步：任务 12“界面清理”无依赖，立即可做；任务 13“界面美化”在功能任务 03–08 完成后进行，集成验收（任务 10）以美化后的界面为准。
- 只改现有界面的外观、排版和交互细节，不提前实现提交区、worktree 侧栏、历史、设置页、命令面板、原生菜单栏等尚未排期的功能。
- 任务 12：测量面板只在自动测量、长测等测量模式下显示；工具栏不显示 Git 版本和文件数（环境问题仍用全局提示条）；去掉 A−／A+，字号调整保留 ⌘+／⌘−。不改其他界面，测量、冒烟与长测工具照常可用。
- 任务 13：布局和外观参照 Rebased（JetBrains 新版界面）：顶部主工具栏的仓库与 worktree 组件、左侧工具窗口图标条、“变更”工具窗口、diff 编辑区、底部状态栏；岛屿面板与 JetBrains 配色，Inter／JetBrains Mono 随应用打包；浅色、深色都要成立；文件名不上色，状态字母与已审阅勾选在行右侧（Q107、Q31、Q37）。动手前先出浅色、深色静态效果图，经用户确认后实现。
- 不再做侧栏半透明（Q107 取代 Q103 的半透明要求）；改版后仍须实测 D06 不退化。
- 两个任务按派发规则先交给 Pi（deepseek），失败时由规划方实现。

## 测试决策

### 接缝与执行方式（Q92）

- 好的测试从应用操作入口验证可观察行为：操作后的 Git 状态、暂存区与工作区字节和模式、回收记录、审阅结果及拒绝原因；不依赖私有函数名或内部存储格式。
- 沿用已有 Rust 集成测试调用 worktree 会话、真实 Git 和临时目录的先例。测试自行创建仓库与独立应用数据目录，隔离用户身份配置、仓库与数据；缺 fixture 不得直接返回成功。
- 尽量在应用操作入口集中接缝，复用现有会话与数据目录边界；提供受控时钟、外部修改、存储失败和执行阶段中断能力。Git 本身使用真实进程，不把整条链替换成模拟结果。具体接口由实施方设计。
- 前端沿用类型检查、lint、build，不新增测试框架。键盘、焦点、可见窗口、响应先后与渲染表现由真实桌面检查。
- 每个任务完成相关修改后集中执行最小相关验证；涉及核心契约的最终集成再跑完整现有检查，不以覆盖率为目标。

### 自动化验收矩阵

| 编号 | 场景与可观察结果 |
| --- | --- |
| T01 | 整文件暂存／取消暂存：工作区字节与模式不变，只有目标暂存区内容变化；覆盖同文件部分暂存、无 HEAD 的初始状态及空文件 |
| T02 | hunk 暂存／取消暂存：来自当前 Git 输出，只有目标 hunk 变化；覆盖多个 hunk、增删、无末尾换行、换行符与中文／空格路径，保留不属于该 hunk 的内容和权限状态 |
| T03 | 类型与状态边界：二进制、仅权限变化、Git 重命名只走整文件；符号链接、子模块、不支持的路径、未解决冲突拒绝；未跟踪只整文件暂存 |
| T04 | 取消暂存重命名可变为删除与未跟踪两条状态，工作区路径集合与内容不变，不猜测配对 |
| T05 | 过期指纹：同文件其他 hunk、类型、内容、相关路径或模式变化拒绝；只改无关文件仍允许；未跟踪和二进制同样校验 |
| T06 | 锁与并发：锁占用不删锁；同 worktree 写操作不重叠、不排队；切换界面不能重定向已发起的操作 |
| T07 | 丢弃前完整保存，保存失败不丢弃；单 hunk 丢弃仍能保存完整文件，暂存区和其他 hunk 不变 |
| T08 | 无后续变化的恢复回到丢弃前内容、存在状态、相关路径与可执行权限，暂存区不变；比较基准是丢弃后的状态 |
| T09 | 文本恢复冲突不写入；二进制保存版本只能写未占用的新路径，原文件与已存在的另存目标不被覆盖 |
| T10 | 持久化隔离：重启仍能查看记录；不同 worktree 不串用；移动或同路径重建后身份不明确时不直接恢复、不继承标记；受控时钟验证 14 天到期清理 |
| T11 | 保存后、写入中及完成结果记录等阶段中断：保留已经保存的记录，不自动续跑；不确定结果重新核对，不能将超时断言为未执行 |
| T12 | 审阅：HEAD／工作区版本变化失效，只暂存／取消暂存保留，重启保留有效标记，跨组共享且进度去重 |
| T13 | 刷新：当前 worktree 的工作区与 Git 元数据变化可见，切换／前台／手动刷新可核对；监视失败显式降级，写前读取失败仍拒绝 |
| T14 | 边界与路径：受控入口拒绝未登记目标、越界或不匹配目标；路径不是可执行参数，不能绕过只读类型限制 |

## 不在范围内

# 04：先保存完整状态再丢弃

**What to build:** 开发者确认后丢弃一个文件或一个 hunk 的未暂存改动；此前完整文件状态已经保存为可查看的回收记录，保存失败则工作区不动。

**Blocked by:** 03

**Status:** ready-for-agent

依据：[M2 规格](../spec.md)实现决策 3、4、7，T05、T07、T10、T11、D02；Q9、Q81–Q83、Q85、Q87、Q91、Q93。

- [ ] 整文件和 hunk 丢弃都有明确目标与确认；⌥⌘Z 只作用于当前文件；旧确认失效时不继续。
- [ ] 在修改工作区之前可靠保存完整内容、相关路径、存在状态、可执行权限，记录归属原仓库与原 worktree。
- [ ] 保存失败时拒绝丢弃；暂存区、其他文件和未选中的 hunk 保持不变；未跟踪文件没有删除入口。
- [ ] 回收区能查看新记录的时间、来源、目标与保存状态，记录在重启后仍在，数据不进入用户仓库。
- [ ] 保存完整的丢弃前状态，并能区分用于恢复安全检查的丢弃后状态；不确定结果不冒充已完成记录。
- [ ] 通过可控存储失败与阶段中断验证：已保存记录保留，不自动继续丢弃或重跑；不同 worktree 记录不串用。
- [ ] 持久身份不能只按路径相同认定；无法确认原身份的记录可查看，但不能关联为新 worktree 的可直接恢复记录。

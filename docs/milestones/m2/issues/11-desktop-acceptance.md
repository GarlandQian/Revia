# 11：规划方真实桌面验收与合并

**What to build:** 规划方在可见窗口确认完整 M2 工作流、最终长期运行与既有 diff 性能，证据通过后才能合并，而不是把自动化通过当作桌面验收。

**Blocked by:** 10

**Status:** ready-for-human

依据：[M2 规格](../spec.md)D01–D08；Q77、Q78、Q92。这里的 `ready-for-human` 由规划方使用电脑操控完成，不要求用户代劳；依赖未完成时不能开始。

- [ ] 代码审查对照规格无未解决的必须修改项，真实 Git 自动化与最终代码的 Windows x64 编译均通过。
- [ ] 用真实桌面完成整文件／hunk 操作、回收恢复、审阅导航、焦点不穿透、刷新选择、旧响应隔离、监视失败降级与安全退出检查，留存截图及结果。
- [ ] 功能完成后的 release 应用同进程、可见窗口连续长测 30 分钟，不卡死且热身后 Rust／WebView 内存不持续增长，记录负载、版本、时间与趋势。
- [ ] 首屏、两种跳转与两种视图滚动满足 D06，保留 M1 表现，不把 backlog 的独立慢帧清零作为通过条件。
- [ ] 报告明确每项实测、未复现结论和遗留问题，没有证据的项目不勾选；所有阻塞项完成。
- [ ] 规划方将 m2 压成一个本地提交合并到 main，提交说明为“M2：<内容>”；实施方不自行合并。
- [ ] 按工作区管理方式清理里程碑 worktree，告知用户验收与合并结果；不因本次 m2 CI 授权而推 main 或发布。

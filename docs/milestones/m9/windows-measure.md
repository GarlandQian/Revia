# M9 Windows 测量步骤

Status: ready-for-human
日期：2026-11-08
依据：Q210、Q211、Q216–Q218；任务 [10](./issues/10-measure-round1.md)、[11](./issues/11-acceptance.md)

给用户在自己的 Windows 电脑上使用。第一轮用测量版，第二轮用验收版，两轮步骤相同。导出的诊断信息不含文件内容和 diff，路径、远端地址、作者邮箱默认脱敏，保存前可以预览。

## 1. 下载

1. 打开 <https://github.com/GarlandQian/Revia/actions/workflows/measure-build.yml>，点进最新一次在 `m9` 上的运行，在 Artifacts 中下载以 `-portable` 结尾的产物（`-setup` 是安装版，测量时不需要）。
2. 解压后使用其中的**便携版** exe，以免覆盖已安装的 0.0.2。便携版的数据放在 exe 旁的 `data` 文件夹，仓库需要重新添加一次。
3. 测量版没有签名。如果出现 SmartScreen 提示，点“更多信息”，再点“仍要运行”。
4. 打开“帮助 → 关于”，确认显示 `m9` 和提交编号。

## 2. 复现并导出（对照开关关闭）

请用平时觉得卡的仓库，每项大约 30 秒：

1. 打开仓库后不碰电脑，窗口保持可见，等 1 分钟（测空闲 CPU）；
2. 打开一个改动多的大文件，上下快速滚动 diff；
3. 在提交日志里上下快速滚动；
4. 拖动窗口，再拖窗口边缘反复缩放；
5. 反复切换编辑器页签和文件列表中的文件；
6. 打开分支弹层、提交选项弹层，打开和关闭设置页、克隆对话框；
7. 切换到另一个仓库（这个仓库本次运行第一次打开），再切回来。

然后点“帮助 → 导出诊断信息”，预览后保存，文件名里加上“对照关”。

## 3. 复现并导出（对照开关打开，仅第一轮）

1. 点“帮助”菜单中的对照开关，按提示重启 Revia。窗口标题会注明处于对照状态，界面变成不透明、无模糊的朴素外观。
2. 重复第 2 节的 7 项操作，导出诊断信息，文件名里加上“对照开”。
3. 测完后再点一次对照开关，重启恢复。

## 4. 发回

把导出的文件发给规划方，并用几句话说明：

- 哪几项仍然觉得卡；
- 对照开和对照关相比，感觉差别大不大（第一轮）；
- 拖动、缩放窗口时有没有拖影或白块。

不需要填写电脑配置，诊断信息会自动带上。

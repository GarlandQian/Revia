# 09：提交信息框的“生成”交互

Status: done
Blocked by: 07, 08

## What to build

已配置 AI 服务时，提交信息框旁出现“生成”。点击后文字流式写进框里，可以取消、确认替换、撤销；第一次使用某个服务前弹出发送确认。见规格 F、G 节。

## Acceptance criteria

- [x] 只在已配置时显示“生成”；没有可提交内容时禁用，并给出说明；生成期间变为“取消”。
- [x] 框里已有内容时，先在界面内询问是否替换，不用系统 `confirm`；选择取消就不发请求。
- [x] 第一次使用某个服务地址前，界面内弹窗说明会发送到哪个地址、发送哪些内容；地址是非本机的 `http://` 时，提示连接未加密。确认后记入设置。
- [x] 文字流式写入；中途取消时，恢复生成前的内容；完成后可以一步撤销，回到生成前的内容。
- [x] 生成的文字和手动输入的内容一样，进入提交草稿保存和提交信息检查；不会自动提交。
- [x] 失败时就地显示结构化双语错误，框内原有内容不变。暂存区模式、更改列表模式和 amend 都能用。
- [x] 新文案照 x18n 流程，英文窄窗下布局不溢出。

## Comments

- `src/components/app/CommitComposer.tsx` 与 `src/App.tsx`：实现完整的 AI 生成与提交信息框交互逻辑。
- 仅在已配置 AI 服务时在 amend 勾选框旁显示“生成”按钮；无勾选或无暂存内容时禁用并提示 `messages.commit.ai.noContent`；生成中切换为带 spin 的“取消”按钮。
- 输入框已有内容时弹出内嵌 `role="dialog"` 确认框询问替换，取消则不发起请求；首次使用新地址时通过 `Modal` 弹窗确认发送内容及明文 http 警示。
- 生成期间文字流式写入文本框，中途取消或报错恢复原有内容，生成成功后提供单步“撤销生成”按钮；报错就地显示结构化错误；生成的文本按普通用户输入处理，可编辑且不自动触发提交。
- 界面布局紧凑，英文窄窗下无溢出。通过 TypeScript 编译与 Vite 前端构建验证。

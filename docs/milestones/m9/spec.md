# M9：Windows 与 macOS 性能、生成提交信息

Status: ready-for-agent
日期：2026-11-08
依据：Q21、Q27、Q30、Q76、Q97、Q113、Q137、Q180、Q187、Q200、Q202–Q205、Q208–Q222；ADR-0002、0003、0004、0013、0015。排查事实见 [perf-facts](./perf-facts.md)。

## Problem Statement

0.0.2 在 Windows 上所有场景都卡：打开仓库、拖动缩放窗口、滚动、切换页签与文件、输入、弹层与对话框，空闲时 CPU 也偏高。macOS 上第一次打开和切换仓库也偏慢。仓库里没有 Windows 性能数据，规划方没有 Windows 机器，只能由用户在真机上测量。另外，用户希望 AI 根据要提交的改动写好提交信息，再由自己修改后提交。

## Solution

先做性能，再做生成提交信息（Q208）。

- **诊断信息**：导出时附带性能记录和 Windows 电脑配置。
- **测量版**：带一个朴素外观对照开关，由 CI 在 `m9` 分支上打包，交给用户在 Windows 上测量。
- **Windows 外观**：去掉网页模糊和选中项玻璃镜片，保留卡片与 Mica。
- **两个平台共用的修正**：诊断摘要攒批写入，文件监视跳过被忽略的文件，消除空闲重渲染，打开和切换仓库时分段出内容。

性能修正经两轮真机实测确认后，再接入 OpenAI 兼容的 AI 服务，在提交信息框旁提供“生成”。

## User Stories

1. 作为 Windows 用户，我希望空闲时 Revia 几乎不占 CPU，以免风扇常转、其他程序变慢。
2. 作为 Windows 用户，我希望滚动 diff 和日志不掉帧，以便连续审阅。
3. 作为 Windows 用户，我希望拖动和缩放窗口跟手，没有拖影或白块。
4. 作为 Windows 用户，我希望切换页签、文件和打开弹层立刻有反应。
5. 作为 Windows 用户，我接受外观更朴素一些，以换取流畅；卡片布局保持一致。
6. 作为两个平台的用户，我希望第一次打开仓库时不必等登录 shell 或 PowerShell profile 加载完。
7. 作为两个平台的用户，我希望切换仓库后马上看到界面和文件列表，日志随后补上，等待期间界面不冻结。
8. 作为开发者，我希望 `node_modules`、`target` 这类被忽略目录的变化不引发整套刷新。
9. 作为反馈者，我希望一次导出诊断信息就带上性能记录和电脑配置，不用手动填写。
10. 作为测量者，我希望能一键切到朴素外观做对照，判断卡顿是不是玻璃效果造成的。
11. 作为测量者，我希望从 GitHub Actions 下载测量版，不必在 Windows 上搭建构建环境。
12. 作为提交者，我希望根据下一次提交将包含的改动生成提交信息，并在框里修改后再提交。
13. 作为提交者，我希望生成的写法跟随仓库最近的提交，也能固定为中文或英文。
14. 作为提交者，我希望看到文字逐字写入、能中途取消，替换已有内容前会先问我，替换后能撤销。
15. 作为注重隐私的用户，我希望第一次使用某个服务前知道会发送什么、发到哪里；二进制文件和 lock 文件不发送内容。
16. 作为用户，我希望密钥存在系统凭据库，不出现在设置文件、日志或诊断信息里。
17. 作为用户，我希望能接 OpenAI、DeepSeek、智谱 GLM 等服务，也能接本机的 Ollama、LM Studio。
18. 作为用户，我希望改写默认提示词，并能一键恢复默认。
19. 作为不用 AI 的用户，我希望没配置服务时不出现“生成”按钮。
20. 作为 amend 用户，我希望生成的信息在原提交信息的基础上改写，并覆盖原提交和新加入的改动。

## Implementation Decisions

### A. 性能记录与电脑配置（Q210、Q217）

- **诊断信息的 `performance` 一节**（`m7/diagnostics.rs`）扩充以下记录。记录器本身不能违反空闲 CPU 门槛：空闲时不跑 rAF 循环，只在用户交互（滚轮、拖动、缩放窗口、键盘导航）开始后采样帧，最后一次输入 1 秒后停止。
  - **帧耗时**：按场景分别统计次数、p50、p95、最大值、超过 16.7ms 和 33ms 的帧数。场景至少有 diff 滚动、日志滚动、窗口缩放和其他。
  - **长任务**：Chromium 下用 `longtask` 记录次数、总时长和最长几次；WebKit 下用超过 100ms 的帧间隔代替。
  - **交互延迟**：Chromium 下用 Event Timing，统计点击、按键从输入到下一帧的耗时，按页签、文件、弹层、其他分类，记录 p95 和最大值。
  - **CPU 与内存**：Rust 每 5 秒采样一次，保留最近 30 分钟。Windows 统计主进程与全部 WebView2 进程的合计和各自数值；macOS 至少统计主进程。
  - **打开与切换仓库的分段耗时**：触发、会话就绪（其中环境捕获、读取 Git 版本各多少）、文件列表数据到达、文件列表绘制、日志首屏绘制。同时注明是本次运行第一次打开还是切换，以及改动文件数。
  - **监视触发的刷新**：每分钟次数，以及触发路径属于被忽略、`.git` 内部还是普通文件。
- **Windows 电脑配置**写在环境信息中：CPU 型号、显卡名称、窗口所在显示器的分辨率与缩放比例、Windows 版本号、WebView2 版本、安装版还是便携版、当前窗口材质（Mica、CSS 材质、实色）。
- 所有新记录照 Q180 脱敏，不含文件正文、diff、路径原文或终端内容。导出前预览、手动导出不变。
- **IPC 计数器**：`src/lib/ipcDiagnostics.ts` 写死了 `ipc://localhost/`。改为同时识别 Windows 的 `http://ipc.localhost/`，让 Windows 上的 IPC 计数生效。

### B. Windows 渲染降级（Q209）

- **Windows 11 Mica 路径**（`html.window-material:not(.native-glass)`）：
  - 去掉日志吸顶表头、通知、弹层、对话框、PR 面板确认框的 `backdrop-filter`，改为不透明或高不透明度的普通底色；
  - 对话框打开时不再对整个界面做 `filter: blur`，背后的界面只降低不透明度或盖一层遮罩；
  - Windows 上不播放选中项玻璃镜片，直接显示普通选中底；
  - 保留侧栏与编辑区两块卡片和 Mica 窗口底。
- **Windows 10 与 CSS 材质路径**（含 `REVIA_GLASS=css`）：Windows 上不渲染 SVG 折射（`GlassLayer` 的 `refraction`、`GlassSurface` 的 `backdrop-filter: url()`），也不使用 WebGL 特效提交按钮（`SpecularButton`）。只保留普通半透明与卡片。
- **macOS 外观不变**，包括原生玻璃、CSS 材质路径和镜片。改动用平台条件集中控制，不散落到业务组件里（Q55）。
- **不提供恢复这些效果的设置开关。** 实色窗口底只在第一轮实测证明透明窗口加 Mica 是主因时才做，由规划方决定（Q218），本次实施先不改。
- 照 Q190，代码与 diff 的可读性优先：去掉模糊后，文字对比度不能下降。

### C. 两个平台共用的性能修正（Q212，以及不改变行为的优化）

- **诊断摘要攒批写入**：`CommandLog::record` 不再在锁内同步调用 `DiagnosticsSummaryStore::observe` 整份重写并 `sync_all`。改为先追加到内存，每隔几秒（建议 5 秒）在后台合并写一次；正常退出时写最后一次。崩溃时可能丢失最后几秒。保留 7 天、手动清空、导出时合并内存中尚未落盘的记录这三项行为不变（Q187）。
- **文件监视跳过被忽略的文件**：判断标准与 Git 完全一致，包括嵌套 `.gitignore`、`.git/info/exclude` 和 `core.excludesFile`，用 Git CLI 判断（ADR-0002）。已确认被忽略的目录，其下的事件直接跳过；任一忽略规则文件变化时清空缓存并刷新一次。`.gitignore` 本身的变化、`.git` 内部（index、HEAD、refs）的变化仍按原样刷新。
- **空闲重渲染**：`App.tsx` 的监视状态轮询只在 `active` 或 `error` 实际变化时更新状态，不再每秒整树重渲染。
- **按实测再做的渲染优化**（不改变外观和行为）：
  - LogView 不在每个 scroll 事件里 `setState`，也不再对全部已加载的行做 `Math.max(...)`；
  - 并排视图行号不再每行都带 `will-change`；
  - 必要时给大组件加 memo。

  以第一轮测量数据为准，没有收益的不做。

### D. 打开与切换仓库（Q211、Q212、Q222）

- **门槛**：切换后 0.3 秒内出现界面和文件列表。日志、分支概览、进行中的操作、stash 等随后补上，不阻塞文件列表。加载期间主线程没有超过 100ms 的阻塞，点击和按键 100ms 内有反应。门槛同时适用于本次运行第一次打开某个 worktree，以及切换到已打开过的 worktree。
- 现有首屏取数顺序拆成两段：“文件列表优先”和“其余在后台补上”。补上的内容出错时，就地显示错误，不影响文件列表。旧响应的处理沿用 Q90，切走后迟到的结果不能覆盖新仓库的界面。
- **环境加载时机（Q222）**。现状是两个平台第一次打开每个 worktree 时，都会在 `commands.rs` 中同步调用 `shell::resolve`：macOS 启动登录 shell，在这台 Mac 上约 0.12–0.19 秒；Windows 启动 PowerShell 并加载 profile，最长 5 秒。之后才创建会话，Git 程序也从这个环境的 PATH 中查找（Q27）。改为两个平台都不等：
  - **手动指定的 Git**（设置中的 `git_path`）始终直接使用；
  - **没有手动指定时**，先用已经找到过的 Git 及其环境的 PATH，立即读取状态、diff 和日志。来源依次是本次运行中其他 worktree 解析出的结果，以及上次运行记住的结果；后者存在 Revia 应用数据中，不写用户的 Git 配置；
  - **从未找到过 Git 时**（第一次使用 Revia），照旧等待环境加载完；
  - **该 worktree 的完整环境在后台加载**，环境内容仍按 worktree 解析（Q21、Q205）；
  - **后台加载完成后**，如果 Git 路径变了，切换到新的 Git 并重读一次；环境就绪前读取失败的（例如找不到 git-lfs 这类过滤程序），不立即报错，等环境就绪后用完整环境重试一次；
  - **需要完整环境的操作**：执行 hooks、提交、fetch/pull/push、打开内置终端，必须使用该 worktree 完整的环境；尚未加载完时等待，并在界面上说明正在等待；
  - 环境捕获失败和超时的提示与回退沿用 Q205；
  - 不修改用户的 profile、执行策略或 Git 配置。

### E. AI 服务与设置（Q213、Q215、Q219、Q221）

- **设置页**：设置的“提交”分类下新增“AI”页（`SettingsDialog.tsx` 的 `commit` 分类，照现有 Loop 式页面写法），内容包括：
  - 服务地址、模型名、密钥；
  - 生成语言：跟随仓库、中文、English；
  - 完整的默认提示词，可整段改写，并有“恢复默认”。
- **调用方式**：采用 OpenAI 兼容接口。服务地址去掉末尾斜杠后，拼上 `/chat/completions`；如果用户填的地址已经以 `/chat/completions` 结尾，就原样使用。输入框给出示例：`https://api.openai.com/v1`、`https://api.deepseek.com`、`http://localhost:11434/v1`。
- **密钥可留空**（本机服务通常不需要）；有密钥时以 `Authorization: Bearer` 发送。
- **只配置一个 AI 服务**。服务地址和模型名存在 Revia 设置中，密钥存在系统凭据库：macOS 是钥匙串，Windows 安装版和便携版都是 Credential Manager。复用 GitHub 凭据的 `keyring` 写法，用独立的 service 名。Q213 把 ADR-0015 的便携版凭据例外扩展到了 AI 密钥；密钥不进设置文件、日志或诊断信息。
- **密钥与服务地址绑定**：改了服务地址视为换了服务（Q221），旧密钥从凭据库删除，需要重新填写，避免把一家服务的密钥发给另一家。
- **未配置时**：服务地址和模型名有一项为空，就视为未配置，提交信息框旁不显示“生成”。
- **HTTP 请求**：在 Rust 层发出，前端只调用固定、带类型的命令，拿不到密钥。复用现有 `reqwest`（rustls）客户端配置。
  - 连接超时 15 秒；
  - 流式输出时，相邻两段数据间隔超过 60 秒视为超时；
  - 不设总时长上限，用户可以随时取消；
  - 不发送 `temperature` 这类部分推理模型会拒绝的参数。

### F. 发送内容（Q214、Q220）

- **改动内容**是下一次提交将包含的改动，在 Rust 层用 Git CLI 生成，不改变用户的暂存区或工作区：
  - 暂存区模式：已暂存改动（`git diff --cached`）；
  - 更改列表模式：勾选的内容。复用更改列表提交时准备独立 index 的同一逻辑，在私有 `GIT_INDEX_FILE` 上生成 diff，用户的 index 不变（ADR-0003）；
  - amend：修改后的提交将包含的全部内容，即相对原提交父提交的 diff；原提交是根提交时，相对空树。同时附上原提交信息，要求在其基础上改写。
- diff 参数固定为 `--no-ext-diff --no-textconv --no-color`，并带 `-c core.quotePath=false`。不读写用户的 diff 配置。
- 二进制文件、lock 文件、子模块只写路径和状态，不写内容。lock 文件清单至少包括：
  - `package-lock.json`、`npm-shrinkwrap.json`、`pnpm-lock.yaml`、`yarn.lock`、`bun.lock`、`bun.lockb`
  - `Cargo.lock`、`Gemfile.lock`、`composer.lock`、`poetry.lock`、`Pipfile.lock`、`uv.lock`
  - `go.sum`、`packages.lock.json`、`flake.lock`、`Podfile.lock`、`pubspec.lock`、`mix.lock`
- **截断**：单个文件最多 6,000 个字符，总量最多 24,000 个字符；被截断的位置写明“已截断”。无论是否截断，都附上完整的文件清单（状态和增删行数）；清单超过 300 项时，写明另有几个文件。上限是实现常量，不进设置。
- **附带信息**：本仓库最近 10 条提交的标题（只取首行；没有提交时省略），用来参考写法。
- **固定规则**：改写提示词后仍然生效，追加在用户的提示词之后。
  - 生成语言：跟随仓库时参考最近的提交标题，或者按设置固定为中文或英文；
  - 首行不超过 `commit_subject_limit`（默认 72）；
  - 首行与正文之间空一行；
  - 只输出提交信息本身。
- **首次使用确认**：每个服务地址第一次使用前弹窗说明：
  - 会发送到哪个地址；
  - 发送哪些内容：改动内容、文件清单、最近提交标题，amend 时还有原提交信息；
  - 地址是非本机的 `http://` 时，额外提示连接未加密。

  用户确认后，把该地址记入设置，不再提示；地址变了就重新确认。
- 请求和返回内容不写进 Git 命令日志和诊断信息，诊断信息也不记录密钥和服务地址。

### G. 提交信息框交互（Q215）

- **按钮**：“生成”放在提交信息框旁（`CommitComposer.tsx`）。没有可提交内容时禁用，并给出说明。生成期间，按钮变为“取消”。
- **流式写入**：返回的文字流式写进框里。
  - 忽略推理模型单独返回的思考字段（如 `reasoning_content`），去掉 `<think>…</think>` 段和包裹全文的代码围栏；
  - 首尾空白去掉后为空，按失败处理。
- **替换与撤销**：
  - 框里已有内容时，先在界面内询问是否替换。不能用系统 `confirm`，取消就不发请求；
  - 中途取消时，恢复生成前的内容；
  - 完成后可以撤销，一步回到生成前的内容。
- **只生成文字，不自动提交。** 生成的文字和手动输入的内容一样，进入现有的提交草稿保存和提交信息检查。
- **失败处理**：认证失败、模型不存在、限流、网络错误、超时、服务端错误、空结果，都在框旁就地显示结构化双语错误（ADR-0013），框内原有内容不变。错误中引用服务端返回的说明时，去掉其中可能出现的密钥。
- **文案**：新增文案和错误键照 x18n 流程管理（Q163）。

### H. 测量版与验收版构建（Q216、Q218）

- **工作流**：新增 `.github/workflows/measure-build.yml`，只在推送 `m9` 或手动运行且 ref 为 `m9` 时触发。在 `windows-latest` 上构建安装版、便携版 exe 和 zip，上传为 Actions 产物，保留 14 天。产物名带 `m9` 和提交短 SHA。
- **不需要的东西**：不需要更新签名密钥，不生成更新清单，不创建 Release，不打标签。现有 `release.yml` 和 Q203 不变。
- **`measure` 编译特性**，测量版和验收版都打开：
  - 关闭应用更新检查；
  - “关于”和诊断信息显示构建来源（`m9` 与提交 SHA）；
  - 提供对照开关，入口是“帮助”菜单中只在测量版出现的一项。打开后，下次启动时窗口以不透明方式创建，不用 Mica，没有模糊、镜片和半透明，窗口标题注明处于对照状态。对照状态写进诊断信息。
- **对照开关的去留**：查明原因后，在合入 main 前删除对照开关和 `measure` 特性中仅供测量的部分；性能记录保留（Q210）。
- **推送由规划方进行**，只推 `m9`，不推 main，不强推（Q216）。测量版没有签名，首次运行可能出现 SmartScreen 提示。测量时建议用便携版，以免覆盖已安装的 0.0.2。

## Testing Decisions

- 照 local-validation 的要求，回归测试放在现有 Rust 测试中，调用真实 Git，用 tempfile 独占临时仓库和独立应用数据目录。前端不引入新的测试框架。
- **需要新增测试的部分**：涉及数据持久化、隐私或跨模块契约的地方。
  - **诊断摘要攒批**：记录时不同步写盘；到间隔、主动刷新、退出时写盘；导出时合并内存中的记录；7 天清理和手动清空不变。
  - **监视过滤**：被忽略路径的事件不触发刷新；`.gitignore`、`.git/info/exclude` 变化会触发刷新；`.git` 内部变化照旧。
  - **发送内容**：暂存区模式；更改列表模式下只勾选部分块，并核对用户 index 前后一致；amend 的普通提交和根提交；二进制、lock、子模块、改名、非 UTF-8 文件名；截断标记与文件清单上限。
  - **AI 请求**：用本机 TcpListener 模拟 OpenAI 兼容的 SSE 服务，覆盖：
    - 请求路径、请求体、没有密钥时不带 Authorization；
    - 思考字段和 `<think>` 被去掉；
    - 取消后连接关闭；
    - 各类 HTTP 错误的映射；
    - 间隔超时。
  - **凭据**：沿用 GitHub 凭据测试的替身做法，不读写真实凭据库；改服务地址后旧密钥被删除。
- **不跑的东西**：测试不访问真实 AI 服务、真实 GitHub 或用户仓库。
- **集中检查**：一批修改完成后集中检查。涉及共享的会话、监视、诊断和设置，交付时运行：
  - 现有完整的 Rust 测试（`/opt/homebrew/bin/cargo test --manifest-path src-tauri/Cargo.toml`）；
  - `pnpm exec tsc -b`、`pnpm lint`、`pnpm build`、x18n check；
  - `cargo check --features measure`。

  失败只重跑受影响的检查。
- **性能门槛靠实测确认**，不靠单元测试（Q211）：
  - **macOS**：由规划方在可见窗口中，用诊断信息的分段耗时，测量 `diffs` fixture 和新增的大仓库 fixture 的第一次打开与切换。大仓库 fixture 约 2 万个文件、3 万个提交、300 个改动文件，由 `tools/fixtures/setup.sh` 用 `git fast-import` 生成。
  - **Windows**：由用户在自己的日常仓库上，按 [windows-measure](./windows-measure.md) 测两轮。
- **AI 端到端**：规划方用本机模拟服务验收；真实服务需要用户自己填密钥，由用户确认。规划方不在界面中输入真实密钥。

# 02：已跟踪文件不可读时避免整次状态刷新失败

**What to build:** 当工作区内某个已跟踪文件被移除读取权限（例如 `chmod 000`）导致 `git diff` 报告退出码 128（`open(...): Permission denied`）时，容错隔离该异常并将该条目标记为只读（`ReadonlyReason::Unreadable`），而不让整个仓库的状态刷新（`list_changes` / `refresh`）整体失败。

**Blocked by:** None

**Status:** ready-for-agent

- [ ] 工作区存在权限为 000 的已跟踪文件时，`list_changes` / `refresh` 仍能成功返回其余文件的快照
- [ ] 该不可读文件在变更列表中显示为只读，鼠标悬浮或提示为“文件无法读取或无访问权限，仅供只读查看”
- [ ] 对应集成测试验证：工作区已跟踪文件被 `chmod 000` 时，其余文件的正常暂存与取消暂存不受影响

## 背景

M2 任务 02 第三轮审查（2026-10-23）建议：
“已跟踪文件不可读时 `git diff` 以 128 退出，整次刷新失败；更好的做法是只把该条目标为不可读。若本任务不处理，请记入 `docs/milestones/backlog/`。”

当前实现中，对于未跟踪文件，如果出现权限问题或无法读取，已能正常将其标记为 `ReadonlyReason::Unreadable` 并仅供只读查看；但对于已跟踪文件，Git 在执行批量 `git diff` 读取工作区以生成 patch 时直接报错并以 128 退出。在不引入逐文件 diff 或复杂子进程重试机制的前提下，该边界场景暂不阻塞 M2 主线任务 02 的交付，放入 backlog 在后续进行专门的容错隔离与降级处理。

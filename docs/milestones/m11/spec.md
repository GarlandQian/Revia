# M11：AI 配置保存与自动获取模型

Status: done
日期：2026-11-11
基线：9f9250c73429e34a326df50ba0c497985d76cf18

## Problem Statement

AI 设置填写后恢复旧值，无法完成配置；模型名必须手工查找。源码诊断确认设置父组件转发遗漏四个 AI 字段，读取状态还会覆盖正在编辑的草稿。

## Solution

修复配置从输入到持久化的完整链路；打开 AI 页、成功保存服务地址或设置/清除密钥后，自动获取当前服务提供的模型列表。用户从列表选择，也可继续手填。不支持列表或请求失败时保留已有配置和输入，并提供重试。

## User Stories

1. 填写服务地址、模型、生成语言和提示词后，重开设置仍显示保存结果。
2. 从地址框转到其他输入框继续填写时，迟到的保存或读取不会抹掉新输入。
3. 已保存值改成另一个值、再改回原值，两次都能保存。
4. 保存密钥时使用当前地址；地址保存失败时不把密钥存到旧服务。
5. 不需要先填写模型名，就能从服务获取模型列表。
6. 从列表选择后即可保存模型；已有模型不被列表刷新擅自替换。
7. 服务不支持列表、无可用模型或网络错误时，仍可手填，输入不会丢失。
8. 快速切换地址、密钥或关闭设置，旧列表和旧错误不能回到当前页面。
9. 本机无密钥服务可获取模型；密钥仍只在系统凭据库保存。
10. 新状态和错误支持简体中文 / English。

## Implementation Decisions

- 四个 AI 字段使用同一带类型的设置 patch 传给 Rust，消除父组件易遗漏的重复映射。其他设置行为保留。
- 集中管理已保存基准、编辑草稿和在途请求。初始化不覆盖已编辑字段；保存只推进相应基准。加载状态不清空新输入的密钥。关闭时使旧回调失效；重新打开取得已完成写入后的状态。
- AI 设置保存按顺序执行；密钥操作须先成功提交地址。Rust 密钥写入/清除接收预期服务地址，并在同一个设置锁内校验和执行凭据操作，避免和换地址交错。不能把旧页面的密钥绑定新服务。
- 获取模型只依赖非空合法服务地址，不依赖模型或 configured。固定类型 IPC 传预期服务地址；Rust 从已保存设置和系统凭据取得一致快照，不接受任意草稿密钥或前端提供的请求头。
- 标准 OpenAI 兼容 GET：普通 base URL 追加 /models；若地址以 /chat/completions 结尾，移除该后缀再追加 /models。保持原来的地址身份规则，不自动加 /v1，也不扩大地址格式迁移。
- 解析 data[].id，忽略其他元数据，去重并稳定排序；过滤空白/无效项。限制超时和响应大小；不跟随重定向发送凭据。返回仅含服务地址及模型名。
- 自动获取后由用户选择模型，不默认选第一项、不覆盖已有选择。输入框保留手填能力，提供明确的列表选择入口、加载/空列表/失败状态和重试。
- 地址开始编辑或密钥操作开始即使旧列表失效；采用服务身份与代次避免 A→B→A、重试、关闭重开及迟到错误污染。请求失败不回滚已保存设置。
- 密钥绑定、地址变更清除旧密钥与发送确认保持 Q221。模型列表不读取仓库或发送 diff、提示词；获取列表不算已确认发送提交内容。
- 结构化双语错误，禁止把服务响应正文、密钥、请求头或请求内容放进错误、日志、诊断。不新增 provider SDK、多服务或数据迁移。

## Testing Decisions

- 通过现有 Node TS/TSX 生产入口与受控 Promise 验证实际转发、输入保留、保存后改回原值、地址失败阻止密钥写入、迟到列表与错误失效；不以源码字符串断言代替行为测试。
- Rust 沿用现有测试框架与模拟凭据，使用独占本机 HTTP fixture 验证普通/完整 endpoint、可选 Bearer、去重与异常响应、超时/体积限制、重定向、服务身份冲突和密钥操作顺序。不得访问用户真实凭据或 AI 服务。
- 同一批相关修改完成后集中执行类型、lint、前端 build、相关 Node 行为测试、AI/设置相关 Rust 测试与 x18n 检查；共享设置接线变更须核对其他 patch 的兼容性。首次失败保留，修正后只重跑受影响项。
- 规划方固定源码构建，在独立应用数据和本机模拟服务上完成 macOS 桌面输入、选择、重开持久化与双语验收。真实 AI 服务、Windows 真实桌面不以本机替代。

## Out of Scope

发布新版本、改动公开的 0.0.4、推送本轮修复、AI 聊天/自动提交、多服务、自动猜测模型能力、真实服务调用、M8/M9 历史性能及 Windows 待验项目。

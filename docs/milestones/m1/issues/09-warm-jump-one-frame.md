## Comments

### 2026-10-20，规划方代码审查（d3a8491 相对 9842fce）

思路对：Pi 指出的“`requestAnimationFrame` 在同一帧内就把预渲染余量补回来，导致大幅跳转只渲染可见行的优化没有生效”是成立的。但以下问题需要修改，修完后本任务才能关闭。

**必须修改**

1. **切换文件或视图后，`compact` 会一直卡在开启状态。** 清理定时器的代码放在依赖 `[entry.path, view]` 的 effect 里，而 App.tsx 中的 `<DiffView>` 没有 `key`，切换文件或视图时组件不会重新挂载，这段清理会执行并清掉 `compactTimer` 与 `idleTimer`，但 `compact`、`scrollIdle` 没有复位。触发方式：按 End 后 150ms 内切到另一个文件。结果：直到下一次大幅跳转前，都没有预渲染余量、也没有语法颜色。修法：定时器只在组件真正卸载时清理；或者切换时同时把 `compact`、`scrollIdle` 复位。
2. **`compact` 期间底部会露出半行“加载中的行”。** 余量为 0 时只渲染 `ceil(视口高 / 18)` 行，滚动位置没有对齐整行时，底部最多 17px 没有内容；现在这个状态会持续 150ms，并且在整个拖动滚动条的过程中都存在，而这些行的数据其实已经缓存。修法：`compact` 时也要渲染足以盖满视口的行（按 `scrollTop + 视口高` 向上取整计算，或至少多渲染 1 行）。
3. **跳回已经着色的位置时，会先闪 150ms 纯文本再上色。** Home / End、F7 跳到下一处差异、拖回看过的位置，两种视图都会出现，F7 尤其频繁。要求：大幅跳转后，已经有缓存的颜色在约 2 帧内恢复，而不是 150ms；同时连续拖动滚动条时，不能因为每帧都恢复颜色和余量而掉帧。

**建议修改**

4. DiffView 第 76 行的注释已经过时（“预渲染余量下一帧再补”），按新行为改写；`150` 不要写死，改用常量；行组件这一层把 `compact` 改名为表达“只画纯文本”的名字，并把 `highlights` 与它合并处理，不要在两处各写一遍 `!compact ? highlights.get(...) : undefined`。
5. commands.rs：`write_measurement` 写完后退出进程，要加一行注释说明原因；是否处于测量模式，应复用 `measure_config` 中 `auto_run` 的判断（只认 `1` / `true` / `yes`），不要另写一套 `is_ok()`。报告 §9.7 “原因分析”的第 3 条不是原因，移到单独的“其他改动”。

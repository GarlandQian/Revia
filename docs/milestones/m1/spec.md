# M1 需求规格：只读界面与 diff 流式取数

> 补写于 2026-10-20（Q71）。M1 已于 2026-10-20 验收并合并进 main。本文根据 [计划](./plan.md)、[评审意见](./review.md)、[报告](./report.md) 以及 Q46–Q53、Q68–Q70 整理，用来记录需求，不是事前规格。

**Status:** done

## 问题

M0 证明了自绘 diff 视图可行，但留下三个问题：

1. 首屏约 210 毫秒里有约 170 毫秒花在把整份 diff（1.15 MB JSON）一次性传给界面，换成真实的大仓库很可能超标。
2. 在真实桌面上快速滑动时，可见区域会出现大块空白。
3. 原型只是测量工具，还没有可以日常打开仓库、查看改动的正式应用。

## 方案

在仓库根目录建立正式工程，做出只读的 Revia：添加仓库、读取状态、按三组列出改动文件、查看 diff。diff 数据改为按可见范围分批获取；diff 区域由程序接管滚动，快速滑动时内容与滚动位置同一帧更新。M1 不做任何写操作。

## 用户故事

1. 作为开发者，我想第一次打开 Revia 时只看到“添加仓库”，按 ⌘O 或把文件夹拖进窗口就能开始。
2. 作为开发者，我想选择的文件夹不是 Git 仓库时得到明确提示，而不是被悄悄初始化。
3. 作为开发者，我想添加过的仓库在重启后仍然在列表里。
4. 作为开发者，我想改动文件分成“未暂存”“未跟踪”“已暂存”三组显示，未跟踪默认收起，只显示数量。
5. 作为开发者，我想文件名旁用带颜色的单个字母标出状态（M、A、D、R、U、?），文件名本身不上色。
6. 作为开发者，我想同一个文件同时出现在“未暂存”和“已暂存”两组时，点哪一行就看哪一侧的 diff。
7. 作为开发者，我想未跟踪的文件也能像新增文件一样查看完整内容。
8. 作为开发者，我想打开仓库到看到第一个文件的 diff 不超过 150 毫秒。
9. 作为开发者，我想默认用并排视图看 diff，一键切换到统一视图，切换后停在同一行。
10. 作为开发者，我想 lock 文件、二进制文件和超大文件默认收起，点开才显示。
11. 作为开发者，我想用触控板快速甩动长 diff 时，不出现白块或空白区域。
12. 作为开发者，我想拖动滚动条跳到很远的位置时，文字几乎立刻出现；跳回看过的位置时在 1 帧内出现。
13. 作为开发者，我想用 ↑↓、PageUp/PageDown、Home/End 键滚动 diff。
14. 作为开发者，我想用 F7 / ⇧F7 跳到下一处 / 上一处差异。
15. 作为开发者，我想代码有语法高亮，滚动时先显示文字，停下后再着色，不影响滚动流畅度。
16. 作为开发者，我想界面和高亮都跟随系统的浅色、深色模式。
17. 作为开发者，我想用 ⌘+ / ⌘- 调整 diff 字号，并且被记住。
18. 作为开发者，我想按 ⌘R 或切回窗口时刷新改动列表。
19. 作为开发者，我想找不到 git 或版本过低时，窗口顶部有提示条；Git 命令失败时能看到它的原始输出。
20. 作为开发者，我想 Revia 只能读取我添加过的仓库，界面层出问题也读不到其他目录。

## 实现决策

- 正式工程在仓库根目录：Tauri 2 + React + TypeScript + Vite + Tailwind CSS + shadcn/ui（Base UI 基座，Q51）；应用标识 `io.github.garlandqian.revia`（Q49）；Rust 结构体通过 ts-rs 生成前端类型。
- 前端只能调用固定的 Rust 命令：打开 worktree、列出改动、按显示行区间取行、按行范围取高亮、行号换算显示行、添加 / 列出仓库。除“添加仓库”外，命令只接受已登记的仓库或 worktree 的 ID；文件路径必须在当前改动列表中。
- 权限只开放核心 API 和“打开文件夹”对话框。
- 未跟踪文件用 `git diff --no-index` 生成 hunk，与其他文件走同一个解析器（ADR-0004）。
- 显示行索引（并排视图的删除行与新增行配对）在 Rust 侧生成，界面按显示行区间取数据；每块 500 行。
- 取数策略：可见范围有缺口时先单独取可见的几十行，再补整块；可见块不受在途上限限制；跳转前已在途的块照常缓存；2 万显示行以内的文件在首屏后于后台取完全部块（Q69）。
- 语法高亮在 Rust 侧用 syntect，只返回 15 个语法分类，界面用 CSS 变量映射浅色 / 深色两套配色（Q50，ADR-0006）。滚动期间不请求高亮，停下 150 毫秒后补齐。
- diff 区域由程序接管滚动：接收滚轮与触控板事件，同一帧内更新内容位移、自绘滚动条和要渲染的行；大幅跳转的那一帧只渲染可见行（Q68，[ADR-0008](../../adr/0008-diff-view-owns-scrolling.md)）。
- 数据没到的行显示“加载中的行”底图，按行高平铺绘制。

## 测试决策

- 好的测试只验证外部行为：给定一个测试仓库，读取状态、列出改动、取行、取高亮的结果是否正确。
- Rust 单元测试覆盖状态解析、diff 解析、并排配对与两种视图的行索引、指纹稳定性；集成测试用临时测试仓库跑通“读取状态 → 列出改动 → 取行 → 取高亮”，并校验分块取行与一次性取全量的结果一致。
- 前端只做类型检查、lint 和构建，不引入前端测试框架。
- 性能用 release 构建在真实桌面会话中测量（窗口可见、帧回调正常）：T1 首屏、未缓存与已缓存跳转、逐帧滚动的帧间隔与未覆盖帧。没有图形合成的会话里的数据只作参考。
- 是否露白以用户在真实桌面上快速甩动时的目测为准。

## 不在范围内

- 暂存、取消暂存、丢弃、提交等写操作（M2、M3）。
- 审阅标记（M2，Q48）、文件监视（M2）、长时间运行卡住的排查（M2，Q53）。
- worktree 侧栏、历史、合并工具、Git 命令日志面板、导出诊断信息、自动更新（M4）。
- Windows（M5）。

# 本地验证与平台提示处理

适用于本地验证、Pi交接，以及平台风险提示出现后的处理；不改变产品规格、测试门槛或平台防护。

## 执行

1. 交接先写业务目标、固定源码、允许修改的实施目录、验证使用的自建临时仓库和独立应用数据目录。Revia是本地Git客户端；恢复验证的目标是文件、路径、权限和暂存区不被错误覆盖。
2. 回归优先加入现有Rust测试，通过会话或命令等生产入口、真实Git和受控阶段验证。工作区写入只针对本次创建的fixture；外部系统、真实用户仓库和凭据不属于测试范围。临时根采用真实路径；路径校验本身仍严格执行。
3. 先完成同任务相关修改，再运行最小相关检查；核心共享契约按既定门槛检查。保存源码SHA、精确命令、真实退出码、原始stdout/stderr。过滤后的摘要只辅助阅读；已有库若源码来源未确认，动态观察只能作补充，不能冒称固定版本通过。既有证据保留，后续不扩展重复的临时验证工具。
4. Pi负责实现及必要检查，按明确文件暂存。规划方全部复核通过后才固定版本构建Release、操作真实桌面、测D06和最终长测；失败则回任务Comments返修。
5. 平台拦截时保留当前提交、已有改动、通知和可用错误标识，停止该被拒请求并核对真实范围；没有服务端规则详情就明确原因未确认。按可用 `/feedback` 或官方支持途径报告疑似误判，提交日志前移除凭据和无关个人数据。保持平台防护，不通过编码、改名、换账号/模型或重复同一被拒请求规避检查；正常工程任务在允许范围内继续。

## 完成条件

每项结论都能对应固定源码、生产入口和实际可观察结果；普通模式与测量模式分开，实施方报告与规划方验收分开。必要的路径、并发和数据完整性回归不能为了减少提示而省略。范围清楚只能减少歧义，不保证平台永不误判。
